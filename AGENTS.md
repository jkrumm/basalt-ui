# Basalt UI — Project Context

An opinionated framework for **React apps on Base UI and Tailwind 4**, extracted from argo (the POC). A
consumer app instantly gets: a `BasaltProvider` (`basalt-ui`, re-exported by `basalt-ui/router`), an app
shell (`AppShell`: header, rail, one scrollport, aside and a phone tab bar, driven by one `defineNav`), a chart system, a
three-tier `--basalt-*` token system, a Vite preset, raw toolchain config presets, and a
`basalt-ui` CLI (bin named like the package — never `bunx basalt`).

**Breaking 1.0** (`feat!:`, same npm name `basalt-ui`): the package pivoted from the old Tailwind
CSS theme into the framework above. The old `./css` and `./starlight` Tailwind exports are
**dropped**. This was recorded at the time as costless ("zero external consumers") and it was not:
`rollhook` consumed `basalt-ui/css` across two apps and sat pinned at a dead 0.4.2 until round 4,
19 minors later. A dropped export with no `MIGRATING.md` entry is how a consumer stalls silently.

## Critical Rules (READ FIRST)

- **Runtime**: Bun (not npm/pnpm)
- **UI lib**: Base UI primitives (`basalt-ui/ui/*`) on Tailwind 4. No 2.x token prefix or UI-library name ships: `scripts/check-legacy-names.ts` gates it (allowlist `scripts/legacy-names.ts`); after a rebase over a rename, rerun `bun scripts/rename-legacy.ts`
- **Tokens**: three-tier `--basalt-*` CSS-variable system (palette data → CSS vars → `BASALT.*` refs). The
  shipped palette (accent, fills, surfaces, ink, status) is GENERATED by
  `packages/basalt-ui/src/tokens/derive.ts` at a default seed/config — never hand-edit a palette
  hex; retune the derive config/constants instead: one accent seed + five bounded knobs, contrast
  guaranteed by derivation. Radius has no knob in 3.0; density is the `data-density` attribute
  (`basalt-tokens.md`). Full law: `docs/DESIGN-CORE.md`.
- **Lint**: oxlint (NOT Biome). **Format**: oxfmt (NOT Prettier). No ESLint, no Biome, no Prettier.
- **TypeScript**: strict mode, no `any`, type inference preferred, explicit types on public exports
- **Git**: conventional commits, **empty scope** (commitlint `scope-empty: always`), `master` branch
- **Exports**: named only, **no default exports**
- **Files**: `kebab-case.ts`; components `PascalCase.tsx`
- **basalt-ui is ALWAYS a separate commit** (NPM published — lefthook `isolated-basalt-ui` guard)
- **Published subpaths**: `./query`, `./connectivity` and `./data` were dropped or folded in 1.29.0; symbol-level mapping in `packages/basalt-ui/MIGRATING.md` § 2.x to 3.0, history in `docs/repo-reference.md`.
- **Content pages**: a page that is content (docs, marketing, guide, README-like) is Astro with MDX on the `basalt-ui/static` parts and the `--basalt-*` tokens, so one token set serves app and site. A Spec that proposes another stack names why `basalt-ui/static` does not fit.

## Charts

Every cartesian chart composes **`CartesianChart`** (the kinds are `CartesianChart` with fixed marks).
Engine `@tanstack/charts` behind one host; `no-restricted-imports` overrides (`gen-oxlint.ts`) ban `@visx/*` and
the engine's react entry outside `src/charts/host.tsx`. Ground truth: `docs/v3/ARCHITECTURE.md`.

## Layer Boundary

`src/charts/**`/`src/tokens/**` stay free of React UI code (`check-dist-layering.mjs` walks the built graph);
`@tanstack/charts/react` is imported by `src/charts/host.tsx` alone (a `no-restricted-imports` override
`gen-oxlint.ts` projects). Full layering + packaging rationale
(repo-internal, not a consumer contract): `packages/basalt-ui/MAINTAINING.md` § Layering.

## Commands

**Root:**

```bash
bun install                # install all workspaces
bun run dev                # = dev:playground
bun run dev:playground     # start the playground consumer
bun run dev:expression     # start the expression scenarios app
bun run lint               # oxlint: the repo on the 2.x config, then apps/playground and apps/expression on the v3 app preset (0 findings; loads basalt-ui/lint from dist, so build first)
bun run fmt                # oxfmt (write)
bun run fmt:check          # oxfmt (check only)
bun run typecheck          # tsc across package + playground + expression, astro check on marketing (see the dist footgun below)
bun run pre                # fmt:check && lint && typecheck && budgets && literals, then `make test`: the unit suite in a host test slot
make check                 # build + pre + the layout suite + pack-test — the full local gate
make check-fast            # `check` with only the layout files and unit tests the branch's changes reach — the lead's check; CI runs the rest
make test-fast             # just that unit step (BASE=<ref>, default origin/master): bun's module graph plus an always-on set, scripts/unit-select.ts
make layout-fast           # just that layout step (BASE=<ref>, default origin/master)
make astro-matrix          # build apps/playground-astro, measure every part per Astro render mode, check the budgets in docs/v3/verdicts/astro-matrix.json
make regen                 # after a rebase: rewrite every generated file (dogfood links, marketing manifest, matrix .md); no slot
make verify                # probe production (curl basalt-ui.com) — not the local gate
```

**Package (`packages/basalt-ui`):**

```bash
cd packages/basalt-ui && bun run build   # dist-first tsup + styles.css copy + tsc declarations
```

## Validate

Before running the layout suite or changing the Makefile or CI, Read `docs/validation.md`: what `make check` and `make check-fast` run, the test slots, the browser switches and the memory budget.

1. Make changes.
2. Run `bun run pre` to validate quickly; `make check` adds the build, the layout suite and the
   pack-test.
3. Fix errors in changed files only — don't refactor untouched code.
4. Commit with conventional format (empty scope).

The user validates running apps manually — don't start dev servers.

## Deploy

The marketing/docs site (basalt-ui.com) deploys continuously on every push to `master` via RollHook
(`.github/workflows/deploy.yml`); `make deploy` is a no-op that prints `deployed by CI on push`. npm
publishing is NOT a deploy — it is the release process (`make release`, below), gated by
`scripts/release.sh`.

## Gotchas

- **`dist` is read by typecheck and lint.** Both resolve `basalt-ui/*` through
  `node_modules → dist/*.d.ts`, so a new or widened export stays invisible until `make check` builds.
  Never trust a bare `bun run typecheck` on a cold tree — `make check` builds FIRST on purpose.
- **Basalt-ui package changes are their own commit.** The lefthook `isolated-basalt-ui` hook fails a
  staging set that mixes `packages/basalt-ui/` and non-package files.
- **`make verify` probes production; `make check` is the local gate.** They are not interchangeable:
  `verify` makes a network call and does not run the tests.
- **The layout suite never runs in `pre`.** It runs in `make check`, and in part in `make check-fast`, on a headless shell in a host slot; details in `docs/validation.md`.
- **Major lines** (what may ship as a major, and the commit footers that follow): see
  `packages/basalt-ui/MAINTAINING.md` § Major lines; the constants live in `scripts/release.sh`.
- **A workspace-set change carries its `apps/marketing/Dockerfile` COPY edit** — the image copies each
  workspace's `package.json` by name.

## Git Workflow

**Branch**: `master`.

**Commit format** — conventional, **empty scope**:

```bash
feat: add chart legend kind
fix: correct dark-scheme surface var
docs: update README
chore: bump dev dep
```

`commitlint.config.ts` enforces `scope-empty: always` — never `feat(scope):`.

**The basalt-ui separate-commit rule (critical):** `packages/basalt-ui/**` changes must be
committed **separately** from everything else. The lefthook `isolated-basalt-ui` pre-commit hook
fails a mixed staging set.

**Pre-commit hooks** (lefthook): oxlint + oxfmt on staged files; commitlint on the message.

**Commit type discipline** (which types release, and when `feat!:` / `BREAKING CHANGE:` may appear): Read `docs/release.md` before committing a `feat`, `fix` or breaking change.

## Release Process

One channel: `master` publishes to npm `latest`. Release only through `make release`, never by dispatching the release workflow by hand, and never queue a release unasked. Before a release, Read `docs/release.md`: the dry run, the version gate and the registry poll.

```bash
make release-dry   # preview only
make release       # dry run, show the bump, confirm, publish, wait for npm
```
