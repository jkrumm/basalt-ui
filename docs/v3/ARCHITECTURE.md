## 0. Position

1. **The premise is half right, so a library swap is not the plan.** 13 of argo's 234 friction rows are Mantine-structural (consumer-argo); bytes do not justify the move (gap-perf). Every mechanism below serves the other 94%.
2. **One package, four additive profiles** (`tokens`, `bridge`, `parts`, `app`). Shell-less is the base case: `./shell` plugs into `./page`, never the reverse.
3. **Primitives ship in npm, eject per file** (DPO 4, section 4), under one import specifier everywhere, `basalt-ui/ui/<name>`, so the delivery shape stays reversible with no app codemod. The digest's "only measured option" is wrong: gap-dist measured shape D (compiled + eject) too, and shape C (managed copy) beat D on judgement.
4. **"Shell" means the app frame and nothing else** (section 6); the card frame and surface role are `card`.
5. **The guarantee is a floor.** An agent cannot produce an off-system UI; typed frames shape structure; reviewer and owner's eye own taste. `shot detect` scored 100 on boards with 17-19 defects (self-agent-layer).

### 4.3 `basalt()`, peers, CLI

- **`basalt()`** runs where CI does not: deploy builds. At `buildStart` it fails, naming the exact command, on (a) an imported subpath's missing peer (`bun add ...`; argo 6.2 "fail the build"), (b) an ejected file whose recorded seed digest differs from the installed one (`basalt-ui sync`). Keying on the seed digest, not the package version, means a release that does not touch an ejected seed asks nothing of anyone. When ejects exist it also sets the alias, `ssr.noExternal` (gap-dist 6: `ERR_MODULE_NOT_FOUND` without it), and `optimizeDeps.exclude` for composite subpaths (F, same run: nothing pre-bundled; real-app HMR is U, F9). With no ejects it sets none of these; un-ejected SSR without `noExternal` is J, the `linewatch` fixture proves it. CSS: `basalt()` regenerates `.basalt/sources.css` each run from a scan of `basalt-ui/*` imports plus a build-time closure table (`@source` is dir-granular, F gap-dist): positive per subpath, `@source not` per unused `ui` module, so it cannot go stale. Non-Vite and `bridge` consumers take the full scan under the 12 KB ceiling. `basalt()` also absorbs `basaltAppPlugin`: it injects `themeScript` through `transformIndexHtml` and owns theme-color, manifest and the PWA half; the anti-FOUC `<style>` is deleted.
- **Peers:** zero required, all optional, so `tokens` installs no React and no Tailwind (console's 19 MB Mantine, epos's rejection). That reopens rb `3517e01` unless all five hold: barrel rule; `required-peers` test; frozen-install fixtures; `init` writes a profile's peers; the `basalt()` failure above. Pins (digest row 23, decided once): exact for lint-bound and pre-1.0 (oxlint, oxfmt, `@shadcn/lint`, stylelint, tailwindcss); tilde for `@base-ui/react`, `@tanstack/react-table`, `@tanstack/charts`; caret for react, Query, Router.
- **CLI, eight verbs:** `init --profile`, `sync [--check]`, `doctor`, `eject`, `migrate --from X --profile P [--json] [--check]`, `tokens:css [--accent --neutral --vibrancy --selector --extra --format css|json --out --check]`, `shot` (floor on `data-slot`, never a score), `lint [--file --agent --changed --stats --hook <event>]`. Unknown flag exits 1; skipped is not passed; one project resolver (argo workspace, rb non-file routes); local bin, never `bunx`.

**Charts doctrine** (Issue 964, from expression cycle 1: findings expression-1.1, .14, .26 and .36 lost the form point because the builder took the first kind the catalogue routed it to; census V1 CONFIRMED):

- **Form from the question.** A chart starts from the one-sentence question it answers, then the form that answers it, then the cheapest substrate that draws that form: a shipped kind, `CartesianChart` marks, or the geometry seam (rung 4). A kind is chosen because its form answers the question, never because it is the nearest catalogue row; a form no substrate draws is reported as a gap and drawn through the seam, not substituted.
- **What `primitive-bypass` denies.** Data-mapped marks, SVG or HTML, drawn outside the geometry seam. A mark is data-mapped when a datum computes its position, size or colour (`data.map((d) => <rect … />)`, a `div` whose width is a datum's share). A page may draw any mark through the seam or through `CartesianChart` marks; static artwork (an icon, a fixed grid) stays legal. Until the seam exports ship, the rule keeps its `svg-data-marks` form, whose message names `CartesianChart` marks as the next rung; the seam exemption and the HTML form follow the exports.
- **Where a bespoke form lives.** App code (the page's own chart file) or a recipe, never a new `./charts` export. The Rule of Three (3 or more copies in 2 or more repos, census V2 rule) and the `./charts` symbol ceiling stand (`EXPRESSION.md` hypothesis 3). A form repeated inside one app is extracted into that app's chart file; a fleet-wide one is filed as a kind candidate for review, never extracted by the builder.
