Inputs: `BRIEF.md`, digest 2.12, `ext-ai` (= ext-ai-streaming-mdx), `epos` (= shadcn-epos-teamchat), `self-agent-content`, `gap-perf`, `console`, `consumer-argo`, `consumer-obsidian`, `consumer-shutterflow`. ## 1. Decision summary

1. **AI is a core need, so the surface gets stronger while the runtime shrinks.** `./agent` (6,438 lines, 10,440 test lines, 0 consumers: `self-agent-content` 1.3) dies. What replaces it is presentation, safety and a small catalog: `./content` (`Markdown`, `CodeBlock`) and `./ai` (`partView`, `defineBlock`, `defineCatalog`), plus `expectCatalog` in `./testing`. Five value symbols in this domain. `Prose`, `Callout`, `Toc`, `ArticleLayout` move to `./page` (Exception 1). Slimming: 11.0k source lines (agent 6,438 + content 4,596, `ext-ai` 6) to an estimated ~2.1k (J).
2. **No own chat runtime and no `chatFor`.** AI SDK `Chat` plus `useChat({ chat })` with a component-owned `useState(() => new Chat())` passes StrictMode, Activity, resume, error and insecure-context (S1, S2, S4, S6, S8, S9; `gap-perf` 5.3). The one silent failure is `useChat()` without `chat` under `<Activity>` (S3: truncated at 27 of 86 chars, status `ready`, no error), and a lint sub-check catches exactly that. A module-level `chatFor` had no named consumer (epos uses assistant-ui, argo deleted its chat) and added SSR sharing, eviction and HMR failure modes, so it is deleted before it ships. The claim is **a single-thread mock stream passes**; argo's multi-thread, server-history workload is unproven until P3b (section 3 row 1). A thin runtime returns only on a named consumer (BRIEF clarification).
3. **Model text is never trusted, and the default is fail-closed everywhere.** `Markdown` takes a required `contentTrust` (no default; 2.x defaulted to `'trusted'`, `self-agent-content` D3), typed as a discriminated union: the untrusted arm has no `sanitize` and no `rehypePlugins`. `partView` pins `untrusted`. Untrusted renders no `<img>` at all (alt text), the way epos does (`NoImage`). The `contentTrust="trusted"` lint is not scoped to files that import `basalt-ui/ai` (section 3 row 3). `streamdown`, `rehype-raw`, MDX evaluation are hard zeros.
4. **Engine: react-markdown 10.1.0 + remend 1.4.0 + `blockSplit`.** Our pipeline +56.8 KB gz vs Streamdown 2.7.1 +152.2; 223-235 ms vs 327-339 for 909 token steps; 448 vs 897 DOM nodes; Streamdown's defaults emit an attacker `<img>` and `<link rel=preload>` (F, `gap-perf` 5.2). The `ext-ai` spike gate is closed without a day of integration.
5. **There is a live 2.x security bug: `//attacker.example` passes the `/` allowlist** (`gap-perf` 4.3, `url-hardening.ts:19-20` `startsWith`). It is an image exfil channel. Fix it on the 2.x line now, as its own `fix:` commit, independent of v3 (section 8). The v3 transform is specified in section 4.
6. **MDX is build-time only; models never write MDX.** `@mdx-js/mdx` `evaluate` runs JS; `next-mdx-remote` had CVE-2026-0969 (CVSS 8.8, RCE) and is archived (`ext-ai` 4.2). Two trust tiers now: authored MDX (compiled by the consumer's toolchain) and model output (tool JSON, rendered by `Block`). No MDX compiler is a basalt peer and **a small fixed `mdxComponents` ships in `./page`** (DPO 12a, default pending owner; alternative: no map, and the brief's "strong MDX components" is recorded as unmet in 3.0): anchored headings, `a` through the url policy, `table`, `blockquote` to `ui/alert`, `Callout`, `Steps`, `Tabs` on `ui/tabs`, `Figure`, `Kbd`. It needs none of the four `./content` peers. Typography alone stays the `tokens` answer. `catalog.mdxComponents` and the fenced-JSON tier are still deferred with the other catalog channels (decision 7). P9 renders every entry. **Caller, stated plainly:** the brief and the rebuilt docs site; the fleet has 0 React-MDX files (F, `find`: jkrumm.com's 5 are Astro), so the symbol is on notice under adopt-or-delete.
7. **One definition, two channels now.** `defineBlock` yields the validator and the renderer. The model prompt, the JSON Schema for the tool, `mdxComponents` and the ` ```basalt:<name> ` fenced renderer are **deferred to the first Issue that names a caller**: epos's server is Python and owns its tool, prompt and `schema.json` (`epos`), jkrumm.com re-implements MDX components in Astro, argo has no AI surface. Epos, assistant-ui spec mode and json-render converged on the same shape (`ext-ai` 3, J); we write ~200 lines instead of adopting json-render 0.22 (0.x, vendor-led). zod is the only schema library the evidence uses; `props` is typed as Standard Schema, which `validate` needs and nothing else.
8. **Built-in blocks cannot live in `./ai`.** The layer contract allows `ai -> content` only; a stat, chart or table block imports `./cards`, `./charts`, `./table`. So blocks are app-owned seeds over the composites, with `sample` fixtures and a contract test. The seed set is the six of section 4 (stat, chart, table, callout, list, layout); it arrives as a playground region surfaced by `docs/recipes/ai-blocks.md`, because the `add` verb is refused and the recipe channel is the compiled source. On-brand holds for geometry, because the composites own it; it does **not** extend to the data, so `validate` applies a URL policy and size limits (row 11).
9. **Chat chrome is not shipped, and a recipe is its legal source** (DPO 12: no chat parts; alternative: `Message`, `Composer` in `./ai` if P6 shows the recipe drifts). At profile `parts`, `@/components/ui/*` is banned unless ejected and `shadcn add` does not apply, so shadcn's parts are no source. `docs/recipes/chat-thread.md` is, compiled on `ui/*` only and copied to `src/components/chat`, outside `components/ui`, so no eject is spent: message without a bubble (section 8), composer laws A13, `partView`, one polite region. Scroller choice is P12. `one-look` and the layout suite carry a thread fixture, so two AI apps get one thread. `partView` renders what a model _produced_: text and tool parts. Reasoning, approvals, sources and citations come from Tuff and AI Elements, no basalt or epos consumer uses them (`ext-ai` census; grep of `epos`), so they are recipes in the reference until a consumer names them.
10. **Take-what-you-want gives one look, and the claim is bounded.** Typography is `.vx-prose` on tokens (works at the `tokens` profile with no React), blocks render through the composites, `partView` uses only `ui/*`, and the `one-look` fixture renders a markdown sample (P8). At the `tokens` and `bridge` depths the look holds through `.vx-prose` and the lint rule only; the consumer keeps its runtime and components. No composite accepts a `className`; a layout class goes on a wrapper element and styling hooks are `data-slot` selectors (section 2).
11. **The premise check.** Only the Mantine-coupled half of this domain is lost by the move (913 CSS lines, `Collapse`, `Drawer`, 6 of 9 `agent/chat` files). The laws were never Mantine's: 35 invariants (A1-A16, C1-C19) are Mantine-free and port as tests first (section 5).

Tools read the schema directly, so `jsonSchema()` has no AI SDK caller and stays deferred; a Python server (epos) owns its own schema. `prompt()` stays deferred for the same reason: the tool's `description` is the model's description.
**URL policy (F on the problem, J on the rule).** 2.x `isAllowedUrl` is `url.startsWith(prefix)` and the untrusted image default is `['/']`, so `//h` and `/\h` pass; 2.x `resolveRelativeUrl` also returns `//` unchanged. A scratch run shows that parsing against a sentinel origin also exposes `/<TAB>/h`, ` //h` and `\\h` (all resolve to origin `h`), which a "not followed by `/` or `\`" string rule would miss. v3 rule: reject an input with C0 controls or leading or trailing space; classify the rest by `new URL(u, 'https://x.invalid')`; same-origin means the resolved origin is the sentinel; otherwise allow only protocols `https:`, `mailto:`, `tel:`; return the input unchanged only when it is same-origin or allowed, so `#anchor` and `a/b` keep their meaning and no parser differential exists (the parse is what the browser does). **Untrusted** additionally rejects any backslash. **Trusted** does not: authored vault paths may contain one, and the parse already classifies `/\h` as another origin, where trusted images and links allow `https:` anyway. Remend sentinels (`streamdown:incomplete-link|image`) are rejected first (C6).
