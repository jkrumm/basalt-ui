# Basalt UI v3 concept: Data Table

Date 2026-11-09, revised against the adversarial review (Review Log, last section). Domain concept under `docs/v3/ARCHITECTURE.md` (section 8 shape). Tags: **F** run or read (cited), **J** judgement, **U** unverified. Slugs as in the digest (`ext-table`, `gap-perf`, `gap-a11y`, `gap-controls`, `self-table-data`); `I1`-`I27`, `R1`-`R9`, `M1`-`M10` are the numbered rows of `self-table-data`. **DPO** = DEFAULT-PENDING-OWNER, register in contract section 12.

## 1. Decision summary

1. **The problem is shape, not library.** The 2.x table is a 2,232-line, ~90-prop component with uncontrolled `initial*` state and three phone mechanisms (self-table-data R1-R9, M1-M10); 6 of 10 repos hand-roll tables. Mantine's `ScrollArea` caused one bug class (I13). Owning the markup removes that class; every other cause needs our own API to change.
2. **Engine:** `@tanstack/react-table` `~9.3.1` through `createTableHook`, one closed **10-feature** set at module scope (8 plus grouping and expansion, DPO 9). Most consumers want less: resize, reorder, tree, export and per-table density have no consumer and wait, each additive (contract section 10). `@tanstack/react-virtual` `~3.14.26` is injected by value from `ui/virtual-list`: a non-virtual table pays neither its install nor its bytes.
3. **Columns are kinds, not cell renderers.** `c.money('amount')` decides alignment, numerals, width, skeleton, sort, filter, card slot, default priority. `col.custom` is the one counted escape. Columns are plain per-render values: closures over `meta`, labels and mutations are free, identity does not matter.
4. **State is one serialisable value**, split on purpose: `TableState = { v, request, display }`. `request` is the query key, so a display toggle can never refetch. It binds through a `FieldHandle`; `initial*` props do not exist. Filters the page owns stay outside and reach the table through `resetOn`.
5. **One DOM, one render path.** Native `<table>` with explicit roles and `table-layout: fixed`, widths owned by kinds. CSS container tiers from `priority` decide columns and the card projection. No layout decision is measured, so server HTML is already the right tier. Virtualization uses spacer rows in the same table.
6. **Phone:** `phone: 'cards'` by default, derived from kinds, and they lose nothing (toolbar sort, explicit Select mode, kebab, detail sheet, the one editor kind). `phone: 'scroll'` for numeric matrices. There is no free card renderer: argo's bodies port to slots or force a new slot (S4). No public reference solves this (ext-table section 0.1); this design is ours and is **conditional on VoiceOver spike S1**, with a bounded fallback.
7. **Sticky is derived, not a prop.** The header sticks to `Main` under `--page-sticky-top` (the shell concept's law) while the table has no horizontal scroller, and inside the table's own scrollport when it has one. Tiers make the first the normal case; no prop can promise what the geometry refuses, so R6 stays unrepresentable.
8. **Honesty is structural.** `mode` is a discriminated union: `rowCount` (`number | undefined`) xor `cursor`; "of N", server select-all and footer totals exist only when the server supplied the number (I1).
9. **Adds zero lint ids** (16 of 18 used). `primitive-bypass` and `import-boundary` catch hand-rolled `<table>` and engine imports; a CSS-grid list of divs imports nothing and is not lintable, so it is a census entry, not a guarantee.
10. **Take less is a ladder:** static `ui/table` (no engine), `DataTable` with defaults, props, parts, headless (section 7).
11. **DPO 9**, as the digest recommends except inline editing, where argo's own code refutes "none":

| DEFAULT-PENDING-OWNER (DPO 9) | Default taken                                                                           | Alternative                                                                                                                  |
| ----------------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Phone default                 | `cards`                                                                                 | `scroll` as default; cards opt-in                                                                                            |
| One component vs parts        | `DataTable` assembled from 4 exported parts                                             | Parts only, no default assembly                                                                                              |
| Saved-view scope              | Personal, device-local through `ViewStore`                                              | Shared editable views with permissions in 3.0                                                                                |
| Inline editing                | One typed kind `c.select`, saved per cell; no `DataGrid` (E6)                           | None: argo's categorise-in-place becomes one detail-sheet click per booking                                                  |
| Grouping                      | Declared `group` in client mode, collapsible group rows, summary, +2.1 KB gz (F, below) | Stay ungrouped: the owner's `inspo/x-reference.jpg` grid (Floor 2, 5 rooms, 4/5) is not reproducible in 3.0 without app code |

## 4. Public API sketch

```ts
// src/table/contract.ts: types only, pinned by check-contract-frozen
type Priority = 1 | 2 | 3
type CardSlot = 'title' | 'subtitle' | 'badge' | 'value' | 'meta' | 'edit' | 'detail' | 'hidden'
type FilterModel = { id: string; op: 'contains' | 'anyOf'; values: readonly string[] }
type TableRequest = {
  q: string
  filters: FilterModel[]
  sort: { id: string; desc: boolean }[]
  page: number
  pageSize: number
}
type TableDisplay = { visibility: Record<string, boolean>; collapsed?: readonly string[] }
type TableState = { v: 1; request: TableRequest; display: TableDisplay }

type Mode =
  | { kind: 'client' }
  | { kind: 'server'; rowCount: number | undefined; facets?: Facets; totals?: Totals }
  | { kind: 'server'; cursor: { hasNext: boolean; fetchNext(): void }; facets?: Facets }
type Selection =
  | { kind: 'ids'; ids: readonly string[] }
  | { kind: 'all-matching'; request: TableRequest; excluded: readonly string[]; count: number }
type View = { id: string; name: string; state: TableState }
type ViewStore = {
  list(table: string): Promise<View[]>
  save(table: string, v: View): Promise<void>
  remove(table: string, id: string): Promise<void>
}
type RowAction<T> = {
  key: string
  label: string
  onClick(row: T): void
  icon?: IconComponent
  disabled?(row: T): boolean
  loading?(row: T): boolean
}

type Scrollport = 'fill' | { maxRows: number }
type DataTableProps<T> = { table: DataTableInstance<T>; detail?: DetailHost } & (
  | { height?: 'auto' | Scrollport; virtual?: never }
  | { height: Scrollport; virtual: VirtualLike }
) // VirtualLike lives in core/ports.ts: no composite .d.ts may name ui/*
type UseDataTable<T> = {
  id: string
  label: string
  columns: readonly KindColumn<T>[]
  data: readonly T[] | undefined
  getRowId: (row: T) => string
  mode: Mode
  state?: StateHandle<TableState>
  phase?: Phase | QueryStateLike
  resetOn?: readonly unknown[]
  phone?: 'cards' | 'scroll'
  cardsBelow?: 'regular' | 'wide' | 'always'
  pager?: 'pages' | 'more' | 'none'
  group?: {
    by: string
    summary?: (rows: readonly T[], box: Box) => ReactNode
  } /* type error unless mode.kind is 'client' */
  selection?: { bulk: BulkAction<T>[]; selectAll?: boolean }
  views?: { store?: ViewStore }
} & (
  | { detail: (row: T, box: Box) => ReactNode; onRowActivate?: never }
  | { onRowActivate?: (row: T) => void; detail?: never }
)
```

```tsx
const c = col<Booking>() // module scope: carries T, nothing else
export const bookingsTable = c.codec(
  { payee: 'entity', amount: 'money', state: 'status', at: 'relativeTime' },
  { defaults: { sort: [{ id: 'at', desc: true }] } },
)
// routes: defineControls({ id: 'bookings', scope: 'page', resets: ['page'], fields: { from: field.enum(MONTHS, ''), table: field.composite(bookingsTable) } })

const [value] = bookings.table.use()
const from = bookings.from.useValue()
const q = useQuery(bookingsList({ from, ...value.request })) // display toggles never touch this key
const columns = [
  // per render: closures over categories, curate
  c.entity('payee', { header: 'Payee', href: bookingLink }),
  c.money('amount', { currency: 'EUR', footer: 'sum' }),
  c.status('state', { options: STATES, tone: stateTone, filter: 'multi' }),
  c.select('category', {
    label: (r) => `Category of ${r.payee}`,
    options: categories,
    commit: (r, v) => curate.setCategory(r, v),
  }),
  c.relativeTime('at', { priority: 3 }),
  c.actions([{ key: 'rule', label: 'Make rule', onClick: makeRule }]),
]
const t = useDataTable({
  id: 'bookings',
  label: 'Bookings',
  columns,
  data: q.data?.rows,
  phase: q,
  getRowId: (r) => r.id,
  resetOn: [from],
  mode: { kind: 'server', rowCount: q.data?.total },
  state: bookings.table,
  selection: { bulk },
  detail: (row) => <BookingDetail row={row} />,
})
return <DataTable table={t} detail={asideHost} /> // virtual={VirtualList} height="fill" for 10k rows
```

**Anatomy, `data-slot` (frozen per major):** `table-root`, `table-toolbar`, `table-search`, `table-filter-add`, `table-chips`, `table-chip`, `table-sort`, `table-display`, `table-views`, `table-scroller`, `table`, `table-head`, `table-header`, `table-body`, `table-row`, `table-cell`, `table-select`, `table-edit`, `table-expand`, `table-actions`, `table-card`, `table-foot`, `table-pager`, `table-bulk`, `table-empty`, `table-error`. **Phases:** `data-phase` on `table-root`: `ready`, `loading`, `error`, `empty`, `stale`.

## 6. State, tiers, phone, a11y, print, i18n

**Where each slice lives**

| Slice                      | Default lane               | In a view                 | In URL                          | Note                                       |
| -------------------------- | -------------------------- | ------------------------- | ------------------------------- | ------------------------------------------ |
| `request.q, filters, sort` | URL, replace               | yes                       | explicit, or `view` while clean | Same write resets page                     |
| `request.page, pageSize`   | URL, replace               | `pageSize` yes, `page` no | explicit                        | Omitted for cursor mode                    |
| `display.visibility`       | device `basalt:table:<id>` | yes                       | never                           | A shared link does not force columns       |
| rowSelection               | memory                     | no                        | never                           | Internal or caller-owned, not `TableState` |

Without `state`, the table holds its own memory handle and needs no router (linewatch). Views default to `basalt:table-views:<id>` in the frozen `{v,value}` envelope; a server `ViewStore` over `createSyncedState` is the documented path, unused in 3.0. v9 traps pinned in tests: one owner per slice (external atom wins over `state`, so `state` + `on*Change` only); `table.reset()` does not reset an external owner, so reset goes through the handle; features object identity stable; methods on the instance, never destructured (F, `table-core/skills/table-state`).

**URL grammar v1** (normalise, never reject; defaults absent). Frozen per major (contract 4.4), so v1 holds only what a consumer backs (finances: enum facets and search; argo: one sort, page, size). Operators, column lists and tombstones are additive later.

| Param          | Example                             | Rule                                                                                                                        |
| -------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `view`         | `?view=open`                        | Replace, not push. Only while the state equals the view; an unknown id normalises away                                      |
| `q`            | `?q=acme`                           |                                                                                                                             |
| `f.<col>`      | `f.state=todo,done`, `f.payee=acme` | Text or enum values of a filterable kind. Comma in a value is escaped by the codec. Page filters never take the `f.` prefix |
| `sort`         | `sort=at.desc`                      | One entry in 3.0                                                                                                            |
| `page`, `size` | `page=2&size=50`                    | 1-based. Out of range corrects only once the count is known, by replace write; while pending the param is untouched         |
| prefix         | `prefix: 'b'` gives `b.sort`        | Second table on a page must set one, else "two fields on one param" throws                                                  |

Carried traps from gap-controls: `[strip, retain]` order, Router JSON-parses `?item=123` so string codecs accept numbers, deleting a retained key does not clear (write undefined). Unknown column ids are pruned and warned in dev, never an error. Filters shared across routes (`from`, `to`) stay `retain` keys on the store.

**Tiers (CSS only, in `@layer basalt`, on `table-root` as `@container`)**

| Tier                       | Inline width                                            | Priority 1 | 2         | 3                              | Other                                                                                   |
| -------------------------- | ------------------------------------------------------- | ---------- | --------- | ------------------------------ | --------------------------------------------------------------------------------------- |
| full                       | >= `data-full-at`                                       | shown      | shown     | shown                          | All columns                                                                             |
| reduced                    | 480 to `data-full-at`                                   | shown      | shown     | hidden, `table-expand` appears | Priority 1+2 fit by plan                                                                |
| card (`phone: 'cards'`)    | <480 (`cardsBelow: 'wide'` moves it to <800, linewatch) | slot plan  | slot plan | slot plan                      | `thead` visually hidden, never `display:none`; tick only in Select mode; toolbar `Sort` |
| scroll (`phone: 'scroll'`) | <480                                                    | shown      | shown     | hidden                         | Identity pinned, horizontal scroll inside `table-scroller`, page never widens (I14)     |

`plan.ts` sums kind widths and floors and emits `data-full-at` from a closed set (800, 1000, 1200, 1440, 1800), so a 14-column catalog holds its reduced tier up to 1200 and does not overflow on the way; this is pure and SSR-equal. A sum above 1800 stays reduced, with a dev warning. If priority 1+2 exceed 480 the card or scroll threshold moves to 800; above 800 the trailing priority 2 demote. Clipped content is therefore impossible by plan, and the widths are `ch` estimates S3 checks. The graded fold of argo's catalog (priorities 0-11) becomes two steps; S3 prices that. Render path: `table-layout: fixed`; width `100%` (scroll tier `max(100%, var(--table-min-scroll))`), flexible kinds share the rest, `overflow-x: clip` on the scroller except at the scroll tier. This gives equal geometry across phases for free (I8 without measurement) and one path for virtual and non-virtual. Row separators are `box-shadow`, not borders (table-border measurement defect, ext-table). The body is one `<tbody>` in every mode.

Card mode loses nothing (R5): sort in toolbar; `Select` button puts the table in Select mode (`data-selecting`, tick visible, row activation off, toolbar replaced by `BulkBar`); kebab stays; `edit` slots stay live; filters in one sheet; pager compacts to prev/next plus range by CSS. **Reaching hidden columns.** `table-expand` shows only when the tier hides at least one column (card tier: a `Details` kebab item) and opens the auto sheet. With `detail`, activation opens it and `table-expand` is absent. With `onRowActivate`, activation still navigates and `table-expand` is the only way to the sheet. With neither, activation opens the auto sheet. Layout test: every column's data reachable at 390 px, one fixture per case.

**Accessibility:** native elements with explicit `role=table|rowgroup|row|columnheader|cell` (Roselli; `no-redundant-roles` off in zone S). `caption` from required `label`; `aria-colcount` = visible set incl. tier-hidden, `aria-colindex` per cell (I9); `aria-sort`. In the card tier each `meta` cell carries a real `<span data-slot=table-cell-label>` from the column, hidden above the tier; S1 decides whether it needs `aria-hidden`. Scroller is a named `role=region`; it takes `tabindex=0` when it holds no focusable row (static decision from props, replacing I9's measurement, per Roselli 2026-10-06 and AGWG #3029; re-tested in S1). One polite `role=status` announces result count, selection count, sort on settle. Page-size `Select` and pager named (axe criticals, gap-a11y). Coarse pointer: `min-h-11` rows, 44 px hit floors.

**Print:** tier rules reset to full, scroller unclipped, `thead` repeats, `tr` avoid-break; virtual tables print mounted rows only (gap-a11y leaves this open). **SSR:** tiers and cards are correct in server HTML; no observer before hydration; `relativeTime` uses `useNow`, same locale and zone on both sides. **i18n, `BasaltMessages` keys:** `table.rowRange`, `.rowRangeUnknown`, `.selectRow`, `.selectAll`, `.selectedCount`, `.allMatching`, `.empty`, `.pageSize`, `.pagePrev`, `.pageNext`, `.filters`, `.filterAdd`, `.chipRemove`, `.sort`, `.display`, `.views`, `.viewSave`, `.viewReset`, `.details`, `.resultCount`; plurals via `Intl.PluralRules`.
