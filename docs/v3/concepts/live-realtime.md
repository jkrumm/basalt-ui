## 0. Decision summary

1. **The premise "Mantine limits us" is false here: 0 of the live friction is Mantine.** Live is L2 logic; the rewrite changes only two small views (`ConnectionIndicator`, `RefreshButton`). The pain is that six stacks share no code (`ext-realtime` section 0): console and shutterflow stream app-wide, epos, rollhook and image-gateway stream per resource, argo, rb and linewatch only poll. **The two halves have different weight:** argo records polling as 1 of 234 friction rows (`consumer-argo` row 11), so the push half (`createChannel`, `bindInvalidation`, `pushed`) serves console, shutterflow, epos and rollhook, and is sequenced behind `liveQuery` (section 10). Argo has **15 active `refetchInterval` sites** on master `f5c49ca6` (F, grep over `apps/dashboard/src`, non-test, non-comment; the report's 25 predates moves), **7 of them call-site spreads** `{...usageQueries.pace(), refetchInterval: REFRESH_MS}` (cadence in the component, not the query) plus **1 opt-out override** (`vault.ts:75`, `refetchInterval: false`).
2. **One declaration per query, not one hook per transport.** `liveQuery(queryOptions, freshness)` with four closed classes: `static`, `standard`, `ticker`, `pushed`. It returns plain `queryOptions`, never a hook, so loaders, `useQueries` and prefetch keep working and the server stays inert.
3. **One push transport: SSE over `fetch` + `eventsource-parser` 4.1.3**, behind a pluggable `Transport` seam. Native `EventSource` cannot send headers or read a status (rollhook and epos already left it; shutterflow documents the 401-closes-for-good trap). WebSocket, WebTransport, leader election, `streamedQuery`, TanStack DB are not wrapped (kill list).
4. **Invalidate is the default; `patch` is the explicit exception** (shutterflow folds `job` and `progress` frames into one `['jobs']` entry, `useJobs.ts`; argo patches a drag control). Failure direction is conservative: an unparseable or unknown frame invalidates every `pushed` query; a **gap** (frames possibly lost) invalidates what `onGap` says (default all `pushed`).
5. **Connection is a derived verdict, never stored.** Offline = the browser says so (Query's `onlineManager`, one source) OR three consecutive **classified network failures** (4.3) with no HTTP response since. A 4xx/5xx, a parse error or a third-party failure is not offline. This corrects console's "any errored query is Offline, and every write disabled" (`ext-realtime` section 2, defect 1).
6. **Challenged evidence.** `ext-realtime` section 5 has the connection store drive `onlineManager.setEventListener`. Rejected: a heuristic that flips `onlineManager` false pauses every fetch, removing the only recovery signal in a channel-less app (argo). The store reads `onlineManager`, never writes it.
7. **Two consumers of the channel have no TanStack Query** (epos: stores + effects; rollhook: hand fetch, `consumer-rollhook` line 51). So `createChannel` is Query-free and lives in `.`, not `./data` (E1).
8. **Persistence, deploy-staleness gate, multi-tab, the write hook: recipes.** `useSettle` (1 consumer, overlaps `optimistic()`) and `safeToReload` (10 lines, 1 consumer) leave the contract allocation (E1); no spare symbol or subpath is used (digest row 24).

## 4. Contract and composition

### 4.1 Anatomy, phases, cursorless servers

`ConnectionIndicator`: dot (`Status`) + word; popover rows stream, last event age, data age. `phase` mapping (glossary): `ready`, `loading`, `error`, `empty`, `stale`; `stale` = data shown and `FreshnessView.fetch` is `stale` or the last refresh failed. Paused without data renders Offline copy, not Loading (today folded into pending, `query-state.tsx:213`). `QueryStateLike` stays UI-free; `dataUpdatedAt` is added only as an optional field.

**Cursorless mode** (`resume` absent; shutterflow's Axum `/api/events`: no `id:`, no cursor, a lagged receiver is dropped silently, F `routes/mod.rs` `events`, `broadcasted`). Loss is then undetectable, so three rules: (a) a reconnect after the stream was live is a `reset: 'gap'`, and `bindInvalidation` applies `onGap` (not the `all` default unless the app keeps it): shutterflow's predicate keeps the cloud manifest out of every reconnect; (b) `pushed.safety` is mandatory and is the only bound on silent server-side lag; (c) the server checklist names two optional server changes (an `id:` per event, a `lagged` frame or close when a receiver falls behind) that turn (b) into a detected gap. Tested: P0 silent-lag case.

### 4.2 Poller rules (a tick is skipped when)

Hidden (Query's `focusManager`, the one visibility truth for polling) unless `background`; offline (`onlineManager`); `isMutating({mutationKey}) > 0`; the query errored with status 401/403 (rb's ~1000 req/s loop, `consumer-rb`); a fetch is in flight. Otherwise `refetchQueries({queryKey, exact, type:'active'}, {cancelRefetch:false})`; Query already skips disabled and `staleTime:'static'` queries (F `queryClient.ts:313-330`). `pushed` reads the channel status through the client runtime and reschedules on change.

**Staleness follows the class.** `ticker`: `staleTime = (q) => { const e = every(q); return e === false ? 30_000 : e }` (a `??` would let `false` through and Query reads it as 0: argo's Garmin returns `false` when idle, `use-garmin-sync.ts:47-51`) and `refetchOnWindowFocus: true`, so a paused hidden tab pulls once on becoming visible when stale instead of waiting a full `every` (argo `gym.ts:38-43`, 5 minutes for usage and radar). `pushed`: `staleTime = safety`. `record-header`'s `visible ? 2000 : false` is deleted, not rewritten: the default background pause replaces it.

**Observers.** Cadence is per query, declared in the factory; an observer cannot change it. With no poller there is no observer counting (the paragraph that counted **enabled** observers for it is gone, P1 drop 2026-11-11). On a class disagreement between observers of one hash the least active class wins and dev warns; that rule stands independently of the poller. Not measured by P1, so not claimed (P3 and P1b own them): observers on one key with different `refetchInterval` values, a request slower than the interval, a hidden tab, `enabled: false` observers, a fetch that errors. Consequences against argo: `useGymSync` and `useWorkoutDraftSync` lose their "mount once" rule and the vault bar's `refetchInterval: false` second-observer override disappears because the factory owns the option. P1 found that argo's comment ("six staggered timers ... six times per interval") does not hold on Query 5.104.1 or 5.107.1 in the measured scenarios (same options on every observer, no error, a request shorter than the interval, a visible tab); a comment correction for the argo wave (G5), not changed here. Conditional cadence stays in `every(q)` (Garmin `in_progress`, finance `syncing`). Shutterflow's SSO poll (`useCloudSession(step==='sso' ? {pollMs} : {})`) is re-pointed at the `cloud-session` event it already receives, a `pushed` query with `bindInvalidation` mapping that event to `['cloud-session']`.

**Dev asserts** (literal `process.env.NODE_ENV` read): a `meta.basalt.live` query fetched on a client without the runtime throws (`liveQuery` wraps `queryFn` and checks `ctx.client`); an observer overriding `staleTime` or `refetchInterval` set by the class warns.

### 4.3 Offline classifier

`statusOf()` in `query-client.ts` returns `undefined` for every error without a numeric `status`, so it cannot define "network". A **network failure** is a `fetch` `TypeError` or the marker error `NetworkError` thrown by the shared fetch and `unwrap` path; a thrown ZodError, a shape error, `unwrap`'s null-data throw (the "204 trap") and any app error with or without `status` are not. Only queries carrying `meta.basalt.live` and not `external`, and the channel's own connect failures, count. A response of any status resets the count. Tests failing-first: three ZodErrors keep `live`; three failed third-party (`external`) polls keep `live`; three `TypeError`s go `offline`; a 503 resets.

### 4.4 Live lists: one thing owned here

This concept owns only **unchanged row identity**: a refetch keeps structural sharing on, per-response stamps are stripped by `select` (console `queries.ts:62-72`), so memoised rows do not re-render. **Not owned here, handed off:** `getItemKey` prepend stability (I26, `self-table-data`; `data-table` owns `VirtualList`), the "N new" `role=status` pill and the held row under an open menu (cards and table owners, with `isSettled` from `state-persistence-forms`), and transcript follow (`ai-mdx` drops `use-stick-to-bottom`; the scroller is the app's). `EventList` has no virtualiser in 3.0 (`charts-cards-kanban` 3: `Show more`, dev assertion above 200 rows); no exception is filed here.

### 4.5 Synced state seam (shared with `state-persistence-forms`)

The seam, one sentence in each concept: `createSyncedState` takes `freshness?: Freshness` (default `'standard'`; argo gym passes `{ class: 'ticker', every: 5_000 }`), builds its Query options with `liveQuery(..., freshness)` and fills `pauseWhileMutating` with its own mutation key; **adoption of a remote value stays in the state concept** (its settle rule). The `pauseWhileMutating` guard covers only the in-flight PUT; the debounce and settle window (2 s) sit outside `isMutating`, so the state concept's adopt gate is the real L8 protection.

### 4.6 Static is Infinity, not `'static'` (F, settles digest U)

Any observer with `staleTime:'static'` makes the query immune to `invalidateQueries` and `refetchQueries` (`query.ts:292-300` + `queryClient.ts:324`): the same options object used in a loader and a component silently ignores a push, a global refresh and a deploy. `static` therefore maps to `Infinity`. `data-primitive` also flags a literal `staleTime: 'static'` on a `liveQuery` argument. Pinned by P3.
