Re-measured for this document (F): repo state on `docs/v3-planning`, the gap-migration spike output re-classified against the v3 class vocabulary, the test classifier re-run per area, argo's real tracked tree with a second `basalt-ui` under Bun 1.4.3 (section 6.1), `commit-analyzer` 13.0.1 on this repo's config, the friction ledger re-partitioned. ## 0. Decision summary

1. **Same name, `basalt-ui`; 3.0 is sanctioned by changing the doctrine and the gate on purpose** (DPO 2; alt: new package name). No routing around: `version_gate` is rewritten and the doctrine commits land before the first breaking commit.
2. **The doctrine gets one home.** The flip costs 9 homes today because the rule was copied. After it, the rule is two constants in `scripts/release.sh` (`CURRENT_MAJOR=3`, `PREVIOUS_MAJOR=2`), table-tested; every other file links. The next major is a one-line diff with the owner's reason.
3. **No-majors resumes per line after GA, as a gate default, with the evidence stated** (DPO 2 part; alt: allow a major per line whenever a release removes public symbols). `self-process-lessons` lists no-majors under "did not earn its keep": 29 minors in 25 days, ~2,300 MIGRATING lines. What failed was unreviewed cadence and breaks shipped silently; v3 fixes those directly (rows required, `valueShifts` required, budget ratchet, release-with-a-reason). The ban's cost is now one line, so keeping it is cheap and reversible.
4. **One channel** (DPO 3, decided 2026-11-09): master computes and publishes `3.0.0` directly; no prerelease line. Branch `v2` is a plain reference at the 2.x tip with no release config; 2.x stays on npm as published. Keep semantic-release 25.0.9 plain; the `semantic-release-monorepo` shim is a no-op and goes.
5. **Designated commit, one footer.** It must carry a `BREAKING CHANGE:` footer: this repo's default preset parses `feat!:` as no release at all (F, section 13), and 2.0 shipped on a footer too (`86f675f3`). Section 4 lands workflows, then the gate and doctrine, then this commit.
6. **The first 3.0.0 is the owner's go, given on master's evidence**: `make check`, the `apps/playground` build and `examples/*` green on master. The gate refuses every computed version until then, and refuses 3.0.0 without `GA=1`. No consumer repo is a precondition.
7. **2.x is frozen on npm as published.** Branch `v2` is a reference with no release config; consumers stay pinned until they migrate; the one post-GA step is `npm deprecate` (section 4.6).
8. **No two runtimes in one document by default.** Small apps cut over in one PR on a branch. Argo and shutterflow build a sibling app on the default branch, because the factory cannot run a long-lived non-default branch; section 6.1 gives the managed layer a place, proven on argo's tree. The coexistence kit stays unbuilt (DPO 8).
9. **Epos gets G6, on GA** (BRIEF). It answers the non-optional-peers rejection with a frozen-install proof on its own shape.
10. **Two claims are restated.** Codemod fidelity: 375/375 is void for v3; the mapping is kept, the claim is replaced by four separate checks (section 7), and 91.4% clean falls to 85-86%. "150 portable, 136 provider swap" overstates carry-over: per file, 115 port, 29 swap-only, 41 retire because their subject is refused (section 8); a ledger makes every disposition explicit, so no law is lost by omission.
11. **Net-negative becomes a machine ratchet on gated budgets** (raise needs a consumer outside argo), not a line-count gate, which the contract rejects. Repo slims by 7 of 8 top-level docs and all of `docs/waves` on master; `v2` keeps them.
12. **Argo's real cost is 14-21 agent-days, not 3-6** (section 6.3). The 3-6 figure was conditional on name compatibility and unchanged field stores; v3 breaks both.

Scope note: the argo ledger's 13 Mantine rows are already closed or fixed in 2.x, so the move closes none of them; G5's acceptance is the row disposition in section 6.5, not "the port compiles".

## 3. Public API sketch

### 3.1 The gate

```bash
# scripts/release.sh. The only statement of the doctrine; a new major is one edit here plus section 4.5.
readonly CURRENT_MAJOR=3
version_gate <bump> <version> <ga_tag_exists 0|1> <ga_flag 0|1>   # ga_flag = the owner set GA=1
```

| State                        | Accepts                                             | Refuses, with reason on stderr                                                |
| ---------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------- |
| no `v3.0.0` tag              | `3.0.0`, bump `major`, `ga_flag=1` (the owner's go) | every other computed version: any 2.x, any prerelease, 3.0.0 without the flag |
| `v3.0.0` tag exists          | `^3\.[0-9]+\.[0-9]+$`, not major, not `3.0.0`       | any major until the constant changes; stderr names section 3.4's recovery     |
| unparsed bump, empty version | nothing                                             | fail closed                                                                   |

`make release` = `make release-dry` first, then one confirmation on the number; `YES=1` skips only the prompt; a green exit means the registry serves the version; exit 3 means still propagating. Unchanged.

### 3.4 MAINTAINING, section `Major lines` (replaces `The one sanctioned major`, whole text)

> A major exists only when `CURRENT_MAJOR` in `scripts/release.sh` is raised with the owner's reason in the commit, following the runbook section. Between majors commitlint refuses `feat!:` and `BREAKING CHANGE:`; a change that breaks a public shape ships as a `feat:` plus a row in `migrations/`, and a value change ships a `valueShifts` row. Only the current line is maintained; 2.x stays on npm as published and receives no further releases. If a breaking footer reaches master after the designated commit: `git revert <sha>` with the default message, then re-apply as a plain commit. The analyzer drops reverted commits. If the revert is impossible, land a one-release `releaseRules` override (`{"breaking":true,"release":"minor"}`) in a `ci:` commit and remove it in the next one.

### 4.5 GA runbook

(1) GA checks on master: `make check` (build, pre, layout, pack-test), the `apps/playground` build, every `examples/*` that declares `basalt-ui` (`v3-ga-prep` records them; a green `make check` is not enough on its own). (2) Ask the owner for the go; nothing before that. (3) Publish, owner: `GA=1 make release` (3.0.0 on `latest`). (4) Deprecate, owner, interactive: `npm deprecate "basalt-ui@<3" "3.0.0 is latest; 2.x stays on npm as published and receives no further releases. Run: basalt-ui migrate --from <version>"`. F: npm's page lists OIDC for publish, stage publish, dist-tag; deprecate is not listed, so assume login with 2FA (U). (5) Announce in the 3.0.0 release notes; the held rows are re-cut against the published tree and filed.

`basalt.sibling` stays through 3.0.0: argo and shutterflow run a second install after the publish, and its removal is the last cutover's re-cut.

### 4.6 2.x status

No fix window, no `dist_tag_for`, no `latest-2`. 2.x stays on npm as published; the 2.x tip lives on branch `v2` for reference and for port-counts (`origin/v2` is what `git show`, the layout suite's v2 target and the test ledger read). Published 2.x keeps the `//host` URL bypass (`createUrlTransform`, `src/content/url-hardening.ts`); its v3 replacement is `v3-ai-i1-markdown`, and consumers get it by migrating.
