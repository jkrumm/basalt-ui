**Premise challenges (evidence corrected, F):** (a) `ext-state-persistence` and `self-controls-forms` wire `validators: { onSubmit: schema }` and claim live revalidation. Spike A: with `onSubmit` a new invalid value shows nothing until the next submit; only `onDynamic` revalidates. Both docs stay wrong as evidence; the skill follows this concept. (b) `ext-state-persistence` 5.5 claims `isDirty` stays truthful after `reset(draft, {keepDefaultValues:true})`. Spike B: `isDirty` is `false` after restore and `true` after the user reverts. (c) **New, spike E:** `isDefaultValue` ignores fields that were never mounted (lazy tab, accordion, conditional field), so a draft restored into them reads as pristine and the autosave would delete it. Nothing here infers dirtiness from it. (d) "Mantine is the limit" does not apply: zero state invariants depend on it. The fixes target re-growth (3 settings-sync copies, 2 draft copies, 3 envelope copies, 8 raw-storage keys in argo), not the library.

### 3.1 Framework-owned preferences: lane and sync route

| Preference                                   | Lane today                                                              | How it follows the person                                                                                                                                                           |
| -------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scheme                                       | Raw `basalt:scheme`, read pre-paint by the boot script; optional cookie | Cookie for a first paint on a new device; otherwise the app calls `setScheme` from its own record after load, one flash on a new device. The pre-paint script cannot reach a server |
| Rail collapse, section folds, column display | `persisted`, `display.visibility` in `basalt:table:<id>`                | `persisted.setStorage` server adapter (recipe, shutterflow shape): preload, whitelist, serialised PUT, hide flush                                                                   |
| Saved views                                  | `ViewStore`, device                                                     | `ViewStore` adapter over synced state; `save` writes one record per table                                                                                                           |
| Aside width, density                         | Fixed in 3.0 (DPO 17, DPO 6)                                            | Nothing to sync; a user density would join the `setStorage` row                                                                                                                     |

**The adapter is not the `createSyncedState` contract.** It serialises and flushes but has no `rev`, so the last write wins across devices. **S1 clause (S1 passed, so it is a symbol; the clause records why the table does not depend on it):** had `createSyncedState` become a recipe at S1, this table would still hold: `setStorage` is a `persisted` port, and the `ViewStore` adapter works over the recipe.

Row 2 detail is owned by the controls concept; this document fixes only that URL state never touches storage. Remembered-last-value on entry is **not shipped** (DPO 14). Its cost to argo is real: `window-stores.ts` declares 42 fields and 20 carry `persist: false`, so about 20 fields rely on remember-on-entry today (F). Before G5 those are listed in the F4 census; each is either bound per field with `persisted` + `externalField` (recipe) or recorded in MIGRATING as an accepted behaviour change. The four tested remember-on-entry cases stay parked in the controls concept, not deleted.

Behaviour of `createSyncedState` (counted fits: argo gym, epos `settings` and `frame`):

- **Definition is module-scope and inert**: no listener, timer or fetch at import. Runtime state lives in a `WeakMap<QueryClient, Runtime>` created on the first `use()`: per router, per request, per test (kills console's SSR-hostile `startLive`, ext-realtime).
- **Resolution**: pending patch, then Query value (dehydrated on SSR), then mirror (after hydration only), then `initial`. `set` writes mirror and pending patch at once. One writer, serial through the mutation `scope.id = key`; the response `{value, rev}` goes in with `setQueryData`, not `invalidate` (a refetch races the next save).
- **Null server**: when `load()` returns `value: null`, once per runtime the mirror (legacy `basalt:<key>` adopted here, else `initial`) is saved whole with `rev: null`; first device wins (argo `seedAttempted`, accepted for LWW). Without this branch a legacy localStorage profile would be reset to the seed.
- **Refresh**: the Query is built through `liveQuery(..., freshness)`, so cadence, background pause and focus behaviour belong to the live concept; raw `refetchInterval` stays banned. Polling pauses while this state saves.
- **Conflict**: server version, not client clock. LWW transports never conflict. On 409/412: `load()`, re-apply the pending patch, retry once, else `status: 'error'`. Epos's per-field `changedAt` does **not** stamp `rev` per field: it is a client-side counter that stops an in-flight read undoing a newer local edit, never sent and never stamped by a server (S1 corrected this claim, `spikes/synced.md`). The core owns the per-field guard that makes epos pass. Contract-suite requirements from S1: a slow load that began before a save and lands after it must not replace `remote.value` and `rev` with the older snapshot; a `storage` event must update `remote`, and the save base and result must be reconciled with the current local value, so a cross-tab edit is not reverted by the next save in the other tab (a two-tab edit-then-edit case); unsent edits are dropped on an owner switch, by design.
- **Flush and loss**: on `visibilitychange:hidden` send the pending patch with `fetch({keepalive:true})` (64 KiB cap; larger is a normal fetch, best effort). A failed write retries with backoff three times, then `status: 'error'`, pending kept until the next `set`. **An edit unsent at a crash or reload is lost**; no outbox, no Web Lock replay (section 11).
- **Echo**: a `storage` event updates memory and carries an origin flag; it never schedules a write.
- **Settle**: a remote value replaces the local one only when nothing is pending or saving, `editing()` is false and 2 s passed since the last local edit; silent per field unless that field is edited (argo `isSettled` plus the focus half).
