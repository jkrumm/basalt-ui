# State cycle 3

One data page built on master's published surface, fresh after cycle 2's fixes: an orders list with four URL filters (a date range, a status multi-select, a search and a "Flagged only" toggle) in the page bar's `FilterSet`, a table and a chart of the same query behind the page's `ViewTabs`, a pushed list query bound to a channel, a polled fulfilment figure, a connection indicator, and a row that opens an edit form with a draft, validation, `toSubmitErrors` and `FormFooter`. The table opens its record through the kit's own detail door, bound to a URL field (`detailState`). Then the user actions of the brief, run in Chrome against the playground build. Protocol: `docs/v3/CYCLES.md`.

The cycle has not converged: 1 P1, 5 P2 and 1 P3. Cycle 2's fixes reached this page, with two partial: the save that closes the record from its mutation's `onSuccess` leaves no draft behind, the binding starts from `BasaltProvider live` with no effect in the page, `toWindow(values.placed)` compiles with no narrowing, status cells print their labels, a filter with no cached result reads Offline, a `Select` homed by a bare `FormField` needs no waiver, and the matrix finds no clipped ring in the page bar. The P1 is new and sits in cycle 2's detail fix (state-2.11): `detailState` opens only a row the table has loaded, so a link that names a record the current filters exclude (the record just saved out of the list, a shared link, a notification) leaves `order=…` in the URL and opens nothing (state-3.1). The other partial fix is state-2.9: a phone card labels its text values, not its money, boolean or date values (state-3.5). Two P2s are about resetting the filters: the store's `useReset()` also unsets the view tab and the open record (state-3.4), and the table's filtered-empty knows only its own column filters (state-3.3). The app wrote no `useState`, no state `useEffect` and no manual URL read, used no escape hatch, and about 7 lines of glue against cycle 2's 12.
