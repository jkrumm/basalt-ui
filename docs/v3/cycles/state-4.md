# State cycle 4

One data page built on master's published surface, fresh after cycle 3's fixes: an invoices list with four URL filters (an issue-date range, a status multi-select, a search and a "Disputed only" toggle) in the page bar's `FilterSet`, a table and a chart of the same query behind the page's `ViewTabs`, a pushed list query bound to a channel, a polled receivables figure, a connection indicator, and a row that opens an edit form with a draft, validation, `toSubmitErrors` and `FormFooter` through the table's own detail door, bound to a URL field (`detailState`) and opening a record the filters exclude through `detailById`. Then the user actions of the brief, run in Chrome against the playground build. Protocol: `docs/v3/CYCLES.md`.

The cycle converged: 0 P1, 3 P2 and 2 P3. Every cycle 3 fix reached this page but one: a link that names a record the filters exclude now opens it (state-3.1), `useReset({ only })` clears the filters and keeps the view (state-3.4), `ViewTabs` back on Table leaves the URL (state-3.7), the `Switch` keeps its size (state-3.2), and the matrix runs green with no waiver (state-3.6). state-3.5 reached the card's meta values, not its money value, which still stands alone at the right (state-4.3). The new P2s sit around the detail door: closing a record replaces the history entry its open pushed, so Back after any close is a dead step (state-4.1), and a record opened by id is titled with the table label, not the title the same record gets from its row (state-4.2). The app wrote no `useState`, no state `useEffect` and no manual URL read, used no escape hatch, and about 8 lines of glue against cycle 3's 7: the filter-only reset costs 4 lines instead of 5, and the by-id door costs 1 new line.
