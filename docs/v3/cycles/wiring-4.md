# Wiring cycle 4

A fresh Vite and TanStack Router app, built outside the repo from the packed tarball, taken from an empty directory to two pages (an AppShell with one `StatCard` on `/` and one `DataTable` on `/orders`, the same two pages as cycles 1 to 3) by following only what ships: the README, `basalt-ui init` and `doctor`, the managed AGENTS block, the placed rules and skills, `docs/*.md` and `llms.txt`. Then a consistency read of the export surface. Protocol: `docs/v3/CYCLES.md`. It reruns cycle 3 (`docs/v3/cycles/wiring-3.md`) on its three fix rows, all closed done.

The cycle converges: 0 P1, 3 P2 and 5 P3, inside the protocol's bound of zero P1 and at most three P2, so it adds no next cycle. Six of cycle 3's seven findings are fixed and the seventh partly. The trap of cycle 3 is gone: `init` writes the first route tree and turns create-vite's `build` into `vite build && tsc -b`, so the stock `bun run build` is green right after `init` and again after both new routes, and doctor fails a script that runs `tsc` first. The first render takes 16 steps, three fewer than cycle 3, with no step left without a shipped answer, 0 reads of package code, 1 read of a public `.d.ts`, lint clean on the first run and doctor at its floor (12 pass) from `init` to the end, in a git repo and without one. The `Total (EUR)` header is whole and the section heading keeps its word space.

What is left is documentation and type homes. The README's own `./table` example does not compile (`mode: 'client'` where `Mode` is `{ kind: 'client' }`, wiring-4.1). The generated docs skip the four chart kinds the AGENTS block sends an author to, and the primitive docs print style variants where the component props should be, so `badge.md` gives `DeltaBadge` a `tone` it does not take (wiring-4.2). The frame value types moved to `basalt-ui/cards`, but `basalt-ui/charts` still exports five of them a second time, three more (`CardAction`, `Fact`, `FrameHead`) live only there, and `ControlHandle` lives only on the root (wiring-4.3). The rest is naming: two names that each mean a component and a type, two names for the accessible-name prop and for the handle prop, and `rows` in two roles.
