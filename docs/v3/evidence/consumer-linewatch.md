# Consumer audit: linewatch (`~/SourceRoot/linewatch/web`)

Audited 2026-11-09 against basalt-ui 2.29.0 (`web/package.json:basalt-ui`). Read-only. Paths are relative to `~/SourceRoot/linewatch` unless noted. Observed facts are marked FACT, my reading JUDGEMENT.

## 0. Profile

FACT: one-page tailnet dashboard (internet-line monitor). One route (`web/src/routes/index.tsx`, 1149 lines), 62 non-test source files in `web/src`, ~15.8k lines incl. tests and a 1092-line mock generator (`wc -l`). `basalt.shell: false` (`web/package.json:basalt`). No BasaltShell, no nav, no forms, no mutations, no auth, no SSR, no SSE/WS, no virtual lists, no notifications/modals/spotlight use (grep over `src`: zero hits for `EventSource`, `WebSocket`, `useVirtual`, `notifications`, `modals`, `spotlight`, `useForm`). Realtime = two `refetchInterval` polls (`web/src/lib/queries.ts:151` 30 s status, `:220` 60 s router).

JUDGEMENT: linewatch is the purest "components + rules + setup" consumer: a chart-and-stat read-only dashboard. It exercises charts, state stores and the guard layer hard, and exercises almost nothing else. It is evidence for what a la carte must mean, not for the breadth of v3.

## 7. What "a la carte" must mean in v3 (derived from linewatch)

FACT basis: linewatch opted out of shell via a flag (`basalt.shell:false`) and still had to re-derive the gutter, sticky bar, anchor offset and nav-scaffold removal by hand. It still carries shiki/markdown/Mantine addons it never uses.

JUDGEMENT, proposed contract:

1. Installable per part. Each part is independently installable and works with zero other parts: `tokens` (CSS + Tailwind preset), `charts`, `stat/cards`, `controls`, `state`, `table`, `shell`, `content`, `agent-chat`. No part forces another part's peer dependency; `doctor` only checks peers for parts the project enabled (the manifest records enabled parts).
2. Source copy-in (shadcn-style) for components, npm for logic. UI components land in the repo (owned, bendable); `state`, chart engine glue, derive/tokens math and lint plugin stay packages. This removes the 36-bumps-in-3-months churn for UI while keeping guards upgradeable.
3. One unavoidable core: tokens + `cn` + the lint/skills layer. Taking a part never weakens the look: parts read only `--vx-*` (or v3 equivalent) so a la carte yields unified output.
4. Guards are keyed to parts, not to the shell. A rule that exists only because of the shell (gutter, `raw-breakpoint` exempt under `shell/**`) must have an equivalent for a page container primitive shipped in the non-shell core, so shell-less apps do not need `shell/**` exemptions.
5. Rules that cannot be satisfied by shipped parts are bugs (detect font-size limit 3 vs a page using `WidgetHeader`+`StatCard`+axes at 6 sizes; `only-export-components` on routes).
6. Leave open by design: domain composition (what goes into a stat bar), series dictionary, store keys, query windows. Provide helpers (window-key quantiser), not policy.
7. Release discipline for the carve-out: every documented export imported in the pack-test (`foldBands` case), rule changes need a MIGRATING line naming the replacement token, and visual shot-diff per release.
