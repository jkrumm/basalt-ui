# Consumer audit: rollhook (tokens-only consumer of basalt-ui 2.29.0)

Audited 2026-11-09, `~/SourceRoot/rollhook` @ master (277 commits). Read-only. Observed fact is marked F, judgement J.

## 0. One-paragraph truth

F: rollhook imports **zero** basalt-ui JS, zero Mantine, zero React surface. Its whole basalt footprint is (a) the pin `basalt-ui 2.29.0` as devDependency in `apps/dashboard/package.json:30` and `apps/marketing/package.json:24`, (b) the CLI (`tokens:css`, `check-theme`, `sync --check`; `apps/dashboard/package.json:10-14`), (c) one committed CSS emit per app (`src/styles/basalt-tokens.css`, 182 lines each, ~6.9 KB) mapped onto Tailwind v4 `@theme inline`. Shell, nav, router, forms, tables, charts, cards, notifications, state are all hand-built or third-party (recharts, tanstack-virtual, orval, lucide). J: rollhook is the evidence that **the token layer + guard CLI is the only part of basalt a lightweight Tailwind app can take**, and that everything above it (the part v3 is about) is something a small app rebuilds in ~600 lines rather than adopts.

App size (F, `wc -l`): dashboard hand-written TS/TSX ~700 lines (excl. `api/generated`, tokens); `packages/ui` 367 lines (7 components); marketing = 1 Astro page (316 lines) + layout. 9 TSX components total, 51 `className` usages in dashboard+ui.

Why it stalled on 0.4.2 (F + J): the consumer had no signal. The dropped export (`basalt-ui/css`) produced no error because nothing re-resolved the pin; renovate-style bumps were not in play, exact pinning (3b1e4d3 "pin direct deps to exact versions") froze it, and the package name was unchanged so there was no deprecation notice at install. It was found by a fleet-level loop, not by the consumer. Cost to recover: a 1.19.1 migration that rewrote both `global.css` files and dropped 351 lock lines (f2c078b stats: 303 insertions, 378 deletions).

Friction items rollhook itself recorded (`docs/basalt-2.28-bump.md`, git a88ad94; `evidence/w1.md`, f8162df):

1. `shot --out` must be inside the project; monorepo cannot collect shots in one root.
2. Plain Tailwind apps have zero `data-shot` anchors; `shot detect` returns P0 `scan/no-anchors` (score 75) for "nothing measured".
3. Score semantics: one P0 caps 75; marketing scored 0 from 10 findings.
4. `shot` needs Playwright in-app and the install dirties `package.json`/lock.
5. `tokens:css --check` fails on every bump (documented, still blocks `check:basalt` until re-emit).
6. A contrast regression was fixed silently by a token change; MIGRATING did not call the colour shift consumer-visible for tokens-only apps (failed red became pink-leaning).
7. Empty/loading/error states never exercised ("no data-shot-states declared" x42).
8. Marketing spacing findings are Tailwind-native; guard judges `py-20/24` against basalt steps; tokens-only on Tailwind always fails `craft-1/off-scale-inset`.
9. `--vx-faint` light value changed with no MIGRATING row (w1.md "Appendix C candidate 2", filed upstream as ledger row 70).
10. `doctor dropped-subpaths` did not scan CSS `@import` until 2.8.0 (so a stale `tokens.css` import went undetected).
11. `basalt.app` needed when two workspace packages depend on basalt-ui (2.0.2); passes anyway.
12. Peer set pulls Mantine 9.7.2 into `bun.lock` of an app that never renders Mantine.
13. 2.28 token deltas shipped inside a minor with a dark-only app seeing visual change (radius, size, colour); 2.28's `[data-basalt-dense]` block "Mantine variables, inert here" ships dead CSS to tokens-only apps (emit grew 169 -> 183 lines).

### 5.5 Migration cost and risk onto shadcn-based v3

F: rollhook uses nothing that Mantine-to-shadcn changes. If v3 keeps the `--vx-*` emit and `tokens:css` CLI contract, **cost is ~0**: re-pin, re-emit. If v3 renames or restructures tokens (very likely under Tailwind v4 + shadcn naming `--background/--foreground/...`) cost is: rewrite 2 `@theme inline` blocks (~40 lines each) and 38 token references. J: rollhook is the **best candidate for the first v3 adopter** because it is already on Tailwind v4 + `cn()` + `tailwind-merge` + lucide (`packages/ui/package.json:13-14`, `utils.ts`), i.e. shadcn's exact stack; it would replace ~370 lines of `@rollhook/ui` with v3 `Badge`, `DataTable`, `LogView`, and chart.

| Risk                                                                                  | Likelihood | Mitigation                                                                                                                                     |

### 5.6 Lesson for v3 migration communication (the 0.4.2 stall)

J, grounded in section 4:

1. **A dropped or renamed export must fail loudly at install/lint time, not silently.** Ship the final 2.x as a thin `basalt-ui@2.last` with a `postinstall` / `doctor` message: "v3 renames X to Y: run `basalt-ui migrate`". Use `npm deprecate basalt-ui@"<3" "..."` so `bun install` prints it for exact-pinned consumers (rollhook is exact-pinned, so it never sees ranges).
2. **Version the token contract separately from the framework** (e.g. `tokens-contract: 1` in the emit header; `check-theme` fails if app's emit contract is older than CLI). rollhook only needs this.
3. **MIGRATING is machine-read per profile.** rollhook's Wave 1 was a manual read of 21 versions of MIGRATING to find 3 relevant rows. Provide `basalt-ui migrate --profile tokens-only --from 2.29.0`.
4. **Never drop a path without a replacement shim for one minor** (`basalt-ui/css` and `tokens.css` both died with a one-line note).
5. **Fleet notification, not consumer polling:** a consumer registry (this fleet) with a pinned-version probe; rollhook's recovery came from the maturation loop, not from rollhook.
6. **Declare which release lines are supported** and publish the 2.x end-of-life date at 3.0.0.
7. Same package name for a new product is what made the stall silent; consider a new package name or a `basalt-ui@3` dist-tag path with `next` for a full cycle, and keep `latest` on 2.x until fleet probes are green.
