# Consumer audit: shutterflow (Tauri desktop, basalt-ui 1.40.3)

Audited 2026-11-09, read-only, repo `~/SourceRoot/shutterflow` (HEAD 2026-11-08, 1047 commits, first 2026-08-13). Paths are relative to it.
Tags: [F] measured fact (grep/script/run), [J] my judgement. Counts are from real greps unless marked "approx".

## 0. Headline

- [F] Largest UI consumer after argo by _kind_, not by breadth: `apps/desktop` is 31,999 non-test LOC in 267 TS/TSX files, 107 files import `@mantine/*`, 112 import `basalt-ui*`; it uses 67 distinct basalt symbols across 10 of 19 code subpaths. `apps/gallery` (public share SPA, 4,050 LOC) uses basalt only for provider, theme, tokens (`apps/gallery/src/main.tsx:2-6`).
- [F] The app is _frozen on 1.40.3 since 2026-10-05_ (last pin `fc7d055`) while it kept growing: 94 desktop commits since. The 2.x upgrade is wanted (`fleet/owner-feedback-2026-10-16.md:75`) but parked (`fleet/handoff/lead-7.md:7`, `d88a549`), and basalt's own plan marks shutterflow "out of this track, stays on 1.x" (`basalt-ui/docs/waves/handoff/mother.md:90`). So v3 is the _first_ migration, not 1.x to 2.x then v3.
- [J] Its value to v3 is not components. It is the proof of what a **desktop-class shell needs that a web shell lacks**: native title-bar contract, a command registry that feeds hotkeys, help, palette and the native menu, server-mirrored UI prefs, a single SSE hub feeding the query cache, an inspector slot, and imperative canvas regions. Almost all of these were built _beside_ basalt, as app code.

## 5. Desktop-class patterns (what a web-only framework misses)

### 5.1 Window chrome

- [F] macOS overlay title bar: `TitleBarStyle::Overlay`, hidden title, traffic lights at (16,28) (`src-tauri/src/main.rs:123-130`); shell injects `data-native-titlebar="overlay"` before first paint (`main.rs:50-58`); CSS sets `--basalt-shell-lead-inset: 80px` (`shell/native-titlebar.css:8-10`); header row 52 px (`RootLayout.tsx:33,69`); `data-tauri-drag-region="deep"` set by a DOM query (`RootLayout.tsx:21-30`); capability `core:window:allow-start-dragging` (`capabilities/default.json`).
- [J] Basalt gave 3 of 5 needed hooks (`headerHeight`, lead inset var, rail offsets). Missing: a first-class `chrome="native-overlay"` profile that sets inset, height, drag region, and exposes `data-slot` hooks without class-name querying; also a trailing inset for Windows controls (the repo has `check-targets` for win/linux, `AGENTS.md` commands table, but overlay is `#[cfg(target_os="macos")]` only).
- [F] Header real estate: badges + quick actions + job progress share one row that "never wraps; the actions group yields first", 3 documented widths 1024/1200/1440 (`docs/engineering/ux-title-bar.md:57-68`). [J] This is a layout contract (priority-collapsing toolbar) the shell should own.

### 5.2 Panels, inspector, layout

- [F] One right-hand 320 px slot, one owner at a time (info / editor / compare-info), grid re-justifies to the narrower width (`ux-detail-sidebar.md:20-40`). Fixed width: no resize handle anywhere (`rg "resizable|col-resize|splitter"` = 0). Sections: collapsible header button with `aria-expanded/aria-controls`, current value shown while collapsed, per-section open state persisted (`DetailSection.tsx:9-40`). Writes target the marked set when one exists and the panel says so.
- [F] Screens fill the viewport: `h="100%"` + `minHeight:0` flex chains (`PhotosRoute.tsx:160-166`, `AlbumPage.tsx:103,181-207`). Content takes the shell gutter; "a screen adds no outer padding of its own" (`apps/desktop/AGENTS.md:55`).

### 5.3 Keyboard

- [F] ~36 `shortcut:` entries in 11 registry files; one table drives hotkeys, `?` help, Settings > Shortcuts, Spotlight and the native Edit/View/Help menu (menu items dispatch the same chord into the webview, accelerator only displays: `menu.rs:1-4`). Single-key culling (0-5 rating, 6-9 labels, x reject, a album, k keywords, i info, c compare, z 1:1, g/e views: `photos/state/README.md` key table, `ux-detail-sidebar.md:59-66`). Hotkeys "skip only text inputs"; `Mod` chords fire while typing (`commands.ts:12-16`).
- [F] Gaps the app patched: scope (mounted flags), conflict resolution (`bindOncePerKey`), control-activation guard, visibility vs enabled split (`commands.ts:9-17`), `keyboard.spec.ts` asserts every route/viewer/editor Tab stop shows a ring (`docs/engineering/a11y.md:15`).

### 5.4 Canvas / GPU regions

- [F] Editor stage is a WebGL2 canvas (`features/editor/gl/renderer.ts` 364 lines, `shaders.ts`, `affine.ts`), DOM overlay owned outright and mutated per frame (`stage/overlay.ts` 536 lines), pointer handlers imperative and never call `setState` on the move path (`stage/Stage.tsx:1-15`). Store has `live` (mutated per pointermove, no React subscription) vs `committed` (pointerup, stable snapshot for `useSyncExternalStore`) (`model/edit-store.ts:1-25`). Sidebar re-renders once per drag (`EditorSidebar.tsx` header).
- [F] The "0 commits across a 60-frame drag" assertion is cited as `src/lib/drag-audit.ts` (`edit-store.ts:21`) but exists only in `spikes/gpu-preview/src/lib/drag-audit.ts`; the desktop app has no such test. [J] The invariant is stated, not enforced, in the shipped app.
- [F] WKWebView facts that bind design (measured in repo, `docs/engineering/tauri.md:506-538`, source `spikes/wkwebview-probe/RESULTS.md`): no `ImageDecoder`; decode 1.4-2.9x slower than Chrome; evict via `AbortController` not `img.src=''`; `SharedArrayBuffer` absent under custom scheme; `hardwareConcurrency` differs. [J] A v3 perf skill must say "measure in the target webview, not a browser tab".

### 5.5 Perf practice

- [F] Layout from index metadata so nothing shifts (`layout.ts:1-10`); rows mounted = viewport +/-2 (`OVERSCAN_ROWS`, `layout.ts:14`) plus pinned focus/marked; rAF-throttled scroll (`ContactSheet.tsx:60-68`); prefetch one screen beyond where scroll stops, low priority, 220 ms debounce (`grid/prefetch.ts`, `fleet/events.jsonl` P2-03); probe `Image()` high priority because never-ending SSE streams starve default-priority requests (`use-decoded-src.ts:6-12`); single SSE connection (`events.ts:1-8`).
- [F] No code splitting, no `React.lazy`, no React Compiler in `vite.config.ts`. Local-origin app, so acceptable. [J] Fine for desktop; a framework-level perf budget should allow "eager is correct" profiles.

### 5.6 Shell-adjacent state that must survive restarts

- [F] Port changes per launch, so webview storage resets; solution in 5.1/2.1 (`ui-prefs.ts`). Colour scheme additionally mirrored in a port-independent cookie to avoid a flash (`features/settings/appearance/scheme-manager.ts`, `tauri.md:496`). [J] Brief item "persisted user settings synced to the server" is exactly this, reached by monkey-patching because the persistence layer had no adapter seam.
