# Consumer audit: weatherorb (`~/SourceRoot/weatherorb/apps/web`)

Audited 2026-11-09 against basalt-ui 2.26.0 (pin: `package.json:30`; Mantine 9.7.2). Fact = grep/read; Judgement = marked **J**. All paths relative to `apps/web` unless prefixed. Counts exclude `*.test.*` unless stated.

## 0. What the app is (and why it is an atypical consumer)

- TanStack Start (React 19), a prerendered landing at `/` plus a **MapLibre map at `/map`** (`ssr:false`, `src/routes/_app.map.tsx:16`) with floating chrome over a canvas. 86 src files, 14,451 LOC (ts/tsx/css incl. 296-line generated `landing/tokens.css`). Dark only, `createBasaltTheme()` bare (`DESIGN.md` Identity; `src/app/providers.tsx:24`).
- **No shell, no PageBar, no nav, no forms library, no data table (one tiny static `Table`), no notifications, no virtual list, no SSE/WS.** It uses basalt as: provider + theme + tokens + one chart component + lint/skills/rules. (`DESIGN.md` § What this app is.)
- Its state engine (`@weatherorb/engine`: `AppState`, `MapController`) is framework-agnostic and owns the map selection; React is a view (ADR 0016 `docs/adr/0016-frontend-agnostic-core.md`). **J:** the most "own-core, thin-UI" consumer; v3 primitives must work without owning state.
- Hard constraint: landing ships **0 JS**; `/map` gzip <= 704 KiB (ADR 0020, `src/bundle-bars.test.ts`). The provider tree therefore hangs off a pathless `_app` layout (`src/routes/_app.tsx:1-10`), in its own module so the CSS side-effect import stays out of the entry chunk (`src/app/providers.tsx:1-10`).
