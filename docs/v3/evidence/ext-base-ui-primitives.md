# Evidence: Base UI (@base-ui/react) as v3 primitive layer vs Radix, and Mantine v9 parity map

Date 2026-11-09. Scope: primitive layer only (not charts, tables, forms-library choice, routing). Fact = read in code/docs/registry; Judgement = marked JUDGEMENT.

Path shorthands used below:

## 0. Verdict in six lines

1. Base UI 1.9.0 (npm `latest` = 1.9.0, released 2026-10-09, `BUI/CHANGELOG.md:7`) covers ~85% of the interactive primitives basalt uses today: Dialog/AlertDialog, Drawer (swipe, snap points, virtual keyboard), Popover, Menu, Tooltip, Select, Combobox/Autocomplete, Number Field, Toast, Tabs, Scroll Area, Slider, Collapsible, Field/Form, OTP. It is a real replacement, not a downgrade, for everything except the 8 gaps in section 5.
2. shadcn made Base UI the default in July 2026; Radix is not deprecated (R1, shadcn changelog 2026-07-base-ui-default, high). Choosing Base UI is the supported mainstream path, and Combobox/multi-select exist in shadcn only on Base UI (R1).
3. Real gaps (nothing in Base UI, we build or adopt): calendar/date picker, command palette ranking+groups, sliding segmented control, tree, schedule/week-month views, color input, layout/typography primitives (go to Tailwind), toast history/notification center (already ours).
4. Hidden Radix: `cmdk` 1.1.1 (the shadcn Command dependency) hard-depends on `@radix-ui/react-dialog`, `react-primitive`, `react-id`, `react-compose-refs` (`console/node_modules/cmdk/dist/index.mjs:1`). Both shadcn+Base UI reference apps ship it; the Console palette chunk is 90.9 kB raw / 28.3 kB gz and contains `data-radix-focus-guard`. A v3 that wants "no Radix" must not take cmdk.
5. Cost is bundle weight: epos first load 210.8 -> 330.8 kB gz after adopting shadcn/Base UI (`shadcn-epos-teamchat.md:92`, `scripts/check-bundle.mjs:7-14` there); maintainers say Base UI will not reach Radix size, detached triggers alone ~10 kB gz (R1, issue #3688, medium). Mitigation: per-part subpath imports, `sideEffects:false` (`BUI/package.json:53`), lazy chunks.
6. Mantine hooks are a non-issue: 12 import lines, 6 distinct hooks, all replaceable by React state, CSS (`:hover`, `:focus-within`, `motion-reduce:`) or ~10 lines of own code.

## 2. Base UI 1.9.0: what exists (fact)

Public root export list (`BUI/index.d.mts:1-43`): Accordion, AlertDialog, Autocomplete, Avatar, Button, Checkbox, CheckboxGroup, Collapsible, Combobox, ContextMenu, CSPProvider, Dialog, DirectionProvider, Drawer, Field, Fieldset, Form, Input, Menu, Menubar, merge-props, Meter, NavigationMenu, NumberField, OTPField, Popover, PreviewCard, Progress, Radio, RadioGroup, ScrollArea, Select, Separator, Slider, Switch, Tabs, Toast, Toggle, ToggleGroup, Toolbar, Tooltip, use-render. Also public subpaths `./unstable-use-media-query`, `./floating-ui-react`. Per-component subpath imports (`@base-ui/react/dialog`) are the norm (80 export keys, `BUI/package.json:61`). Peer: react 17/18/19 (`BUI/package.json:39`). Installed size 20 MB (unpacked, dev disk).

Not in the list: Calendar/DatePicker, Command/Spotlight, Table, Pagination, Breadcrumb, Badge, Card, Alert, Skeleton, Kbd, Stepper, Timeline, Tree, Sidebar, Resizable, Sonner, ColorInput, Rating, any layout or typography primitive.

Cadence (fact, `BUI/docs/react/overview/releases/v1-*.md` subtitles): 1.0 Dec 11 2025, then 1.1 Jan 15, 1.2 Feb 12, 1.3 Mar 12, 1.4 Apr 13, 1.5 May 19, 1.6 Jun 18, 1.7 Aug 4, 1.8 Sep 4, 1.9 Oct 9 2026: one minor per ~month, no majors since v1. Stable vs preview inside 1.9.0: Drawer stable since 1.3 (`v1-3-0.md`), OTP Field added 1.4 preview, renamed `OTPFieldPreview` -> `OTPField` in 1.6 (`v1-6-0.md`), `Menu.FilterProvider`/`Menu.Input`/`onItemHighlighted` added as preview in 1.9 (`v1-9-0.md`), `unstable-use-media-query` still unstable by name. Pre-1.0 betas had renames in nearly every release (`openMultiple` -> `multiple`, `trackAnchor` -> `disableAnchorTracking`, `loop` -> `loopFocus`, `cols` -> `grid`: `v1-0-0-beta-4.md`, `beta-5.md`); since 1.0 none seen in the notes I scanned. Judgement: pin exact (`1.9.0` as epos and Console both do: `console/package.json:19`), upgrade monthly through a wave, treat `preview`/`unstable` as banned-by-lint until stable.

Calendar status (fact, GitHub PR #1973 read via agw web read): "[temporal] New Calendar component" merged to master 2026-03-13 but NOT in `package.json` exports; maintainer: "we want to iterate on Pickers components before releasing them publicly". `BUI/internals/temporal*` (date-fns, luxon adapters) ships inside the package but is private. DateField/TimeField PR #3666 closed unmerged 2026-04-13; umbrella #1709 open. Judgement: do not plan on a Base UI date picker in the v3 window.

Accessibility stance (fact, `BUI/docs/react/overview/accessibility.md:23-31`): WAI-ARIA APG keyboard patterns, automatic focus management with `initialFocus`/`finalFocus` props (beta-3 notes), but "it's the developer's responsibility to visually indicate focus" and to check contrast (APCA suggested). Labels via Field/Fieldset/Form (`accessibility.md:39`).

## 6. Accessibility and mobile behaviours (what Base UI gives, what stays ours)

### 6.1 Given by Base UI (fact)

- Focus: automatic trap/return, `initialFocus`/`finalFocus` functions (beta-3), `modal={'trap-focus'}` on Dialog/Popover (alpha-8 notes), `loopFocus` on menus/toggle groups (beta-5), roving focus fixed for dynamic items in 1.8 (`v1-8-0.md`).
- Nested layering: `data-nested-dialog-open`, `--nested-dialogs` (`dialog.md:713-717`), nested drawers stack with `--nested-drawers` (`drawer.md:635-637`); backdrop of child dialog not rendered.
- Touch: Drawer swipe with `--drawer-swipe-progress/-strength`, snap points, virtual-keyboard provider, swipe-to-open; Toast swipe-to-dismiss with `data-swipe-direction` and `data-base-ui-swipe-ignore`; Select disables item-aligned positioning when opened by touch (`select.md:551`); Dialog backdrop has an iOS 26 viewport-coverage `@supports (-webkit-touch-callout:none)` branch (`dialog.md:130,563`); Autocomplete command-palette demo uses `any-pointer-coarse:text-base` to avoid iOS focus zoom.
- Announce: Toast `priority` low/high (`toast.md:3743-3748`), F6 landmark jump (`toast.md:458`); Tabs/Accordion/Collapsible `hiddenUntilFound` (`collapsible.md:237`, 1.9 sync expand on `beforematch`, `CHANGELOG.md` 1.9 Accordion).
- SSR: `Tabs.Indicator renderBeforeHydration` (`tabs.md:736`), `CSPProvider`, `DirectionProvider` (RTL), `unstable-use-media-query` double-render for hydration (`index.d.mts` comments). Fine for "SSR and hydration must be allowed" (brief).

### 6.2 Not given, stays ours (and where rules/skills must bite)

- Visible focus rings and contrast (`accessibility.md:23-31`): token-level `:focus-visible` ring + contrast gate (we already have `theme/contrast.test.ts`; keep).
- Touch fallback for tooltips (`tooltip.md:419-432`): rule "no information only in a tooltip on a control that is reachable by touch".
- Esc/focus layering across mixed overlays: epos needed a hand-rolled `layerOpen` and a Modal that "pulls stray focus back every render" when a non-Base-UI drawer sat beside Base UI popups (`shadcn-epos-teamchat.md:95`). Lesson: one overlay stack (all Base UI), no hand-made drawers.
- Test environment: popups mount a tick after click; tests must `await findByRole` (`shadcn-epos-teamchat.md:88`, jsdom). Our 329 test files (112 touch Mantine) need a shared test harness.
- Page rubber-band on macOS/iOS needs `overflow:hidden; overscroll-behavior:none` on html/body (`shadcn-epos-teamchat.md:96` item 6): shell responsibility.
- Mobile >=16px input font-size to prevent iOS zoom: ours (existing `font-size floor` guard, `guard/index.ts:2191`).
