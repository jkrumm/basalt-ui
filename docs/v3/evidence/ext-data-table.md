# External evidence: best-in-class data tables (v3 input)

Read 2026-11-09, read-only. "Fact" = observed in installed source or a read page (cited); "Judgement" = mine. Companion to `self-table-data.md` (basalt's own table: causes of "immature/non-responsive", 27 invariants I1-I27, section refs below are to that file). Employer code is described as pattern only. Research runs: `agw research` x10 (TanStack Table v9, tablecn/Dice UI, Bazza, openstatus, ReUI/MRT, phone patterns, saved views, AG Grid/APG, TanStack Virtual, table a11y).

## 0. Verdict

1. **No public reference solves the phone.** tablecn/Dice UI claim "mobile-first with overflow handling" (no detail); openstatus has only a filter drawer; ReUI free grid = scroll area + pinning (card view is a Pro block); Bazza = a chip strip. Design systems document stacking only in ONS, list slots in Polaris, tap-to-detail in Notion/Airtable/Stripe. basalt's headline requirement (responsive transformation) has to be designed by us from rules in section 6, not copied.
2. **The engine question is settled: TanStack Table v9 (stable 2026-08-04, 9.3.1 latest), through `createTableHook`.** v9 gives basalt the exact "headless yet enforced" lever: a closed, typed feature set per app hook, typed column helper, registered cell/header components. Three independent references (openstatus `col.*`, Bazza `createColumnConfigHelper`, Dice `meta.variant`) converge on **typed per-kind column builders** that decide filter type, alignment and width. That is basalt's `meta.kind`, upgraded from a meta flag to a factory.
3. **Everything good is copy-in source, everything shipped as a package is stale.** tablecn/Dice, openstatus, ReUI are shadcn registry blocks on v9; Bazza (alpha, 818 stars, last changelog 2025-04) is pinned to v8; official Mantine React Table is dead for our purposes (beta.9, Feb 2025, Mantine 7 + TanStack v8). Take concepts and port; depend on none.
4. **Their weak spots are our checklist:** URL round-trip bugs (Dice #1257 operator lost on reload, Bazza Date revival), nuqs + TanStack Router crash (#1268), "virtualized" claimed but absent from the core component (openstatus), stale agent docs (openstatus AGENTS.md/llms.txt still say v8), moving column API (Dice breaking change 2026-11-01).
5. **State is the product.** Every strong table keeps its whole state (search, filters, sort, page, visibility, order, pinning, density) in one serialisable schema that URL, server, saved views and agents all share. basalt already has the carrier (`FieldHandle` lanes, `self-controls-forms.md`); the table must adopt it instead of `initial*` props (M2).
6. **Proposal (section 9):** one `DataTable` composed of exported parts over a headless engine; discriminated `mode`; one state schema with a versioned URL grammar and a `ViewStore` port; CSS-only phone projection of ONE DOM (container queries, explicit ARIA roles, `priority`/`card` slots on kinds); virtualization opt-in on fixed row heights; five lint rules + dev assertions + one skill that defers v9 facts to TanStack's own shipped skills.

A11y facts for the reshape (agw r10, Roselli): Safari 17 (Oct 2023) fixed table semantics under `display` overrides, older WebKit dropped them; Roselli still advises explicit `table/rowgroup/row/cell/columnheader` roles when restyling, testing with VoiceOver, and avoiding `display: contents` on tables. ## 6. Responsive rules for the basalt table (judgement, built on section 5)

1. **Decide per table what the phone is for.** Compare records across attributes = scroll mode; read/act on records = card mode. One enum on the table: `phone: 'cards' | 'scroll'`, default `cards`. Cards destroy column comparison (Accessible Data Interfaces), so numeric matrices opt into `scroll`.
2. **Key on the table's own width, never the viewport** (I11 kept). Tailwind 4 container queries: a `@container` wrapper, `@max-md`/`@max-sm` variants. Baseline-widely-available since 2025-08 per agw r6; the table behaves the same in a full page and in the aside.
3. **Three tiers, CSS only, SSR-stable (no first-paint fold):** wide = all columns; medium = `priority:3` columns leave the row and appear in the detail; narrow = card projection. `priority` is `1|2|3` on the kind; at most two `priority:1` columns (identifier + one value, the old fold floor) enforced by a dev assertion.
4. **Card projection from slots, not from consumer JSX.** Each kind has a default `card` slot (`title`, `subtitle`, `badge`, `meta`, `value`, `hidden`, `detail`); `entity` -> title, `status` -> badge, `money|number` -> value, `relative-time` -> meta. The consumer overrides per column; `renderCard` stays as the escape hatch (then one of two renderers is mounted, never both: `basalt/responsive-twin`).
5. **One DOM reshaped by CSS needs explicit roles.** Keep real `table/thead/tr/th/td` (or divs) with `role=table|rowgroup|row|columnheader|cell` on every element, headers visually hidden not `display:none`, each cell labelled (`data-label` from the column). Judgement: acceptable only after a VoiceOver iOS + macOS Safari pass (spike S1); fallback is the keyed JS switch of today's I11 with a server-safe default.
6. **Card mode must lose nothing** (R5): sort moves to a toolbar `Select` (header hidden), selection stays as a leading tick behind an explicit "Select" mode that replaces the toolbar with the bulk bar (count, select-all, actions) and disables row activation (Carbon, Polaris), row actions go to a trailing kebab and to the detail sheet footer as a bottom action bar (Stripe), filters live behind one `Filters (n)` button opening a sheet (kept from today, `self-table-data.md` R9).
7. **Tap opens detail.** Row activation opens the sheet on phone, the aside on desktop; the sheet renders every column as label/value in priority order, so nothing is unreachable.
8. **Assume no hover.** Actions visible or in a menu; tooltip content reachable otherwise; coarse pointer gets 44 px targets (existing `hit-floor`).
9. **Scroll mode keeps the first column pinned**, opaque, with an edge cue; the scroller is keyboard-reachable; table never widens the page (I14, existing layout tests `no-horizontal-overflow`).
10. **Layout tests are the guarantee:** extend `tests/layout/` to 1440 / 768 / 390 / 360 / 320 for tables with long text, 8+ columns, 0 rows, loading, selection mode, a11y roles present in each tier.

## 8. State and saved views: concrete design

Facts: Notion's API exposes the full view model (`filter`, `sorts`, `quick_filters`, per-property `visible/width/wrap`, `group_by`, `frozen_column_index`, `wrap_cells`) (https://developers.notion.com/reference/create-view); Airtable stores hidden/reordered fields, filters, sorts, groups, row height, widths; Linear separates Filters from Display options; GitHub marks unsaved with a dot; Attio's menu is Save for everyone / Save as new view / Discard (agw r7). nuqs: `clearOnDefault` defaults true, so a URL that omits a default changes meaning when the default changes; updates are throttled ~50 ms (120 ms Safari); `processUrlSearchParams` can sort keys for stable URLs (https://nuqs.dev/docs/options). TanStack Router: `validateSearch` with Zod; a strict schema without `.catch()`/`.default()` breaks the whole route; URLs cap near 2000 characters (https://tanstack.com/router/latest/docs/how-to/validate-search-params).

Design (judgement):

```
TableState  = { v: 1, q, filters: FilterModel[], sort: {id,desc}[], page, pageSize,
                visibility, order, pinning, density, group? }        // zod, every slice .catch(default)
View        = { id, name, scope: 'personal'|'shared', state: TableState, isDefault }
URL         = ?view=<id> + only the slices that differ from the view (key-sorted, stable)
dirty       = !deepEqual(urlState, view.state)  -> dot + [Save] [Save as new] [Reset]
storage     = ViewStore port { list, create, update, remove }  adapters: local (default), consumer server
```

- Store explicit values in views (never rely on default omission: nuqs warning). The URL omits only what equals the active view.
- Personal prefs that are not "view content" (column widths, density) auto-persist per user (Airtable); filters/sort/columns of a shared view require explicit save (GitHub, Attio).
- `ViewTabs` in argo is a field-bound enum switch (`consumer-argo.md:104`); saved views are user data. Do not merge the two concepts.
- Prune unknown column ids on load; a view that references a removed column degrades, never errors.
- Every slice is `FieldHandle`-shaped (`self-controls-forms.md:40`), so lanes url / mirror / memory plug in without `key=` remounts (M2).
- No nuqs: basalt owns `router-tanstack/search-store.ts` (599 lines, 38 tests), and Dice #1268 shows the nuqs + TanStack Router seam is fragile.

## 9. Architecture proposal for basalt v3

### 9.1 Layers (headless yet enforced)

```
table/engine/     headless, Tailwind- and Mantine-free, unit tested (`bun test`, jsdom)
  features.ts     createTableHook({features: basaltFeatures, tableComponents, cellComponents, headerComponents})
                  -> useBasaltTable, createColumnHelper (the ONLY exported table constructors)
  kinds.ts        kind registry: entity status number money relative-time meter text + delta trend bar link person tags date
                  each kind = { align, numerals, width, minWidth, skeleton, filter type + operators, sortFn, card slot,
                                priority default, exportValue, ariaLabel }
  state.ts        TableState zod schema + URL grammar + FieldHandle adapter + page-reset rules
  filters.ts      FilterModel, per-kind operator sets, predicates (per-fn imports), facets contract
  server.ts       mode union, useServerTable (TanStack Query key from state), select-all-matching state
  views.ts        ViewStore port, dirty diff, apply/reset
  tiers.ts        priority -> tier data-attrs, card slot plan, container thresholds
  a11y.ts         roles, aria-rowcount/-index, roving focus, rangeExtractor helper
table/ui/         shadcn-style parts, Tailwind v4 + data-slot, each file exported (owned and bendable)
  data-table.tsx toolbar.tsx filter-chips.tsx filter-popover.tsx sort-menu.tsx column-menu.tsx view-menu.tsx
  pager.tsx load-more.tsx bulk-bar.tsx row-actions.tsx detail-sheet.tsx card-rows.tsx footer.tsx cells/*
```

`DataTable` is composed only from the exported parts. A consumer can recompose parts (bend) but must keep the engine and kinds, which carry the doctrine. Distribution (npm vs shadcn registry) is the owner decision open in `self-controls-forms.md:115`; this layout works for both because the lint keys on the engine import path and on `data-slot`.

### 9.2 API sketch

```tsx
const col = createColumnHelper<Booking>()
const columns = [
  col.entity('payee',   { header: 'Payee',  priority: 1, card: 'title' }),
  col.money('amount',   { priority: 1, currency: 'EUR', footer: 'sum' }),
  col.status('state',   { priority: 2, options: STATES, filter: 'multi' }),
  col.relativeTime('at',{ priority: 3 }),
  col.actions(rowActions),                                  // stable reference (I23)
]
<DataTable id="bookings" columns={columns} getRowId={(r) => r.id}
  mode={{ server: { rowCount, facets } }}                   // or mode="client"
  data={page.rows} query={q}                                // QueryState branch (I20)
  state={bookingsField}                                     // FieldHandle<TableState>
  views={viewStore} selection="multiple" bulkActions={bulk}
  detail={(row) => <BookingDetail row={row} />}
  phone="cards" density="compact" virtual />
```

Kinds as factories deliver, at compile time: allowed filter type and operators (openstatus `col.enum()` -> checkbox only), alignment, numerals, width, skeleton width, card slot, export. `col.custom` is the one escape and demands `sortValue`, `exportValue`, `card`, `priority`.

### 9.3 Server contract

`mode.server` implies `manualSorting + manualFiltering + manualPagination`; `rowCount` xor `cursor` (type); selection requires `getRowId`; "of N" printed only when `rowCount` known (I1). `parseTableQuery(columns, searchParams)` yields `{page, pageSize, sort, filters, q}` for any backend (Dice `getDataTableQuery` analogue); ORM mapping stays with the consumer.

### 9.4 Rendering

One scrollport owned by the table; native `<table>` semantics kept via explicit roles; column sizes as CSS variables computed once (TanStack perf pattern, used by openstatus `:283-300`); grid layout with explicit widths when `virtual`, content-sized otherwise (spike S1 decides whether to unify). Fixed `--row-h` per density. Skeleton rows by kind width (I8 kept).
