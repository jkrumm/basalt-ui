# External benchmark: data-dense professional UIs (Nov 2026), input to Basalt UI v3

Date 2026-11-09. Read-only research. Sources: 15 `agw research` runs (cited URLs inline), the installed `@base-ui/react` 1.9.0 and compiled CSS in `~/SourceRoot/software-factory`, the Kibo registry JSON fetched directly, and the owner's `inspo/` images. Tags: **[F]** fact with source, **[J]** my judgement, **[U]** unverified. Brief: `.claude/plans/v3/BRIEF.md`. Overlaps already covered elsewhere (Base UI parts: `ext-base-ui-primitives.md`; Console anatomy: `shadcn-factory-console.md` §5) are referenced, not repeated.

## 0. Verdict

1. **[F]** Nobody publishes a numeric density spec for the products we admire. Linear, Vercel Geist and Stripe give principles and changelogs, no px (Linear refresh: "Don't compete for attention you haven't earned", "Structure should be felt not seen", https://linear.app/now/behind-the-latest-design-refresh). Only design systems (Primer, Carbon, Radix Themes, Atlassian, Material 3) document numbers. So the "unified spacing" the brief wants is ours to define; there is nothing to copy.
2. **[F]** The strongest enforcement precedent is PostHog's: a repo `AGENTS.md` + `frontend/src/design.md` that tells agents to use Lemon/Quill components "rather than hand-built tables, badges or menus" and states density as rules (one primary + max two secondary toolbar buttons, one search + one filter funnel per list, 4px scale, body `text-xs`, pale tinted status, no phone layouts). This is the shape basalt's shipped rules/skills already have; v3 should copy the specificity.
3. **[F]** The shadcn ecosystem has converged on Base UI + Tailwind v4 + TanStack Table v9 (shadcn default since July 2026; Kiranism dashboard starter v2.0.0, shadcnstore v2.0.0, coss ui). It still has **no** stat-card/KPI primitive, no filter bar, no density system, no inspector: those are exactly the gaps basalt can own. Tremor (the old KPI answer) is frozen (npm 3.18.7, Jan 2025; last repo commit 2025-10-10).
4. **[J]** The owner's reference screens (`inspo/x-reference.jpg`) contain five composites no library ships as one unit: StatCard (header trio + inset + two-pair footer), a resource timeline board with grouped rows and a sticky resource grid, a section card with toolbar (view switch, range nav, search, Filters, date), a worklist with count-tabs, and a legend footer. Each below gets an API shape (section 5).
5. **[J]** Mobile: authoritative guidance (Material 3, Apple HIG, Primer) says reduce panes, move supporting content to a bottom sheet, put 3-5 destinations in a bottom bar, and size by column priority rather than shrinking. PostHog explicitly does not build phone layouts. Basalt's "nearly impossible to ship unprofessional on mobile" is therefore a differentiator, and it must be a composite contract (slots with declared mobile behaviour), not CSS luck.
6. **[J]** Biggest single guarantee we can add that none of the benchmarks have: **one controls model rendered by surface** (page bar / card header / sheet) and a **precedence law** for global vs local (PostHog states it, Grafana and Datadog imply it), enforced by types and lint instead of docs.

## 3. Findings by topic

### 3.1 Spacing systems and density scales

| System            | Mechanism                                                           | Values [F]                                                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Radix Themes      | `scaling` 90..110% multiplies space, font, line height; `--scaling` | space 1..9 = 4,8,12,16,24,32,40,48,64 px                                                                                                                                                       |
| Primer            | control sizes + padding `condensed/normal/spacious`                 | control 24/28/32/40/48; inline pad 8/12/16; stack gap coarse 12-16 vs fine 8                                                                                                                   |
| Carbon            | data-table size tokens                                              | row xs24 sm32 md40 lg48 xl64; col padding 16                                                                                                                                                   |
| Atlassian         | 8px base, tokens only, no density switch yet                        | space.025=2 ... space.1000=80; "0-8px for compact pieces (table cells, icon buttons)"                                                                                                          |
| Material 3        | density 0,-1,-2,-3 (4dp steps)                                      | target floor 48dp; "do not change density across breakpoints"                                                                                                                                  |
| Fluent 2          | 4px ramp                                                            | touch min 44 (web/iOS), 48 (Android)                                                                                                                                                           |
| Tailwind v4       | `--spacing: .25rem`; utilities `calc(var(--spacing) * N)`           | my check: compiled CSS `.p-4{padding:calc(var(--spacing) * 4)}`, `.size-8`, `.h-6`, `.gap-3` all use it; `.text-sm` uses `--text-sm` (`software-factory/apps/console/dist/assets/index-*.css`) |
| WCAG 2.2 AA 2.5.8 | min target                                                          | 24x24 CSS px, spacing exception; WCAG note recommends a density control                                                                                                                        |

- **[F]** Console today: `--vx-hit` (24px, 44px coarse) is defined but unused (0 refs); touch target is hard-coded `size-11 md:size-8` (`software-factory/apps/console/src/components/shell.tsx:88`); type split 14px Tailwind default vs 13px basalt (84 vs 27 uses; `shadcn-factory-console.md` §3). The tokens never reached the Tailwind side.
- **[J]** Recommended v3 model: `data-density="compact|default|comfortable"` on the root, set from a persisted user setting (never from viewport; M3). It rewrites **five** custom properties only: `--spacing` (so every `p-* gap-* size-* h-*` utility rescales, verified mechanically above), `--text-xs/sm/md` (spacing utilities do not move type), `--ctl-h`, `--row-h`, `--radius-ctl`. A separate `--hit-min` (0 -> 44px under `@media (pointer: coarse)`) floors interactive sizing via `min-block-size: max(var(--ctl-h), var(--hit-min))`; do not write the floor into the density variable (cycle). Visible-compact controls keep a 44px hit area through a `::after` expander.
- **[J]** Starting values (mine, derived from Primer/Carbon, not published by any system): controls 28/32/40, rows 32/40/48, card shell padding 4px with 10px header sides (Console `stat-card.tsx:111-135`). Owner works at 1800x1200 (`DESIGN.md:6-13` of Console), so default = the dense one; "comfortable" exists for touch/accessibility.
- **[U]** Rescaling `--spacing` also rescales fixed-looking boxes (icon tile `size-8`); needs a spike to see whether that is wanted (probably yes for tiles, no for hairlines/borders).
- **Owner's four questions.** Implement: density tokens + `Density` provider + settings control. Guarantee: lint bans `px`/`rem` literals and arbitrary `h-[..]`/`text-[..]` (Console shows the cost of not doing so: 7 `text-[color:var(--vx-..)]`, 5 `color-mix` arbitraries); rule `control-size-literal` already exists in 2.x (`self-controls-forms.md` line 23). Teach: skill page "pick a scale step, never a number". Leave open: the accent seed and which density is default per app.

### 3.4 Global vs local controls

| Product       | Global                                                              | Local                                                                                                                               | Precedence                                                                            |
| ------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Grafana 13    | dashboard variables + time picker (URL `var-<name>`, `skipUrlSync`) | section-level variables/filters (row/tab); panel time settings drawer (range, shift, comparison); view-mode panel sidebar (unsaved) | local override explicit in UI; "use panel time overrides sparingly"                   |
| Datadog       | global time selector, template variables, saved view of selections  | widget "Global Time" toggle vs local frame; variables referenced per query                                                          | widget opts in; at least one widget must use Global Time                              |
| PostHog       | dashboard date range, interval, property filters                    | tile "Override tile filters" (date, interval, filters, breakdown)                                                                   | tile scalar replaces; filters AND-combine; same key tile wins; warning shown on card  |
| Linear        | workspace default view via "Set as default"                         | per-user display options; URL holds main filters, not view options                                                                  | user-local until "Set as default"                                                     |
| Console (own) | theme, Mod+K, chords                                                | route search params                                                                                                                 | URL only; one filter rendered 3 ways (`flow.tsx:46-77,171-197`, `sidebar.tsx:96-120`) |

- **[J]** Law for v3: three scopes only: **app** (user setting, persisted/synced), **page** (router search params, shareable), **widget** (local state, optional override of a page value). A widget control that overrides a page value must (a) show it is overridden, (b) offer reset, (c) follow tile-wins/AND-combine, as PostHog documents. Express as a type: `useControl(key, {scope: 'app'|'page'|'widget', inherits?: PageKey})`.
- **[F]** Basalt 2.x already has "no global control type; placement is law C1: three homes" (`self-controls-forms.md:71`). v3 should add the _scope_ axis (where state lives) next to the _home_ axis (where it renders).
- Guarantee: lint `control-outside-home` (exists) plus new `override-without-indicator`; types make `scope: 'widget'` unable to write the URL. Teach: skill table "where does this state live". Leave open: variable vocabulary, defaults.

### 3.5 Filter bars

- **[F]** Three families: (a) chip row/builder over a typed query tree (ReUI: `<Filters fields query onQueryChange variant="basic|advanced">`; rule `{id,type:'rule',path[],operator,value,negated?}`; group `{combinator:'and'|'or',rules}`; `onBeforeQueryChange` veto; `loadOptions(query,{signal,cursor})`; reasons add/update/remove/duplicate/negate/reorder/combinator/clear; https://reui.io/docs/base/filters; two conflicting spec pages exist [U]); (b) URL-backed persistent + readonly + removable pills (Geist Filter Params); (c) one-funnel menu (PostHog: search + `FilterMenuTrigger`, order: group/sort, filters, display, "Clear filters" last; dot = differs from default; sort/display never light the dot).
- **[F]** Linear distinguishes filters (remove rows) from display options (change rendering) and keeps view options out of the URL (https://linear.app/docs/filters, /display-options).
- **[J]** v3 should ship **one** model: `FilterSpec[]` (field id, type text|number|range|select|multiselect|boolean|date, options or async `loadOptions`) + `FilterState` (flat AND list by default; groups/negation only behind `advanced`). Three renderers over the same state, chosen by the HOME, never a prop: pills (page bar), rows (sheet/aside), chips (active-filter strip). That is basalt 2.x `FilterSet` (`self-controls-forms.md:43`) plus the missing typed query; Console proves the cost of hand-rolling (one filter, three UIs, three copies).
- Sketch:

```ts
type FilterSpec = { id: string; label: string; icon?: IconId; kind: 'select'|'multi'|'range'|'text'|'bool'|'date';
  options?: Option[]; load?: (q: string, ctx: {signal: AbortSignal; cursor?: string}) => Promise<Page<Option>>;
  pinned?: boolean /* persistent pill */; scope?: 'page' | 'widget' }
<FilterBar specs={specs} /* state lives in the router search schema, not here */ />
```

- Guarantee: lint `hand-rolled-filter` (exists), type-check that `FilterBar` state comes from `useSearchField` (URL) or `useLocalField`; `dirty dot` computed from defaults, so it cannot be wrong. Leave open: operators beyond the default set, serialization to backend.

Virtualise columns with TanStack Virtual with `getItemKey` stable and the active item pinned through `rangeExtractor` [J, design inference]. Mobile: columns become status tabs or a single column with a status filter (Console `flow.tsx:154,255,274-290`; Board compact mode).

### 3.9 Badges and notifications

- **[F]** Taxonomy split across systems: Atlassian Lozenge (important attribute) vs Tag (descriptive) vs Badge (tally); Polaris Badge (status, tones info/success/warning/critical/auto/neutral/caution) vs Chip (user label); Carbon four statuses x three attention levels, requires 3 of 4 cues (symbol, shape, colour, text); Primer `Label` variants. Common law: status != metadata; never colour alone; tone chosen from meaning, not colour (Polaris migration note).
- **[F]** Counts: number only if actionable; dot for generic unread; Slack three tiers (bold, dot, number); Linear lets users pick count or dot per sidebar; Carbon: more than 5-6 indicators overwhelm.
- **[F]** Inbox: split needs-attention vs other (Linear Priority tab), triage verbs (snooze, done, save, unsubscribe), keyboard J/K/U/H, caps (Linear 2000), no archive.
- **[F]** Toasts: Base UI Toast 1.9.0 installed (`createToastManager`, `limit` 3, `timeout` 5000, `priority: 'low'|'high'` = polite/urgent, swipe, stacking via `--toast-index`, F6 landmark; `.../@base-ui/react/toast/useToastManager.d.ts:41`). shadcn July 2026 changelog added a Base UI Toast; Sonner 2.0.8 stays (default 4000 ms). Carbon: toast = transient, inline = persists until resolved, callout = cannot dismiss; 2 lines max.
- **[J]** Own a `Status` vocabulary as **data**: `type Tone = 'good'|'warn'|'bad'|'info'|'accent'|'neutral'` + `<Lozenge tone>` (text on 12% tint, h-5, Console `lozenge.tsx:17-28`, explicit map, never derived from the word) + `<CountBadge n tone? mode='count'|'dot'>` + `<Delta>`. Intent -> toast mapping 1:1 (`priority`, `timeout`, role), history/dedup/bell stay ours (Base UI has no history; `ext-base-ui-primitives.md:101`).
- Guarantee: `status-fill-as-text` (exists), new `badge-in-header-count>1`, type: a nav item's `badge` is `{count|dot|none, tone}`; tone from a closed union. Teach: skill "attention budget": at most one filled badge per row/card, counts only for actionable items.
