## 2. Taxonomy: where state lives (decision order, first match wins)

| #   | The state is                                                                                         | Home          | Mechanism (v3)                                           | Lint / guarantee                                                                           |
| --- | ---------------------------------------------------------------------------------------------------- | ------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 1   | a copy of server data                                                                                | server state  | TanStack Query                                           | `query-fn-unwrap`, `provider-above-router` exist; add `no-query-data-in-store` (judgement) |
| 2   | something a link should reproduce (filter, range, tab, sort, open item)                              | URL           | field store `url:true` lane over router search           | `search-literal-link`, `use-search-from-literal` exist                                     |
| 3   | a view choice that should survive a visit but is not shareable (compact, chart picker)               | this device   | field `{url:false}` lane = `createPersistedState`        | key namespace `basalt:*`; add `no-raw-localstorage`                                        |
| 4   | a preference that must follow the person across devices (theme, density, saved views, default range) | server-synced | `createSyncedState` (persisted mirror under it)          | version/migrate required, schema required                                                  |
| 5   | an unfinished edit (form, composer)                                                                  | draft         | `useFormDraft` local, or synced adapter for cross-device | `form-without-draft-or-guard` (judgement)                                                  |
| 6   | live client state read across routes (timer, auth, selection)                                        | memory        | Zustand store                                            | no `persist` middleware in app code                                                        |
| 7   | open/closed, hover, pending text of one control                                                      | component     | `useState` / control-local draft (`use-committed-field`) | `no-usestate-for-filter` is already the rule in `basalt-state.md:21`                       |

- Fact: the shipped lane model is `{url, persist, history}` with default `{true,true,'replace'}`, resolution URL over mirror over fallback (`state/fields.ts:20-38`, `router-tanstack/search-store.ts:6-14`). Rows 2, 3 and the memory lane are already covered; rows 4, 5 and the injectable storage are the gaps.
- Judgement: "global (site-wide) control" needs no new store kind. Declare the field on the root route's `validateSearch` and add root `search.middlewares: [retainSearchParams(globalKeys)]`. `retainSearchParams` exists in installed router-core (`@tanstack/router-core/src/searchMiddleware.ts:20-23`). This supersedes the `createGlobalStore` idea in `self-controls-forms.md:72`. Needs a spike: confirm child routes inherit the root schema in types and that `clear()` interacts correctly with retention.
- "Page state" = a `createSearchStore` owned by the route file (`scope: 'page'`), never a module singleton shared across routes by accident.

## 5. Per problem: choice, reasons, failure modes

### 5.1 URL state: router-native search params, nuqs rejected

- Fact (research + installed adapter): nuqs's TanStack adapter is experimental, not covered for TanStack Start, serializes through nuqs's own `renderQueryString` and navigates with a string `to` (`tanstack-router.js:31-40`), has an open object-serialization bug (nuqs #1127, arrays of objects become `[object Object]`), and typed `Link` works only for trivial parser types. Loaders see a param only if it is in `validateSearch` and `loaderDeps`.
- Fact: basalt already has what nuqs offers: typed per-field codecs (`field.range/enum/multi/string/number/boolean`), lanes (`history:'push'|'replace'`), `clear()` unsets rather than writing the default (`fields.ts:318`), hydration handling (`search-store.ts:105-120`), debounce inside `SearchFilter`. nuqs would become a second owner per key. Research names "two validators can disagree" as a failure mode.
- Judgement: keep one owner, the field store, whose `validateSearch` is a Standard Schema-shaped codec that never throws (clamp/allowlist) so a hand-edited URL cannot blank the route. Consumers writing raw `validateSearch` use Zod 4 with `.catch()`/`.default()`.
- IMPLEMENT: field stores, root `retainSearchParams` for global keys (spike), `loaderDeps` helper from a store's keys (`store.loaderDeps`). GUARANTEE: existing `search-literal-link`, `use-search-from-literal`; add `validate-search-must-catch` (a `validateSearch` schema without `.catch/.default/fallback`). TEACH: `basalt-state` skill section "which lane". LEAVE OPEN: param names, `urlKeys`, history mode per field.
- Failure modes: param drives a loader but is not in `loaderDeps` (stale data, no refetch); whole `search` returned from `loaderDeps` (reload on every param); two stores sharing a param name on overlapping routes read as one owner (known honest limit, `self-controls-forms.md` section 3 URL binding).

### 5.2 Persisted device state and the storage seam

- Choice: keep `createPersistedState`; add `storage?: StorageLike` (get/set/remove/subscribe) to its options and the field lanes. Default `localStorage`. This is the seam shutterflow lacked; it removes the `Storage.prototype` patch and the `mantine-*` key naming hack (`consumer-shutterflow.md:55`).
- Judgement: keep key prefix `basalt:*` (argo and rb persisted values depend on it, `consumer-argo.md:229`); ship a one-shot key migration only for `mantine-*` keys.
- GUARANTEE: `no-raw-localstorage` outside the adapter (argo has 23 mentions, `consumer-argo.md:106`); the existing `localstorage-theme` guard kind stays. TEACH: skill recipe "new preference" in 8 lines. OPEN: which storage (IndexedDB/Tauri store).
- Failure modes: quota or private mode (handled, `persisted.ts:132-139`); schema bump without `migrate` discards user data silently (test: every persisted key has a version and a schema); SSR mismatch for first-paint prefs, solved by the boot script already in `vite-boot.ts:42` (theme) and, for SSR consumers, a cookie mirror (judgement, only for theme/density/sidebar).

### 5.3 Settings synced to the server with local-first feel: `createSyncedState`

Choice: own primitive, not TanStack DB, not Zustand persist.

Shape (judgement):

```
createSyncedState({ key, version, schema, initial,
  transport: { load(): Promise<{value, rev}>, save(patch, baseRev): Promise<{value, rev}> },
  storage?, debounceMs = 600 })
-> use(): [value, set(patch), { status: 'saved'|'saving'|'error'|'offline', rev }]
```

Behaviour: read mirror synchronously (instant paint, no spinner); Query loads the server document in the background and reconciles per field; `set` updates the mirror and an in-memory pending patch immediately (this is the optimistic apply); one debounced writer sends `{patch, baseRev}`; writes run serially (Query mutation `scope.id = key`, same effect as argo's promise chain `draft-writer.ts:25-30`); response `{value, rev}` is written to the cache with `setQueryData` (not `invalidate`, which refetches and can race the next save).

Why these details (research, MDN and TanStack docs cited in section 9):

- Version, not client clock: whole-object LWW with client timestamps loses fields when two tabs or devices edit different settings. Server merges per top-level key and returns `rev`; a 409/412 means refetch, re-apply the still-pending patch on top, retry once. Because the client sends a patch (only fields the user touched), the rebase is trivial. argo's per-whole-key LWW (`consumer-argo.md:110`) is the special case for drafts; epos's per-field `changedAt` guard (`settings.ts:95-96`) is the client-side half of the same idea.
- Flush on `visibilitychange` to `hidden` (MDN: `pagehide`/`unload` unreliable, bfcache-incompatible) with `fetch({keepalive:true})` (64 KiB cap) after writing the pending patch to a localStorage outbox; clear the outbox on acknowledgement; replay on next start. Fact: argo flushes on both events but neither file mentions `keepalive` (`workout-draft.ts:200-216`, `draft-writer.ts`), so a hide-flush there can be cancelled by the browser.
- Do not persist Query mutations (`persistQueryClient` resume needs `setMutationDefaults` with a `mutationFn` or fails "No mutationFn found"); a typed outbox is simpler.
- Settle window (adopt a remote change only when nothing is focused or pending): carry argo's rule `isSettled()` (`workout-draft.ts:72`) as the default for drafts; for settings the reconcile is per field and silent unless the field is being edited.

IMPLEMENT: the primitive, a `useSettingsSync` status hook feeding a quiet "Saved / Saving / Offline" indicator, an in-memory test transport. GUARANTEE: schema + version mandatory (types); `no-raw-localstorage`; a contract test every transport must pass (serial order, 409 rebase, outbox replay, hide flush); lint `synced-state-needs-owner-key` (key includes user id so account switch cannot leak prefs; epos keys its local cache by owner, `shadcn-epos-teamchat.md:42`). TEACH: `basalt-state` skill "server-synced preference" recipe plus the server contract (`GET /settings`, `PATCH /settings {patch, baseRev}` returns `{value, rev}`). LEAVE OPEN: transport, endpoint, auth, what counts as synced, conflict UI.
Failure modes: lost update (rev solves); stale outbox replayed after a long offline gap (409 path); account switch leaks prefs (owner key); keepalive body over 64 KiB (size check, fall back to outbox); two tabs both PUT the same change (see 5.6); Tauri origin changes per launch wipe localStorage (shutterflow: server is truth, mirror is warm cache, so the first paint after a wipe is defaults then reconcile: show a skeleton only for theme-critical keys and carry those through the boot script).

### 5.4 Forms and validation: TanStack Form v1

- Fact: `@tanstack/react-form` 1.33.5 is latest; `2.0.0-alpha.3` is the `alpha` tag, announced 2026-08-06, React-only, no built-in persistence, `withForm` removed, `revalidateLogic` replaced by per-trigger `when`, `useStore` to `useSelector`, `form.store` to `form.atom` (research). shadcn's TanStack Form guide is written against v1 (`field.state.meta`, `FieldError errors`).
- Choice: v1, exact pin. Schema on `validators: { onSubmit: schema }` plus `validationLogic: revalidateLogic({mode:'submit', modeAfterSubmission:'change'})` (those are the library defaults, `ValidationLogic.ts:74-78`): errors appear after the first submit, then live. Standard Schema means Zod 4.6.7, Valibot 1.5.0 and ArkType 2.2.9 all work; document Zod 4 only (argo already validates with zod, `consumer-argo.md:111`; epos uses zod only for AI specs, `shadcn-epos-teamchat.md:50`).
- Judgement: ship `useBasaltForm` as a thin `createFormHook` wrapper with pre-bound field components (`AppField` + `FieldRow` on shadcn `Field`) to kill `form.Field` verbosity (TanStack's own guide calls it verbose). Rule from the docs to carry: `withForm` render must be a named function.
- Do not wrap an async schema in sync-only contexts: URL fields and `createPersistedState` treat an async schema as invalid (`persisted.ts` header), TanStack's router throws on it.
- Server errors: `onSubmitAsync` returning `{form, fields}` in v1; known pitfall: a field's own validator can overwrite a form-level field error. Wrap once in `submitWithErrors(form, fn)` that maps the API `fieldErrors` envelope and focuses the first error (reinstates `useFormSubmit`, `self-controls-forms.md:60`).
- IMPLEMENT: `useBasaltForm`, `FormField`, submit lifecycle. GUARANTEE: `no-raw-useform` (replaces `forms-field-key`), accessible-name test per row, version pin test. TEACH: skill section "schema first, then form". OPEN: schema library, field widgets.
- Failure modes: `defaultValues` mutated by a draft restore (dirty never fires); schema transforms are not returned by validation (use the submit handler); `extendForm` chains above 3 to 5 slow TS; v2 migration cost is high (mitigation: all access through basalt wrappers).

### 5.5 Drafts and the unsaved-changes guard

- Local draft (ship): `useFormDraft(form, { key, version, schema, scope })`. Store `basalt:form:<key>` (envelope reuse), autosave 500 ms trailing via `form.store` subscription, restore once on mount by `form.reset(draft, { keepDefaultValues: true })`. Fact from installed source: with `keepDefaultValues:true`, `defaultValues` stay as the server baseline, so `isDirty`/`isDefaultValue` still tell the truth (`FormApi.ts:1810-1824`); without it the draft becomes the baseline and a dirty guard never fires. Clear on successful submit and on logout; scope key by user id.
- Exclusions by type, not by hope: draft schema omits passwords, tokens and `File`; `useFormDraft` requires a `pick` list or a schema (no "persist everything").
- Cross-device draft (document, do not ship transport): the synced engine of 5.3 with a per-key adapter (`PUT/GET/DELETE /drafts/:key`), argo's rules: per-key debounce 900 ms, serial chain, flush on hide, adopt remote only when settled, server stamps `updated_at`, TTL on the server.
- Guard (explicit-save forms only, e.g. settings): `useBlocker({ shouldBlockFn: () => form.state.isDirty, enableBeforeUnload: () => form.state.isDirty })`. Fact: `useBlocker` has `shouldBlockFn` and `enableBeforeUnload?: boolean | (() => boolean)` (`react-router/src/useBlocker.tsx:74-75`); the maintainers closed the long-running issue #3761 on 2026-07-11 as expected behaviour with exactly this recipe. The browser shows its generic text on unload, a custom message is impossible. Judgement: a draft-enabled form does NOT prompt in-app (nothing is lost); prompt only if a write is pending. shutterflow's `unsaved-guard.ts` registry (validate-first save-all) carries over as `FormGuardProvider`.
- GUARANTEE: lint `form-needs-draft-or-guard` for forms with more than 3 fields or any `textarea`; test: reload restores, submit clears, logout clears, version bump discards. TEACH: skill table "draft vs guard vs neither". OPEN: which forms are draft-worthy, TTL.
- Failure modes: restoring a draft over fresher server data (compare `rev`/`updatedAt`, offer "restore draft?" instead of silently applying when the server changed); draft key collision between users on one browser; draft survives forever (add `savedAt`, drop after 30 days, judgement).

### 5.6 Cross-tab sync

- Choice: the `storage` event on the persisted mirror (shipped, one listener per key, `persisted.ts:195-197`, same-tab `notify` at `:248` because `storage` never fires in the writing tab). For synced state, a received storage event updates the in-memory value and MUST NOT schedule a write (origin flag), otherwise tab B re-PUTs tab A's change. One Web Lock (`basalt-outbox:<key>`) elects the tab that replays an outbox on start.
- Rejected: `broadcastQueryClient` (experimental; ships whole query state; structured-clone failures), a custom BroadcastChannel for settings (the storage event already carries it; one more channel = one more echo path), Query cache sharing across tabs (focus refetch and polling cover it).
- Judgement: "log out everywhere" rides the storage event on the auth key (argo's token is a Zustand `persist` key `argo-auth`, `consumer-argo.md:92`; keep, since an auth token is the one persistence case outside the basalt envelope; document it).
- Failure modes: storage event not delivered inside Tauri webviews with separate origins (shutterflow changes port per launch; same-launch windows share origin, untested here); echo loops; Safari private mode (writes throw, handled by `unpersisted`).

### 5.7 Optimistic updates

- Choice: the cache-write recipe from the TanStack guide, packaged once: `optimistic({ queryKey, apply })` returning `{ onMutate, onError, onSettled }` for `useMutation`. Steps: `cancelQueries`, snapshot, `setQueryData`, rollback on error, settle by invalidate only when `queryClient.isMutating({mutationKey})` is 0 (TkDodo's window-of-inconsistency fix), mutation `scope.id` per entity so saves run serially (installed `mutation.ts:60`).
- Why not variables-only: only one component shows the value; basalt's lists, badges and sparklines read the same entity in several places. Variables stay allowed for a single pending cell.
- Fact: argo `useCurate` and rb's list patch are two hand-written copies (`consumer-argo.md:108`, `consumer-rb.md:45`); rb's query keys are hand-written strings (`consumer-rb.md:45`), so the helper pairs with a key factory recipe (`queryOptions` factories, argo has 101).
- GUARANTEE: lint `mutation-without-settle` (a `useMutation` that calls `setQueryData` without rollback) and `query-key-literal` (judgement). TEACH: one recipe, rollback test pattern. OPEN: the patch function, error toast text.
- Failure modes: refetch between two overlapping mutations reverts the UI (isMutating guard); callbacks passed to `mutate()` fire only for the last call (put handlers on `useMutation`); out-of-order completion without a scope.

### 5.8 TanStack DB and local-first: not in v3.0

- Fact: DB is `1.0.0-rc.1.4` (installed rc.1.1 resolved first, so versions already move), the migration from 0.9.2 removed `$synced`, `transaction.isPersisted.promise`, `useLiveQuery` dependency arrays and automatic refetch in Query Collection handlers; 139 open issues at snapshot, open bugs in on-demand windows (#2155, #2326); about 102 KB gz typical app (TanStack's own report); production users cited: Prisma Studio, Unkey.
- What it would give: client-side joins/filters over loaded data, optimistic overlays with rollback, paced (debounced) mutations, a localStorage collection with cross-tab sync (`local-storage.ts:33-52`). All four are things basalt already solves at smaller grain for its consumers.
- Evidence of need: argo has zero virtualization, zero infinite queries, server-paged tables, polling only (`consumer-argo.md:118`); no consumer needs offline writes (argo's gym-basement mirror is read-mostly; epos is online).
- Revisit trigger (judgement): final 1.0 AND adapter-only bundle measured under 40 KB gz (not measured here) AND two consumers asking for client joins/live queries. Until then the Table integration owns client filtering.
- Sync engines: if offline writes appear, PowerSync (Web SDK GA, own React hooks, not its Alpha DB adapter). Zero needs Postgres + zero-cache and has no offline writes; Electric Cloud is winding down; LiveStore is beta. None is a framework dependency; basalt stays transport-agnostic.

### 5.9 Notifications

- Choice: Base UI `Toast` through the shadcn `toast` component (`toast.add({title, description, type, actionProps})`), `createToastManager` in its own tiny module so imperative `emit()` works from non-React code without loading the viewport (epos pattern, `toast-manager.ts:1-6`; `limit` of 1-3). Sonner rejected: shadcn retired its Base sonner page (2026-07-23 changelog) and both libraries would each add a live region.
- Carry the concepts basalt already has: typed `defineNotifications` registry (argo: 9 kinds, 19-25 call sites, `consumer-argo.md:115`), persisted history ring buffer of 50 with serializable action refs so an actionable notification survives reload (`commands/notifications/store.ts:4,92`), `NotificationBell` + `center.tsx` with Inbox vs Everything-else views. These sit ABOVE the toast library; only `notify.tsx` (Mantine wrapper, `:2`) is rewritten.
- Judgement, three surfaces kept apart: toast = what just happened (transient, `role=status`, politeness `polite`); inbox = what still needs the user (persisted, bell with `aria-expanded`, count in the accessible name, display cap "9+", clear on open); inline result next to the control for important outcomes (WCAG 2.2.1 allows auto-dismiss only if the information exists elsewhere). Errors that block a task use priority high (`role=alert`); routine success never does.
- Undo: Base UI `actionProps.onClick` only closes the toast; it reverts nothing. Pattern: apply optimistically, hold the server commit behind a 5-8 s timer, Undo sets a flag and restores, close-without-undo commits (`onClose`). Ship as `emit('x', {undo})` so the commit-after-window logic is one implementation. Prefer undo over confirm dialogs for reversible actions (NN/g).
- GUARANTEE: `no-direct-toast-import` (only `emit`), registry key type-checked via `BasaltRegister`, test that no two toasters mount. TEACH: skill "which of toast / inbox / inline". OPEN: kinds, copy, server-pushed inbox items (SSE source).
- Failure modes: toast flood (limit + dedupe by id, already in history store), live-region chatter when an open inbox also toasts (do not toast what the open panel shows), focus theft (never move focus to a toast).

### 5.10 Global client state: Zustand 5.1 as the sanctioned store

- Choice: Zustand for in-memory, cross-route client state (argo timer survives route changes and renders in the app bar, `consumer-argo.md:93`). It is a documented optional peer, imported by consumer code, never by basalt core (basalt core keeps zero runtime deps; `externalField` already accepts any `{get,set,subscribe}`, `fields.ts:1257`).
- Why not the others: TanStack Store 0.11 is alpha-labelled local-state infrastructure with no persistence/hydration API (the site says Router/Query/DB own the rest); Jotai 3.0 is two months old with a mount-timing change that can miss a write between first render and subscribe, which is precisely the hydration and cross-tab window; Valtio's persistence is hand-written; epos's own 26-line store proves the floor but gives selectors and devtools nothing (`createStore.ts:9-26`, 44 sites).
- Rules (GUARANTEE): no `zustand/persist` in app code (persisted state goes through `createPersistedState` so keys, versions and cross-tab stay uniform; auth-token key is the documented exception); no server data in a store (taxonomy row 1); selectors returning objects or arrays must use `useShallow` (v5 infinite-loop failure; `no-unstable-selector` is hard to lint, so teach plus test); controls bind through `externalField`, never `useState` mirrors. TEACH: skill states the 7-row taxonomy. OPEN: store shapes, slices.
- Failure modes: v5 selector loops; a store subscribing to another store (epos `settings` follows `authStore`, `settings.ts:195-205`) creating hidden init order; SSR: a module-level store is shared between requests on the server (create per request or keep client-only).

### 5.11 Debounce primitive

- Fact: `SearchFilter` uses `@mantine/hooks useDebouncedCallback` (`search-filter.tsx:19`); v2 rejected Pacer because Mantine's hook was enough (`V2-SPEC.md:357`), which is gone in v3.
- Choice: `debounce(fn, ms) -> { call, flush, cancel }` plus `useDebounced` hook, ~25 lines, in `basalt-ui/state`. Needed by `use-committed-field` (IME-safe Enter, blur, unmount flush), `useFormDraft` and the synced writer. `flush` is the load-bearing method (hide, unmount, Enter). Pacer is 0.23 and does not add anything those three need.
