## 0. Headline and what changed since v2 was designed

1. Everything the brief needs from TanStack is stable except Hotkeys, Pacer, DB, Devtools and Store. Router, Query, Table v9, Virtual, Form v1, Start 1.0, Charts 1.x and AI core are all at stable majors; the unstable set is exactly the "nice to have" set (section 1).
2. **Query's imperative API is being replaced under basalt and argo.** `ensureQueryData`, `prefetchQuery`, `fetchQuery` are `@deprecated`, "will be removed in the next major version", replaced by one `queryClient.query()` (FACT `/tmp/pk/qc/package/build/modern/hydration-9_kOYxJM.d.ts:1715,1914,1922,1931`; added 5.102.0, CLAIM). argo has 30 `ensureQueryData` and 8 `prefetchQuery` call sites, and the shipped skill teaches neither the new API nor a lint (section 3).
3. **Start 1.0 is stable (13 Oct 2026) and requires Vite 8** (FACT registry peer `vite >=8.0.0`, engines `node >=22.12.0` for 1.169.5). SSR is therefore a real, supported host, not a risk. But basalt's SSR support is accidental: no `setupRouterSsrQueryIntegration`, a provider that also mounts `QueryClientProvider`, and a `validateSearch` that reads localStorage behind a private router global that the router itself deletes (section 5).
4. **TanStack now ships first-party agent skills inside npm packages** (`@tanstack/intent`, `skills/` dir): router-core 10, react-router 3 (incl. `router-query` composition and `migrate-from-react-router`), react-table 3, react-start 3, charts 12, ai 12, react-db 1, hotkeys 2; none for Query, Virtual, Form, Pacer, Store (FACT, unpacked tarballs). basalt's skills must delegate to these and teach only the delta, instead of re-teaching Router/Table/Charts (section 6).
5. basalt's TanStack peers are exact pins that already diverge from consumers (section 2).

## 3. Optimal unified wiring for a data-dense SPA that may later SSR (JUDGEMENT, grounded in the sources above)

One data flow, one owner per kind of state:

| State kind                                   | Owner                                                    | Bound to                                                                                                 | Notes                                                                                                          |
| -------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Server state                                 | Query cache                                              | `queryOptions` factories                                                                                 | the only cache; Router SWR cache is switched off for it (`defaultPreloadStaleTime: 0`, already set)            |
| Global controls (range, scope, environment)  | Router search on the ROOT route                          | `validateSearch` on root, `search.middlewares: [retainSearchParams([...]), stripSearchParams(defaults)]` | root `validateSearch` is inherited by every child; without it children cannot share params (CLAIM router docs) |
| Local controls (table sort/filter/page, tab) | Router search per route                                  | basalt typed fields (lanes law kept)                                                                     | table state binds through v9 `atoms`/`state` + `on*Change` (CLAIM table docs)                                  |
| Device preferences                           | localStorage (cookie when SSR must render them)          | `createLocalStore`                                                                                       |                                                                                                                |
| Server-synced settings                       | Query + optimistic mutation                              | applied to the store once                                                                                | weatherorb `SavedSettingsApplier` is the existing pattern (`evidence/consumer-weatherorb.md:106`)              |
| Form drafts                                  | TanStack Form + persisted draft keyed by route+record id | `useBlocker` (experimental) for leave-guard                                                              | Form has no built-in persistence (CLAIM)                                                                       |
| Ephemeral UI                                 | `useState`                                               |                                                                                                          |                                                                                                                |

Request lifecycle (what we implement as the default, consumers write plain TanStack):

1. `validateSearch`: Standard Schema directly (Zod 4, Valibot, ArkType, no adapter), `.catch()`/fallback not `.default()`, so a bad URL degrades instead of showing the error screen; must be deterministic and side-effect free (CLAIM docs).
2. `loaderDeps`: return only keys the loader reads (docs: cache key, deep-equal).
3. `loader`: critical data `await context.queryClient.query({ ...opts, staleTime: 'static' })`; secondary `void context.queryClient.query(opts).catch(noop)`. Return nothing; data is read in components. This is verbatim the Router team's recommended pattern (`/tmp/pk/rr/package/skills/compositions/router-query/SKILL.md`, "Core Pattern", "Streaming Pattern"). It replaces argo's `ensureQueryData`/`prefetchQuery` 1:1 (CLAIM migration table: `ensureQueryData -> query({staleTime:'static'})`, `prefetchQuery -> query().catch(noop)`).
4. Component: `useSuspenseQuery(opts)` for what the loader awaited; `useQuery`/section `Suspense` + `QueryState` for secondary data, so a failing card never takes the route down (argo `astro-window.tsx:139-147`).
5. Pending and error: route `pendingComponent` only after `pendingMs`; basalt must set `defaultPendingMs` and `defaultPendingMinMs` explicitly (docs defaults 1000/500 ms; with cached Query data loaders usually resolve instantly, so a 1 s blank wait is the wrong dashboard default). Values need a trial, not a guess: propose 300/300 and measure. Error: `errorComponent` + `useQueryErrorResetBoundary().reset()` + retry via `router.invalidate()` (skill "Error Handling").
6. Prefetch: `defaultPreload: 'intent'` (set). Touch preloads immediately, hover after 50 ms; `viewport` fires on scroll so use it only on a few links (CLAIM PR #8044, recommendation mine).
7. Code splitting: `autoCodeSplitting: true` (defaults split component, errorComponent, notFoundComponent into chunks); never export route properties; read route data in split components with `getRouteApi` (CLAIM docs).
8. Mutations: invalidate the right owner: `queryClient.invalidateQueries` for Query data, `router.invalidate()` for loader/context data (CLAIM Start guide). OPEN VERIFICATION: the loader calls `query({ staleTime: 'static' })` while components observe with the 30 s default; docs say static queries with data ignore invalidation (5.105.3 note). It should apply only to that call, not to the observer, but write a test in the v3 data wave before the skill asserts it.
9. Structural sharing: set `defaultStructuralSharing: true` (docs: default false, may change); needed because `useSearch({ select })` returning objects re-renders every call.
10. Live data (poll/SSE/WS): keep it a Query concern: `refetchInterval`, invalidate-on-event (`software-factory/apps/console/src/lib/queries.ts:51-56`, SSE client per `evidence/shadcn-factory-console.md:154`); `experimental_streamedQuery` exists but is still `experimental_` (FACT query-core index export, CLAIM docs): do not build on it.
11. Snapshot persistence: offer `persist` as an opt-in seam over `PersistQueryClientProvider` with the console's three hard-won rules (buster per build, `gcTime >= maxAge`, exclude large roots, restore = first paint then refetch).

## 5. SSR, hydration and streaming: what must hold (the brief says SSR "must be allowed")

CLAIM (Start docs via agw): `beforeLoad` then `loader` then component then streamed HTML; per-route `ssr: true | false | 'data-only' | fn`; `defaultSsr` in `createStart`; a child may only be more restrictive than its parent; the first `ssr: false` route renders its `pendingComponent` on the server; root `shellComponent` always server-renders. SPA mode prerenders only the root into `_shell.html` and bakes root loader data in at build time, so a request cookie cannot shape the shell. Streaming: `useSuspenseQuery` runs on the server and streams; plain `useQuery` does not run on the server; `await queryClient.query()` in a loader blocks the shell; un-awaited `void ...query().catch(noop)` streams. Compression is off by default because a compressed streamed page reaches the browser only when the stream ends.

FACT (ssr-query): server side dehydrates initial queries and streams ones that resolve during render; client hydrates, then incrementally hydrates streamed ones; redirects thrown from queries are handled; option `wrapQueryClient` defaults to wrapping (`/tmp/pk/ssrq/package/src/index.tsx:12-28`, `/tmp/pk/core/package/src/index.ts:25-72`).

Recommended posture (JUDGEMENT, medium confidence; the Start docs give no dashboard recipe):

| Route class                         | SSR setting                                                             | Reason                                                                                                                                     |
| ----------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Public landing, docs, static pages  | `ssr: true`, prerender                                                  | zero JS, weatherorb already does it                                                                                                        |
| Authenticated data-dense dashboards | SPA mode or `ssr: false`; `'data-only'` when a first-byte win is wanted | personalised HTML needs `Cache-Control: no-store` and per-request client (Start guide, CLAIM); charts cannot size themselves on the server |
| Map/canvas/measured widgets         | `ssr: false` or `ClientOnly`                                            | weatherorb `/map`                                                                                                                          |

Hazards found in basalt that SSR must not inherit (FACT unless marked):

1. `validateSearch` reads localStorage on the client (`search-store.ts:331-337`) and is protected by `'$_TSR' in window` (`:121`). The router deletes `$_TSR` once hydration AND stream end are both done (`node_modules/.bun/@tanstack+router-core@1.171.39/node_modules/@tanstack/router-core/dist/esm/ssr/tsrScript.js:2`). The guard therefore rests on a private global whose lifetime the router controls, and the docs say `validateSearch` must be deterministic. JUDGEMENT: make it pure (URL then fallback); apply the remembered value with one client-only `beforeLoad` `throw redirect({ search, replace: true })` (documented pattern, CLAIM) or, when SSR must render it, from a cookie read in a server function (`getCookie` from `@tanstack/react-start/server`, CLAIM). Cost: one replace navigation on a bare URL; gain: URL is always the truth and the `isDehydrating` machinery (about 40 lines plus a test hook) disappears.
2. Provider double-mount: ssr-query wraps `QueryClientProvider` by default; basalt does too (`index.tsx:554`). Choose router `Wrap` as the single mount (`createBasaltRouter` sets it), then `BasaltProvider` stops knowing Query. Not verified in this repo; the pattern is what ssr-query itself does.
3. `basaltRouterOptions` default components were Mantine, so prerender crashed (`evidence/consumer-weatherorb.md:138`); `ssr.noExternal: ['basalt-ui']` exists only for CSS Modules (`evidence/consumer-weatherorb.md:83`). Tailwind v4 removes both; keep "provider-less landing" as a tested mode.
4. Measured table fold is SSR-unstable (`evidence/self-table-data.md:66`); container-query tiers are the SSR-stable route (the same file proposes them).
5. `createPersistedState` is already SSR-safe by construction (`getServerSnapshot` returns `initial`, `src/state/persisted.ts:242,257-260`): keep.
6. Charts: server output needs `initialWidth` plus `height` or `aspectRatio`; otherwise 320 px fallback and a layout jump on hydration (CLAIM charts SSR guide). Card sparklines must carry a fixed aspect ratio. `renderChartSvg` needs no browser.
