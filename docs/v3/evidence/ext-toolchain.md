# ext-toolchain: toolchain and dependency baseline for v3 (as of 2026-11-09)

Scope: Bun monorepo, one published React library, Mantine v9 -> shadcn/Base UI/Tailwind v4. Sources: `npm view` (registry, read 2026-11-09), `agw research` runs (URLs inline), installed source, and four scratch spikes in `/tmp` (no repo touched). Tags: [F] fact with citation, [S] spike I ran, [J] my judgement, [U] unverified.

## 0. Headline

1. **TypeScript 7.0 (native `tsc`) is GA since 2026-07-08; `typescript` latest = 7.0.2** [F npm]. `tsgo`/`@typescript/native-preview` is a dead-end preview channel (last build 2026-07-07). Our `typescript ^6.0.3` is the last JS-based line. One owner app already runs 7.0.2 (`~/IuRoot/epos-ai-teamchat-athena/ui/package.json`, vite 8.3.4, vitest 5.0.5). Programmatic API is absent in 7.0 (arrives in 7.1, beta since 2026-10-20), so JS-API tools (typescript-eslint, rollup-plugin-dts, TypeDoc, vite-plugin-dts) need a side-by-side `typescript` 6 alias.
2. **tsup is officially unmaintained** (9.0.0 on 2026-10-14 is a maintenance release; README recommends tsdown). **tsdown 0.23.7** (rolldown 1.3, 2026-11-06) is the successor and I proved the exact shape we need works: `unbundle: true` + per-file CSS preserved + oxc `.d.ts` (S1). It replaces four of our five build steps (section 4).
3. **Tailwind 4.3.5** (2026-11-06) and `@tailwindcss/vite` 4.3.5 support Vite 8. The library-shipping pattern that works without consumer boilerplate: ship a CSS file whose own first line is `@source "."` (S2). `node_modules` is NOT scanned otherwise (S2 negative case).
4. **Version drift inside our own pins is large** (section 1): `@tanstack/charts` 1.1.0 -> 1.5.0 (exact pin), `@tanstack/react-hotkeys` 0.13.0 -> 0.22.3, `vite-plugin-pwa` ^1.3.0 -> 2.0.0, `react-table` 9.2.8 -> 9.3.1, oxlint 1.90 installed -> 1.93, oxfmt 0.72 -> 0.78. v3 should start from latest, not carry pins.
5. **Release chain:** `semantic-release-monorepo` is stale (npm: last publish ~3 years ago) and not needed for one package; `bun publish` still cannot do provenance or OIDC. Keep `npm publish` under trusted publishing (already so). Doctrine change needed anyway for 3.0 (`version_gate`), see section 9.
6. **Icons:** shadcn default is Lucide (lucide-react 1.70.0, daily releases); both owner shadcn apps chose Phosphor (`@phosphor-icons/react` 2.1.10, **last npm release 2025-05-22**, last commit 2026-01-06); argo/linewatch use Tabler. Recommend a decision, not a default (section 8).
7. **Dates:** drop `dayjs` with `@mantine/dates` (only referenced as that surface's peer: `src/surfaces.ts:545`). Use `Intl.DateTimeFormat` for display, `date-fns` 4.4.0 for logic. Base UI 1.9.0 already declares optional peers `date-fns ^4` + `@date-fns/tz` [F npm peerDependenciesMeta], and react-day-picker 10 depends on date-fns, so date-fns is the zero-extra-cost choice.

## 2. TypeScript: tsc 7, tsgo, declarations

- [F] 7.0 CLI is `tsc` from the `typescript` package; `tsgo` is the old preview name. `tsc --declaration --emitDeclarationOnly` works on 7.0.2, **but** microsoft/TypeScript#64589 shows non-deterministic union member order in `.d.ts` on 7.0.2; fixed by PR 64621, milestone 7.1 Beta; no 7.0.x backport found [researched, unverified for later patches]. 6.0 added `--stableTypeOrdering` to diff 6 vs 7 output.
- [F] 7.0 hard-errors what 6.0 deprecated: `moduleResolution node/node10/classic`, `baseUrl`, `target es5`, `esModuleInterop:false`, `module amd/umd/system/none`. 6.0 defaults: `strict:true`, `types:[]`, `rootDir` = tsconfig dir, `module esnext`, `noUncheckedSideEffectImports:true`. [https://www.typescriptlang.org/docs/handbook/release-notes/typescript-6-0.html]. Our tsconfigs already use `moduleResolution: bundler` and explicit `types` (`packages/basalt-ui/tsconfig.json:5`, `tsconfig.base.json` root).
- [F] 7.1: RC planned 2026-11-10, stable 2026-11-24 per the 2026-07-31 plan, slipped (iteration plan #63703); API entry points `typescript/sync|async|fs|ast`.
- [J] v3 typecheck gate = `tsc` 7.0.x (`typecheck`, tests). Declaration emit for the published artifact: either tsdown's oxc generator (needs `isolatedDeclarations`, section 4) or TS 6.0.3 `tsc` until a 7.x release fixes union ordering and the packaging pipeline is verified. Do not use `@typescript/native-preview`: tsdown 0.23.5 notes drop it; tsgo backend in tsdown needs 7.1+ and is experimental.
- [F] `oxlint-tsgolint` (type-aware linting) requires TS 7.0+, covers 59/61 typescript-eslint type-aware rules, memory-heavy on large repos; `--type-check` (replace `tsc --noEmit`) is experimental. [https://oxc.rs/docs/guide/usage/linter/type-aware.html, via research]
- Ours today: `tsc` is the declaration emitter (`package.json:123` build script, `tsconfig.build.json`), CSS-module `.d.ts` copied by hand (`scripts/copy-assets.mjs:3-12`).

## 3. Tailwind 4.3 and shipping CSS from a package

Facts [F, https://tailwindcss.com/docs/detecting-classes-in-source-files, blog v4.1/v4.3, releases]:

- Auto detection skips `.gitignore`d files, `node_modules`, binaries, CSS, lockfiles. `@source "<path>"` is relative to the stylesheet. `@source not`, `@source inline("{hover:,}bg-red-{50,100}")`, `@import "tailwindcss" source(none|"../src")` exist (4.1+).
- 4.1: `@source not`/`inline()`, `pointer-fine|coarse`, text-shadow, mask. 4.2 (2026-02-18): 4 new palettes (mauve, olive, mist, taupe), logical-axis utilities (`pbs-*`, `mbe-*`, `inset-bs-*`; `start-*`/`end-*` deprecated), webpack loader. 4.3 (2026-05-08): `@container-size`, `scrollbar-*` (`thin|none`, thumb/track/gutter), `zoom-*`, `tab-*`, stacked/compound `@variant hover:focus {}`, `--default()` in `@utility`. 4.3.4 adds `@tailwindcss/turbopack`.
- `@tailwindcss/vite` peer `vite ^5.2 || ^6 || ^7 || ^8`; Vite 8 support landed in 4.2.2 (2026-03-18, PR #19790).
- Official docs state no library-shipping pattern. Community: tailwindlabs/tailwindcss discussion #19684 (scanning a whole package emits every component's utilities; prefixes must match on both sides).

Spikes (tailwindcss 4.3.5 + `@tailwindcss/cli`, scratch dir `/tmp/ext-tc/spike`):

- [S2a] Package in `node_modules/fakelib` with `dist/button.js` containing class strings and `dist/styles.css` = `@source "."; @theme {...}; @custom-variant libonly (&:where([data-lib]))`. Consumer CSS = `@import "tailwindcss"; @import "fakelib/styles.css";` -> output contains `.bg-sky-600`, `.px-3`, `.text-white`, `data-open` ring, and `.libonly\:underline:where([data-lib])`. **The library CSS registers its own scan root; the consumer writes zero `@source`.**
- [S2b] Same package with a CSS lacking `@source` -> 0 library utilities generated. Confirms `node_modules` is skipped.
- [S2c] `@import "tailwindcss" source(none)` plus the lib's own `@source "."` still generates the lib's classes (consumer opted out of auto-scan, lib still works).
- Precedent in our own fleet: `shadcn/tailwind.css` is an npm-shipped CSS entry (`node_modules/shadcn/package.json` exports `./tailwind.css`, `sideEffects: ["./dist/tailwind.css"]`) holding 3 `@theme` blocks, 11 `@custom-variant data-*` and ~25 `@utility` rules (`software-factory/apps/console/node_modules/shadcn/dist/tailwind.css:1-631`), imported in one line at `src/styles/index.css:3`. The Console also depends on `tw-animate-css` (`package.json`).
- [J] Pattern for v3 `basalt-ui/styles.css`-family (names illustrative): `theme.css` (tokens: `@theme`, light/dark vars), `utilities.css` (`@utility`, `@custom-variant`), `source.css` (`@source "../dist"`), and one `index.css` that imports all three. The consumer app's CSS is `@import "tailwindcss"; @import "basalt-ui/index.css";`. Do NOT put `@import "tailwindcss"` inside the library CSS [inference from docs: would ship the framework twice; not spike-tested].
- [J] **Whole-package scan cost:** the lib's `@source` emits every shipped component's utilities even if the app imports one (#19684). With ~100 components it is bounded and small; the alternative (per-subpath CSS like `components/table.css` with its own `@source`) is available because S2a shows relative self-registration works per stylesheet.
- [J] Keep the `style`/`default` conditions on CSS exports: `"./index.css": { "style": "./dist/index.css", "default": "./dist/index.css" }`. The `style` condition is a Sass/bundler convention (Sass RFC 2023); Tailwind itself defines none [U: not tested in Vite 8, webpack].
- **Shipped class strings are the contract.** Since scanning is textual, library class names must be written literally in source/dist (no `` `bg-${tone}-600` ``). That is a lint rule (section 7), and it is why `@source inline()` exists for the exception.
- **`cn()` trap** [F from epos report `shadcn-epos-teamchat.md:88`]: tailwind-merge 3.x mis-reads custom `text-*` scale tokens as colours; epos replaced it with `cn` 0.5.0 + AOT tables generated from `@theme`. v3 ships its own custom type/shadow scale, so the `cn` decision is part of the design, not an afterthought.
- **Breakpoint reset trap** [F epos: `md:` emits nothing after resetting `--breakpoint-*`, 227 arbitrary variants as workaround]. Lint candidate: forbid `[48rem]`-style arbitrary breakpoints; keep Tailwind's scale or ship named container tokens.
- **Preflight cursor** [F factory console `index.css:64-75`]: Tailwind 4 preflight resets buttons to arrow; every shadcn app repeats the fix. Library base layer should carry it once.

- [J] Alternative if CSS stays a problem: keep `bundle:false`-equivalent via tsdown but leave `css` off and keep `copy-assets` (smaller step) until `@tsdown/css` leaves experimental. Vite library mode is wrong for us (single merged CSS, no unbundle, no dts).
- [J] Keep the unbundled shape. Reasons already recorded: subpath exports resolve to real files, source shipped for go-to-definition (`package.json:36-37`, `MAINTAINING.md:136-137`), per-subpath peer optionality (peer-boundary tests).
- [J] Source in tarball (`src/` ships, `package.json:37`) is also what lets a consumer's Tailwind scan `src/**/*.tsx` as an alternative to scanning `dist`. Pick one scan root (`dist`) and document why; scanning both doubles nothing but invites drift.

## 5. React, Compiler, Vite

- [F] React 19.3.1 (2026-10-14; also patch lines 19.0/19.1/19.2 same day). 19.3: View Transitions and Fragment Refs stable, Trusted Types, `AnimateView` needs React 19.3 (Motion readme).
- [F] React Compiler 1.0 stable 2025-10-07, supports React 17+. `target: '17'|'18'|'19'` (default 19); target 19 imports `react/compiler-runtime`, 17/18 need `react-compiler-runtime` in `dependencies`. react.dev "Compiling Libraries": compiling before publish is allowed (benefit: consumers get optimised code without config); test both compiled and uncompiled; the compiler version is frozen into the published artifact. [https://react.dev/reference/react-compiler/compiling-libraries via research]
- [F] Vite 8: two routes. Documented, stable: `@rolldown/plugin-babel` + `babel-plugin-react-compiler` with `reactCompilerPreset()`. New, experimental: `@vitejs/plugin-react` >=6.1 `react({ compiler: true })` via optional peer `oxc-transform-react`; peer range lags (`>=0.152 <0.157` vs npm 0.158.0) so a fresh install can warn [F npm]. Oxc team claims >10x faster than the Babel plugin; skips `node_modules` by default.
- [J] **Library should NOT precompile at v3.0.** Peer is React `^19.3`, so `target:'19'` needs no runtime shim, but: (a) consumers with the compiler on would skip `node_modules` by default (oxc) and then still get our output, fine; (b) compiling freezes a 1.0.0 compiler into every release and an experimental oxc port is not a publishing dependency; (c) shipping uncompiled keeps the artifact valid for consumers on any compiler version. Instead: make the code compiler-clean (our lint already enables the compiler-derived rules: `.oxlintrc.json` lines `react/globals|immutability|incompatible-library|preserve-manual-memoization|refs|set-state-in-effect`) and document `babel-plugin-react-compiler` as the consumer's opt-in. Revisit when oxc route leaves experimental.
- [J] Peer policy for Vite: our `^7 || ^8` (`package.json:201`) is wider than `@vitejs/plugin-react@6` (`^8` only). v3 should declare `^8` (Rolldown) since tsdown, `@tailwindcss/vite` and plugin-react 6 are all Vite-8-centred; Vite 7 consumers are a downgrade path, not a target.

- [F] oxfmt 0.78.0 beta (2026-02-24 beta post), passes 100% of Prettier JS/TS conformance; **default printWidth 100** (Prettier 80); `sortImports` (perfectionist-based; no `tsconfigPath`), `sortTailwindcss` (replaces prettier-plugin-tailwindcss; `functions: [clsx, cn]`, no regex attributes), `sortPackageJson` on by default; all disabled except package.json sort. - Ours: shipped plugin `configs/oxlint-plugin.js` is **4,382 lines** of ESLint-v9-style `create(context)` rules on the alpha API (`oxlint-plugin.js:3`, rules at :507, :573, :627, :735), driven by `scripts/gen-oxlint.ts` (362 lines). Root `.oxlintrc.json` loads it as `jsPlugins`. Judgement: the alpha API risk is already carried and has held through 1.87 -> 1.90.
- [J] **How we GUARANTEE with this toolchain in v3**
  1. Tailwind-class rules need the class string, not types: all feasible in the alpha JS API (JSXAttribute `className`, `cn()`/`cva()` call args, template literals). Candidates: no arbitrary values (`[...]`) for colour/spacing/breakpoint, no raw palette utilities (`bg-blue-500`), no `!` modifier, no dynamic class assembly, literal-only classes (scan contract). Reuse `better-tailwindcss` for unknown/conflicting classes rather than writing them.
  2. Rules that need types (e.g. "prop must be a Tone union") stay on `isolatedDeclarations`/`tsc` or `oxlint-tsgolint` (TS 7 only, non-semver). Do not build custom type-aware rules; the API forbids it.
  3. A lint rule living in `bun test` (factory console `test/raw-colour.ts`, `shadcn-factory-console.md:51`) is the signal that consumers want rules but have no shipped plugin; v3's plugin should cover it.
- [J] Upgrade now: oxlint ^1.93, oxfmt ^0.78 (both released 2026-11-09). Pin oxfmt exact (0.x; format drift changes diffs) and re-run `fmt` as its own commit.

## 7. Release and publishing

Ours: `Make Release` workflow runs `node -r semantic-release-monorepo ./node_modules/.bin/semantic-release` with `MONOREPO_DIR=packages/basalt-ui`, PAT `RELEASE_TOKEN` to bypass the branch-protection ruleset (`.github/workflows/release.yml:44-60`); `.releaserc.json` uses commit-analyzer, notes, changelog, exec (`prepareCmd` regenerates `llms.txt`, MIGRATING), git, github. `Publish to npm` fires on `release: published`, `id-token: write`, Node 22, `npm install -g npm@latest`, `npm publish --access public` (`publish.yml:42-56`), `publishConfig.provenance: true` (`package.json:120`).

- [F https://docs.npmjs.com/trusted-publishers/, GitHub changelog 2025-07-31] Trusted publishing (OIDC) GA; needs npm >=11.5.1 and Node >=22.14; GitHub-hosted (and GitLab shared, CircleCI cloud) runners only, **not self-hosted**; provenance is automatic for public repo+package; `repository.url` must match exactly; workflow filename registered on npmjs.com; unconfigured/unverified config expires in 2 days; up to 10 publishers; "require 2FA and disallow tokens" setting; npm package pages warn token-based direct publishing is being restricted (Aug 2026 account, Jan 2027 direct). - [F] `bun publish` cannot generate provenance (`--provenance`, `publishConfig.provenance`, `NPM_CONFIG_PROVENANCE=true` all error) and has no OIDC exchange (oven-sh/bun#22423 open). Keep `npm publish`. `bun publish` strips `workspace:`/catalog specifiers; npm does not [U: if v3 uses `workspace:` deps in the published manifest, pack with bun first, check manifest].
- [F] `semantic-release-monorepo` 8.0.2: npm shows last publish ~3 years ago; plain `semantic-release` 25.0.9 current. It must be loaded via `-e`/`extends`; our `node -r` shim is a workaround.

## 9. Package shape and peer policy for v3

- [F ours] Today: 0 `dependencies`, 24 peers all optional via `peerDependenciesMeta` including the 5 hard-required ones, because npm is per-package not per-subpath (`MAINTAINING.md:155-161`); 13 subpaths + `./styles.css` + `./configs/*` (`package.json:49-116`); `sideEffects:["*.css"]` (`:46`). Exact-pinned peers for engine-coupled packages (`@tanstack/charts`, `d3-scale`, `remend`, fonts) (`MAINTAINING.md:163`).
- [F] shadcn changes the _shape_ question. shadcn registry types: `registry:base|style|theme|ui|block|component|page|file|lib|hook|font|item`; `shadcn build` -> static `/r/[name].json`; consumers map `@namespace` URLs in `components.json`; `registry:base` carries `style`, `iconLibrary`, aliases, `tailwind.baseColor`, `cssVars`, `css`, `registries`; `shadcn init -p <preset>`, `shadcn apply <preset> [--only theme|font]`; `base` option `base|radix|aria`; Base UI is the `init` default since July 2026, Radix still supported, `asChild` -> `render`; versioning in a registry is URL/tag based, `meta.version` is not semver-enforced; `tailwind.config` deprecated for v4. [https://ui.shadcn.com/docs/registry, changelog 2026-07, via research]
- [J] Fit for basalt-ui: its differentiators are **lint rules, tokens, skills, runtime wiring** — all things a registry cannot lock, and a registry copy is a fork the lint rules must chase. Evidence from our own consumers: epos kept shadcn files but repainted them (max 4 commits per primitive; churn was in app composites, `shadcn-epos-teamchat.md:86`); factory console never ran `shadcn add` (`shadcn-factory-console.md:31`); neither adopted basalt runtime. Recommendation shape: **npm package owns runtime, tokens, CSS (`@theme`, `@utility`), lint plugin and skills (single semver, single upgrade path); components are shipped as source in the tarball and consumed through npm imports by default, with a registry (`registry:ui`/`registry:block`/`registry:base`, one `shadcn build`) as the "own it" escape hatch generated from the same source.** One source, two delivery faces; the registry is a build artifact, not a second codebase. Hybrid is what shadcn itself does (npm `radix-ui`, `@base-ui/react`, `@shadcn/helpers` + registry) [F]. This is architecture; another agent owns the final call, flagged here because it drives the build and peer policy.
- [J] Peer policy proposal (inputs to the plan): (1) Hard peers only for what every subpath needs: `react`, `react-dom`, `@base-ui/react`, `tailwindcss` (`^4.3`); declare them **non-optional**; for subpaths that need none, rely on the tokens/CSS-only entry existing as its own package or as a no-JS subpath (rollhook and the factory console consumed only the token CLI output, `consumer-rollhook.md:7`, `shadcn-factory-console.md:8`; epos only tokens+concepts, `shadcn-epos-teamchat.md:30`). The optional-for-everything trick exists only to keep the token layer installable without Mantine; with shadcn the token layer needs no UI peer at all if it is CSS. (2) Feature peers stay optional per subpath (`@tanstack/react-table`, `charts`, `react-virtual`, `ai`, `shiki`, `react-markdown`...) as today, with ranges not exact pins except where the engine contract is the API (`@tanstack/charts`). (3) Replace dev-pins-as-peers with `^` ranges tested in CI at floor and ceiling. (4) `class-variance-authority`, `clsx`, `tailwind-merge` (or the `cn` decision above), `tw-animate-css`: **`dependencies`** (internal implementation, not user-facing), unlike today's "dependencies is empty". The "bare install = 1 package" property (`MAINTAINING.md:155`) is a v2 value that conflicts with owning shadcn components; decide it consciously.
- Preserve gates: `publint` + `attw` (already devDeps) in-build; `pack-test.sh` (658 lines) proves the tarball; `check-dist-layering.mjs`; export-surface snapshot (`scripts/export-surface.json`). `sideEffects` must list CSS (`["*.css"]`).
