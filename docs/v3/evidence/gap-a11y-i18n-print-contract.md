## 0. Verdicts

1. **A11y target WCAG 2.2 AA, enforced by axe in the real-Chrome layout suite plus the consumer gate.** Today basalt has no axe at all [F: no `axe` in
   `package.json`, `tests/`, `Makefile`; only shutterflow runs it]. A first axe pass over 16 fixture specs found 7 rule classes, 2 critical (section 1.6).
2. **Base UI does behaviour, we do appearance, names and announcements.** It never draws focus, never names icon controls, hardcodes two English
   strings, and leaves route-change announcement, skip link, tooltip touch fallback, forced colours and chart/table alternatives to us.
3. **i18n: do NOT build a translation system; ship one typed message catalog (English default) plus a locale/timeZone context on the provider, and
   delete the render-phase `defineFormat` global.** All 7 consumers are English-chrome; locale policy differs per app (section 2.3).
4. **RTL out of scope for v3 (not a promise), logical-property discipline in scope** because it is nearly free (basalt CSS is already ~83 % logical).
5. **Print: today it is broken, not merely unsupported.** An 80-row table prints 24 rows on 1 page, because the shell scrollport clips print
   (section 3.2, measured). v3 ships a small print contract (shell unclips, scheme reset, avoid-break marks); report layout stays with the consumer.

### 2.2 The render-phase global (F)

`BasaltProvider` calls `defineFormat({ locale, timeZone })` during render (`src/provider/index.tsx:508-513`); `defineFormat` mutates module state and clears two `Intl` caches (`src/format/shared.ts:45-54`). Formatters are plain functions reading that global (`:97-` `resolveLocale`). Consequences [J]: not concurrent-safe (an SSR process serving two locales cannot, as its own doc admits `:41-43`), mutated in render (Strict/Concurrent hazard), invisible in the type system, and two providers disagree. Brief marks it for redesign; agreed.
