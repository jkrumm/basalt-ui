## 0. Headline

- **Coexistence works at the CSS level with five conditions; route-by-route is viable but a bad default.** Recommend a per-app cutover on a branch (J); route-by-route only for argo, time-boxed (J).
- **Layout-primitive codemod: 91.4% of 2,555 target elements convert with no human flag, and 375/375 distinct prop signatures render geometry-identical** to the Mantine original in Chrome (F). ### 1.1 Layer order and preflight (F, measured)

| CSS entry                                                                         | Effective layer order (verified in built css)            | Mantine region vs Mantine-alone                                                                                                                                                           | v3 region vs Tailwind-alone                                                                                               |
| --------------------------------------------------------------------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| naive: `@import 'basalt-ui/styles.css'; @import 'tailwindcss'`                    | mantine < basalt < base < theme < components < utilities | 13/17 elements changed, 76 property diffs: Button padding 16px to 0, background to transparent, radius 6px to 0, 13px to 15px; Title 26px/550 to 15px/400; inputs lose padding+background | 12/17, 21 diffs (inherited type only)                                                                                     |
| ordered: first line `@layer theme, base, mantine, basalt, components, utilities;` | theme < base < mantine < basalt < components < utilities | 3/17, 12 diffs, all from one bare `<button>` inside the Mantine region now reset (UA outset border and grey fill gone) plus the parent height it caused                                   | 12/17, 21 diffs (below)                                                                                                   |
| no preflight: only `tailwindcss/theme.css` + `utilities.css`                      | mantine < basalt < theme < components < utilities        | 0/17                                                                                                                                                                                      | 17/17, 52 diffs: bare buttons keep UA fill `rgb(107,107,107)` + 2px outset, `p`/`h2` margins 14px/14.9px, no border reset |

- Cause of the naive break (F): `basalt-ui/styles.css:17` declares `@layer mantine, basalt;`, Tailwind's preflight lands in `base` after it and beats every Mantine class rule regardless of specificity. The fix is one statement placed before any import (F: verified order `properties, theme, base, mantine, basalt, components, utilities` in the built file).
- Residual v3-region differences under `ordered` (F): inherited type (`body` is Mantine's 15px/1.55 from `@layer mantine` baseline, Tailwind-alone is 16px/1.5) and `input,select,textarea { font-size: max(16px, ...) !important }` at `packages/basalt-ui/src/styles.css:150-153`, which turned a 14px v3 input into 16px. An `!important` in a lower layer beats every utility, so v3 dense inputs cannot win without their own `!important`.
- Tailwind classes on 2.x components do not win (F): 54 `*.module.css` ship in dist with 0 inside `@layer`, and components also write inline style (`dist/dashboard/empty-state.js:25-30`). Unlayered beats layered, inline beats both.
- Fonts and rem (F): root stays 16px in all configs, `--mantine-scale` is 1, so no rem drift. Type differs: Mantine tokens 12/13/15/16/18px against Tailwind defaults 12/14/16/18/20px. The codemod bench (section 2) needs `--text-*`, `--radius-*`, `--breakpoint-*` (basalt: xs=sm=52.5em, md=lg=xl=75em, from the injected `--mantine-breakpoint-*`) and `--font-mono: var(--basalt-font-mono)` overridden to be exact. Two font-stack variables coexist (`--basalt-font-sans` vs `--font-sans`).
- Cost (F, minified gz): Mantine-only css 43.4 KB / js 229 KB; both 48.5 KB (+5.1) / 255.8 KB (+26.7 with five Base UI parts). Two runtimes are shipped for the duration.

### 1.2 Scheme attribute and tokens (F, measured)

- Mantine writes `data-mantine-color-scheme` on `<html>`; the v3 tokens key off `data-theme`. Both define the same `--vx-*` names (basalt injects its palette per `[data-mantine-color-scheme]`; `tokens.css` per `[data-theme]`).
- With the attributes split, `tokens.css` wins the `--vx-*` variables (v3 attribute light, Mantine dark: v3 surfaces and body light, `color-scheme: dark`), while `color-scheme` and Mantine's own `--mantine-color-*` follow Mantine. Result is mixed: scrollbars and native controls disagree with the page.
- Default is split-brain: `localStorage['mantine-color-scheme-value']='light'` plus reload gave Mantine light and the hard-coded v3 attribute dark. The boot script reads only that key (`src/vite-boot.ts:27-42`).
- A 6-line one-way bridge (MutationObserver, Mantine attribute to `data-theme`) fixed all three cases (verified). Mantine is the single writer while both exist.

### 1.3 Overlays, focus, z-index (F, measured with real clicks)

- Mantine z-indexes: modal 200, popover 300, overlay/notifications 400 (`--mantine-z-index-*`, container computed 400). shadcn base-nova puts `z-50` on the **Positioner**.
- Base UI Popover opened inside a Mantine Modal: hidden behind the Modal overlay (`elementFromPoint` returns `mantine-Modal-overlay`), click times out. Raising the Positioner to 300 makes it visible and clickable and does not close the Modal.
- Mantine Select dropdown (300) inside a Base UI Dialog (50): visible, option selectable, Dialog stays open. But Base UI marks the sibling portal subtree `aria-hidden="true"`, so the dropdown is hidden from assistive tech (F: `closest('[aria-hidden=true]')` true).
- One Escape closed both the Base UI popover and the Mantine modal: no layered dismissal across libraries.
- Base UI Dialog sets body `overflow:hidden` and html `scrollbar-gutter:stable`, cleared on close (no leak). Mantine notification (400) renders above a Base UI dialog.
- Fix (J): one z scale during coexistence, v3 overlays take Mantine's values (dialog 200, popover 300) via `z-[...]` on the Positioner.

### 1.4 Providers (F, measured)

- Two `QueryClientProvider`s nested: both regions fetch; caches are separate (no shared invalidation). `BasaltProvider` reads `context.queryClient` from its router and throws without it (`src/provider/index.tsx:459-467`).
- Second TanStack router on memory history: independent, works. Second router on browser history: `second.navigate('/v3page')` moved the first router to `/v3page` and unmounted the page that hosted the v3 region; after `first.navigate('/')` the second still reported `/v3page` (stale). Two routers cannot share one URL, so v3 routes must be routes of the **one** router.
- Same npm name: `basalt-ui` 2.x and 3.x can coexist only via an alias (`"basalt-ui-old": "npm:basalt-ui@2.28.0"` installed and resolved as a second physical copy; dist JS has no self-imports by name, only `.d.ts` hits). The `basalt-ui` bin, `doctor` and `sync` bind to the primary name.

### 1.5 Verdict

Route-by-route needs: (1) the layer statement first, (2) one router and one QueryClient owned by the 2.x provider, (3) the scheme bridge, (4) one z scale, (5) no Tailwind overrides on 2.x components and a scoped input floor, plus the npm alias if v3 pages import v3 components. The shell is the atomic unit (J): v3 page bodies can sit inside the 2.x shell only if they keep calling the 2.x `PageBar`/`PageAside` portals through the alias. Per-app judgement: the ten consumers are single-owner, mostly tailnet apps with gates and baselines, so a branch cutover has no user-facing risk and avoids two runtimes, the alias, a mixed lint regime (J). Exception: argo (180 basalt-importing files, daily churn, 234 friction rows) where a frozen branch would rot; there a time-boxed route-by-route with a coexistence kit of about 40 lines is justified (J, U: owner may prefer a pure rewrite on a branch, as the brief frames "argo rewrite").

### 3.2 2.x support window, jumps, migration format

- **2.x window (J):** patch and security only, no features, no token value changes, until argo and the last 2.x consumer cut over, with a hard review date 120 days after the first stable 3.0.0; announce the end date at 3.0.0 (rollhook lesson 6, `consumer-rollhook.md:203`). `latest` stays on 2.x during the `next` series; at 3.0.0 `npm deprecate "basalt-ui@<3"` points to the migration (rollhook is exact-pinned and never sees ranges). Gate change (F): `scripts/release.sh:37` `version_gate` and `MAINTAINING.md:511` must allow a `next` prerelease channel and 3.x; `.releaserc.json` has `branches: ["master"]` only.
- **Direct jump (J, yes):** shutterflow (1.40.3) and image-gateway (1.41.0) go straight to 3.x. A second baseline regeneration is avoided (every 1.x bump regenerated 33-36 PNGs: `consumer-shutterflow.md:117`) and rb needed 8 waves for 1.41 to 2.8. Needs `migrate --from 1.40.3` to fold the 2.0.0 and 3.0.0 rows (A to B then B to C resolves to A to C).
- **Same name vs new name (U, owner):** a major under the same name caused the silent rollhook stall (`consumer-rollhook.md:195-205`); mitigations are deprecate, a `2.last` doctor message and exact-pin probes in a fleet registry.
- **Machine-readable format (J):** seeds exist (F): `scripts/export-surface.json` (symbols per subpath, 2.5 KB), `scripts/consumers.json` (124 symbols to first consumer file), `doctor --from` parsing `Visible without code change` headings (`src/cli/doctor-upgrade.ts:698-728`) and `scripts/release-migrating.ts`. Today MIGRATING.md is 6,850 lines of prose (F). v3 ships `migrations/<version>.json` as the source and generates the human file:

```
{ schema:1, from:">=1.40 <3", to:"3.0.0", profiles:["tokens-only","components","shell","charts","agent"],
  rows:[{ id, kind:"rename|move|replace|removed|behavior", from:"basalt-ui#BasaltShell", to:"basalt-ui/shell#Shell",
          profiles, codemod:"id|null", verify:"grep|ast check", note, manual:false }],
  tokens:{ contract:2, renamed:[...], valueShifts:[{token,from,to}] },
  storage:[{ key, action:"keep|read-legacy|rename", to }], urls:[{ store, golden:"fixtures/..." }],
  attrs:[{ from:"[data-mantine-color-scheme]", to:"[data-theme]" }], rules:[{ old, new, severity }],
  codemods:[{ id, covers:[...], residual:"human reasons" }] }
```

`basalt-ui migrate --from X --profile P [--json]` selects rows by the consumer's import census (as `consumers.json` does), `--check` fails loudly on any removed symbol still imported, and the release gate fails when the export-surface diff has a symbol with no row (the `release-migrating.ts` pattern). This answers rollhook's "21 versions of MIGRATING for 3 rows" (`consumer-rollhook.md:129`).

- **Persistence contract (J):** (1) `basalt:<key>` `{v,value}` envelopes and the `createSearchStore` URL codec frozen, proven by golden round-trip fixtures captured from argo, linewatch, shutterflow; (2) scheme: v3 reads `mantine-color-scheme-value` as legacy and writes the new key, exposes `data-theme` (already what the tokens CLI and the console use), and `doctor` lints `[data-mantine-color-scheme]` selectors (rb `styles.css:19-23`, weatherorb `landing/tokens.css:199`); (3) app-owned `mantine-*` keys (shutterflow) are untouched, a storage adapter in `createPersistedState` would delete its `Storage.prototype` patch (U owner, `consumer-shutterflow.md:237`).

### 4.2 Consumer-facing test contract v3 ships (J unless cited)

1. **Public stable handles.** `data-slot="<name>"` on every owned part (shadcn convention; Base UI itself emits none, F: dialog popup attributes are `data-open,id,role,tabindex,data-base-ui-focusable,style,aria-labelledby`). A typed `SLOTS` list is the promise: shell regions (`shell, sidebar, sidebar-footer, header, titlebar, page-bar, main, aside, mobile-nav`), composites (`stat-card, chart-card, data-table, table-toolbar, board, section, empty-state`), plus `data-state="loading|empty|error|ready"`. `main` replaces `data-basalt-scrollport` (already promised, `tests/layout/harness.ts:52-53`). Everything else internal, with a consumer lint rule against selecting classes or unlisted slots (shutterflow does `querySelector('.mantine-AppShell-header')` at `app/RootLayout.tsx:26`; its e2e has 12 such selectors). Guarantee: a snapshot test of `SLOTS` against rendered DOM, like `export-surface.json`.
2. **Scheme attribute.** `data-theme="light|dark"` plus `color-scheme` on `<html>`, boot script before paint, and a `setScheme()`; the harness needs one switch (shutterflow flips the Mantine attribute in 26 e2e files).
3. **`basalt-ui/testing`.** `renderApp(ui, { route, search, scheme, queryClient })` returns the RTL result plus router and client, generalising `src/provider/test-router.tsx:1-28` which is not exported today (F: consumers hand-roll `MantineProvider` wrappers: linewatch 4 render tests, obsidian 9 sites). Defaults: fresh QueryClient per test with no retry, `Tooltip` delay 0, `await settled()` flushing router, queries and the Base UI mount tick, own cleanup (F: RTL auto-cleanup no-ops under `bun test`, `tests/setup/dom.ts` note).
4. **jsdom/happy-dom requirements (F, measured with Base UI 1.9.0).** Dialog, Popover, Select, Menu, Tooltip, Tabs all work in jsdom 30.1.3 (vitest 5.0.5) and in happy-dom 21.0.4 under `bun test` with **no shims** for these six. Rules: popups are not reliably present synchronously (Select and Menu items needed `findBy*` in jsdom but were present at once in happy-dom, Dialog and Popover content were present after `await user.click` in both), so always `findBy*`/`waitFor` (epos reaches the same rule: `repo/AGENTS.md:4075-4077` per `shadcn-epos-teamchat.md:88`); Tooltip needs hover delay about 600 ms (616 ms measured) so tests set `delay={0}`; `Select.Value` shows the raw value unless `items` is passed (test failed "b" vs "beta"); an open modal Dialog `aria-hidden`s the rest, so `getByRole` misses outside content unless `hidden:true`; floating geometry is zeros in both DOMs (`--available-width:-10px` in the dump). Geometry therefore belongs to the browser layer. epos stubs `ResizeObserver`, `matchMedia`, `scrollTo` (`ui/src/test/setup.ts:15-30`); the kit ships `installDomShims()` for the parts not covered here (U: ScrollArea, Slider, virtual lists untested).
5. **Shell invariants kit (Playwright).** `expectShellInvariants(page, { states: expanded|collapsed|native })` ports shutterflow's `e2e/desktop/visual/invariants.spec.ts`: footer rows inside the sidebar with bottom inset at least the horizontal padding (:121), footer rows share the nav icon column and native header height 52 (:146-165), first nav item same top offset expanded and collapsed (:182), content starts at the shell gutter with nothing clipped at the window bottom (:207), one header height (:236), nav rows evenly spaced within 1px (:251), footer rows share nav row pitch (:271), no element overflows the viewport (:349-368). It reuses basalt's own `expect*` assertions (`tests/layout/harness.ts:764-1003`), so two implementations collapse into one, keyed by `data-slot`.
6. **`shot` anchors.** Do not survive as a consumer contract (J). F: argo has 152 `data-shot*` attributes (evidence counts 88 anchors in 46 files) which `consumer-argo.md:91` calls boilerplate; `--auto-anchors` already tags by Mantine class (`src/cli/shot/capture.ts:237`) and `STATE_SURFACE` already uses `data-basalt-*` (`capture.ts:241`). v3: shot reads the public card-like `data-slot`s, consumers write none; `data-shot`, `-states`, `-absent` remain optional override attributes; argo's 63-line `shotFetcher` shim becomes a provider-level forced-state hook so per-page `Box data-shot-states` wrappers die. Also remove the `mantine-color-scheme-value` seed at `capture.ts:1026`.
