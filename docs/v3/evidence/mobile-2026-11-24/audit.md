# basalt-ui v3 on a phone: read-only audit (2026-11-24)

Paths: `pkg/` = packages/basalt-ui, `pg/` = apps/playground. Static read only: no build, no test, no browser, so every "renders as" below is derived from code, not observed. Items marked (unverified) need a device.

## 1. Phone shell

- Size classes. Viewport: compact < 840, medium >= 840, expanded >= 1200 (pkg/src/tokens/size-classes.ts:10; hook pkg/src/page/use-size-class.ts:5-31, server and hydration read 'compact'). Tailwind md = 840, xl = 1200 (pkg/src/css/tailwind.css:74-75). There is no "tablet" class: an iPad portrait (820) is compact and gets the phone shell. Container classes (a component's own width): micro < 240, narrow 240-479, regular 480-799, wide >= 800 (size-classes.ts:13); a 390 page is "narrow".
- Frame: one CSS grid, root `h-dvh`, document never scrolls, `Main` is the scrollport (pkg/src/shell/parts/grid.tsx:16, 287). Compact: rail width 0, surface flush (no inset/rounding), `--shell-gutter` 8px (grid.tsx:291; 16 at md, 24 at xl: 294-295). Landscape phone (<= 30rem tall): header height clamps to clamp(2.25rem, 9dvh, 3rem) (grid.tsx:297); `compactHeader="hidden"` removes the header on a phone (grid.tsx:298).
- Tab bar built in pkg/src/shell/parts/mobile/tab-bar.tsx (285 lines), mounted `md:hidden` in the footer grid row (pkg/src/shell/parts/mounts.tsx:24); rail is the `hidden md:block` twin (mounts.tsx:16). Both server-render, CSS picks one.
- Bar geometry: `h-12` (48px) nav + 1px border + `pb-[env(safe-area-inset-bottom)]` (tab-bar.tsx:240-246); tab `min-h-11`, pill icon 24px, label `text-micro` 11px, max ~10 chars else dev warning (tab-bar.tsx:63-70, 138-150). Header is another 48px (`--shell-header-h` spacing(12), grid.tsx:291): fixed chrome is 96px + safe area (~11% of 844 before the inset).
- Slot selection is pure data: `projectMobileNav` (pkg/src/shell/core/mobile-projection.ts:467). Sources, in order: `mobile.tabs` explicit id list (:317-355, replaces every item flag); else section `mobile: { tab: true }` (a section tab, one slot holding a menu or sheet, :258-294); else items with `mobile: 'tab'|true` (:366-371); else fallback = first maxTabs-1 top-level items (:374-383). Item values 'tab' | 'more' | 'hidden', `undefined` means More (:142-149; type pkg/src/router/nav/types.ts:18-39). `short` is the bar label (types.ts:35).
- Max items: `maxTabs` default 5 INCLUDING More (mobile-projection.ts:41, :471); More exists only if something overflows or extras exist (:502-507); slice at maxTabs-1 then (:507-509); dropped candidates fall into More with a dev warning (:511-515). `menuMax` default 12 rows (:44): a slot with <= 12 rows is a "menu", more is a "sheet" (:281). DOC DRIFT: pkg/src/router/nav/types.ts:163 says `@default 6`, code says 12.
- More surface = `ui/sheet` bottom panel (pkg/src/shell/parts/mobile/more-surface.tsx:1-12, 70-90). "menu" is the same panel lifted `mb-[calc(spacing(12)+1px+env(safe-area-inset-bottom))]` so the bar stays visible (:52); "sheet" rises from the edge with `pb-[env(safe-area-inset-bottom)]` (:81). Cap `min(72dvh, 560px)`, rows scroll inside with `overscroll-contain` (:48). Rows `min-h-12` (48px, :44). More also holds blocks, settings, workspace and account rows (mobile-projection.ts:444-461), so account/settings live behind More on a phone.
- Badges on tabs: SUPPORTED but dot-only. A lit badge (count or dot) draws an 8px dot on the icon, warn colour if `attention` (tab-bar.tsx:113-120); a count is never shown on the bar (test pkg/src/shell/parts/mobile/tab-bar.test.tsx:451-456 passes `{count: 3}`, expects a dot). A More/section slot shows the rollup (sum, mobile-projection.ts via `rollupBadges`, shell/core/badges.ts); inside the surface rows show a real `CountBadge` (more-surface.tsx:93-104).
- Header on a phone (pkg/src/shell/parts/header.tsx:1-24, 283-380): logo-only `BrandMark` (:167-180, no brand name, no rail toggle), breadcrumb with the nav section dropped (pkg/src/shell/app-shell.tsx:244-252: page parent + title only), `globalControls` hidden unless the slot sets `compact: true` (header.tsx:337-343), page actions (each action's `mobile` flag, `max-md:hidden` when 'more'/'hidden', :255-265), the aside trigger as a secondary Button (app-shell.tsx:74-90, 261-265), global actions with `mobile: 'bar'|'more'|'hidden'` (pkg/src/shell/contract.ts:65) and a kebab only when a phone-kept action yields (header-kebab.tsx:20-28).
- Rail/sidebar on a phone: NOT reachable. Decision 6 "no mobile sidebar" (docs/v3/concepts/shell-nav-router.md:16; tab-bar.tsx:2). The shadcn-style mobile Sheet sidebar was rejected as contradicting the tab-bar law (docs/v3/DISCOVERY-DIGEST.md:59). The command palette has no phone trigger: the only opener is Mod+K or the rail's search row (pkg/src/shell/parts/rail.tsx:137), and the rail is hidden below 840; no phone/touch code in pkg/src/shell/commands/ (rg: 0 hits).
- Safe-area: bottom only. Used in tab-bar.tsx:241 and more-surface.tsx:52,81. Not handled: top inset, left/right inset (landscape notch), generic bottom `Sheet` content (pkg/src/ui/sheet.tsx:52 has `max-h` only; PANEL_BODY/PANEL_FOOTER pkg/src/core/panel.tsx:31-35 add no inset), so Peek/aside/detail sheets on a home-indicator iPhone end under the indicator when `viewport-fit=cover` is on (unverified).
- viewport-fit: the Vite plugin injects `width=device-width, initial-scale=1.0, viewport-fit=cover` ONLY when index.html has no viewport meta (pkg/src/vite/head.ts:75, 197-206). `basalt-ui init` writes no meta itself (pkg/src/cli/init/steps.ts wires `basalt()` only; router-seeds.ts:145 only deletes index.html for Start). pg/index.html:5 carries its own `width=device-width, initial-scale=1.0` with no `viewport-fit`, so `env(safe-area-inset-*)` is 0 in the playground by construction; apps/marketing/src/layouts/Layout.astro:25, apps/playground-astro/src/layouts/Part.astro:13 and examples/react/index.html:6 likewise. Manifest option sets status-bar style 'default' (head.ts:140).
- dvh/svh: `h-dvh` frame (grid.tsx:287), Sheet `72dvh` (sheet.tsx:52), Dialog `100dvh-2rem` (pkg/src/ui/dialog.tsx:24), chart box coarse cap `45svh` (pkg/src/charts/chart-box.module.css:45-48), `100vw` in Dock compact (pkg/src/page/dock.tsx:112).
- Virtual keyboard: nothing ships. rg for visualViewport / interactive-widget / keyboard inset in pkg/src (non-test, non-lint) finds only a comment that Safari lacks `interactive-widget` (pkg/src/styles.css:98). Frame is `h-dvh`, so where the browser resizes the layout viewport for the keyboard (Chrome Android) the bar rides above it; on iOS Safari dvh does not track the keyboard (unverified). A soft-keyboard model exists only as a spike (tools/spikes/scroller/run.ts:11). Dialog is centred (`grid place-items-center p-4`, dialog.tsx:68), not bottom-anchored.

## 2. Overlays on touch

Library: Base UI 1.9 (`@base-ui/react ~1.9.0`, pkg/package.json:336, 382). Nothing swaps its form on a phone except Sheet's edge, Peek, and the table detail.

- Tooltip (pkg/src/ui/tooltip.tsx:36-52): hover/focus only, `delay` 600; no touch path. Doc calls the label "a visual aid only", so on touch the label is simply absent.
- InfoHint (pkg/src/ui/info-hint.tsx:53-58, 83-87): Popover with hover 150ms and press; tap opens; hit area `pointer-coarse:after:-inset-2.5`.
- Popover (pkg/src/ui/popover.tsx:16, 52): anchored popup, `w-72 max-w-(--available-width)`; `openOnHover` also opens on touch press. Same floating form on a phone.
- HoverCard = PreviewCard (pkg/src/ui/preview-card.tsx:8-16, 84-125): first touch tap opens the card, second tap follows the link (FIRST_TAP attribute).
- Menu (pkg/src/ui/menu.tsx:16, 27): anchored popup; rows `pointer-coarse:min-h-11 text-base`. Not a sheet.
- Select (pkg/src/ui/select.tsx:47, 67, 552): anchored popup, trigger and items 44px/16px coarse. `NativeSelect` exists as the OS-picker option (:91-99, 617-645; doc :255 "an OS picker on phones"), opt-in only.
- Combobox (pkg/src/ui/combobox.tsx:49, 69, 81): anchored `max-h-(--available-height)` popup, coarse 44px/16px; no sheet form.
- Dialog (pkg/src/ui/dialog.tsx:24, 62-68): centred modal, `max-h calc(100dvh-2rem)`, `p-4` viewport; no bottom-sheet form. Sizes sm..wide are max-widths, so on 390 all are ~358 wide.
- Sheet (pkg/src/ui/sheet.tsx:1, 51-52, 181-190): THE drawer. Built on Base UI `Drawer` (`import { Drawer as BaseDrawer } from '@base-ui/react/drawer'`, :1). `placement="auto"` = bottom below 840, right from 840 (:26-27, 182-184); swipe-to-dismiss is on (`swipeDirection` down or right; `translate-y-[var(--drawer-swipe-movement-y)]`, `data-swiping:transition-none`, :52, 66). Gaps: no visible grabber/handle on the bottom edge (PanelHandle only for the right edge, :257-265); no snap points wired (Base UI `snapPoints` exists in node_modules/@base-ui/react/drawer/root/DrawerRoot.d.ts:89, passes through the props type but no CSS/height logic and zero uses in pkg/src); fixed cap `min(72dvh,560px)`; right-edge width is persisted-resizable (:36-49).
- Peek (pkg/src/page/peek.tsx:211-253): under a shell and compact it becomes a bottom `Sheet` with scrim (`PeekSheet`); otherwise a `<dialog>` panel.
- Dock (pkg/src/page/dock.tsx:109-113): compact keeps a side panel, widened to `calc(100vw - rail-w)`, handle hidden; NOT a bottom sheet, and a compact screen never docks (grid.tsx:530).
- PageAside: compact claim = Sheet opened from a header button (app-shell.tsx:74-90, pkg/src/page/page-aside.tsx:266-284).
- Command palette (pkg/src/shell/commands/command-palette.tsx:162-208): centred Dialog, list `max-h-80`, row size lg; no phone trigger (see 1).
- DatePicker (pkg/src/ui/date-picker.tsx:165-186): Popover with `w-auto` calendar; day cell 36px, 44px coarse (:48-53; calendar.tsx:44-45), ~334px wide, fits 390. Field coarse 44px/16px (:32). No sheet form.
- Table detail (pkg/src/table/parts/detail-sheet.tsx:81-111) and view panel (view-panel.tsx:8): bottom Sheet on compact, Peek beside the table above it.
- Chart info glyph: native `popover` API (pkg/src/charts/parts/chart-card-frame.tsx:46-60), tap works.

## 3. Inputs

- Component text: Input md = `h-ctl px-3 text-sm` (28px high, 13px at the default dense density), sm = `h-6 text-xs` (pkg/src/ui/input.tsx:18-30). Coarse: `pointer-coarse:min-h-11 pointer-coarse:text-base` = 44px / 16px, same on Textarea (pkg/src/ui/textarea.tsx:53), Select trigger (select.tsx:47), Combobox (combobox.tsx:49, 102, 139), DatePicker (date-picker.tsx:32), TagInput (tag-input.tsx:19), Autocomplete/OptionRow (pkg/src/core/list/option-row.tsx:22).
- Axis is the PRIMARY POINTER, not width: a desktop window narrowed to 390 with a mouse keeps 28px/13px controls. Matrix emulates it by width: `pointer: cell.width <= 600 ? 'coarse' : 'fine'` (pkg/tests/quality/matrix/matrix.test.ts:83).
- 16px zoom rule exists twice. (a) `basalt-ui/tailwind.css`/`static.css`: `@media (pointer: coarse) { input, select, textarea { font-size: max(16px, 1em) !important } }` (pkg/src/css/tailwind.css:189-195, generated from pkg/src/css/generate.ts:191). (b) `basalt-ui/styles.css`: UNCONDITIONAL `font-size: max(var(--basalt-input-fz-floor, 16px), var(--input-fz, 1rem)) !important` on input/select/textarea at every pointer (pkg/src/styles.css:114-118, pinned by pkg/src/styles.floor.test.ts:24-33). pg/src/main.tsx:2 imports styles.css, so the playground gets (b): desktop inputs there are 16px whatever `text-sm` says (static read; the CSS-layer outcome is unverified). The two files disagree on the policy; the comment in (b) cites 2.x-era files (app-sidebar.module.css, styles.css:53-60).
- `maximum-scale` / `user-scalable`: none anywhere (rg: 0 hits in pkg/src, apps). The viewport meta init path is in section 1.

## 4. Touch targets

- Tokens (pkg/src/css/tokens.css:177-198; emit pkg/src/tokens/emit.ts:80-92): `--basalt-ctl-h` dense 1.75rem (28), normal 2rem, comfortable 2.5rem; `--basalt-row-h` 2rem / 2.5 / 3; coarse raises row-h to 2.75rem (44) for dense and normal only; `--basalt-hit` 1.5rem (24), coarse 2.75rem (44). `--basalt-ctl-h` itself does NOT change on coarse; each component adds `pointer-coarse:min-h-11` (Button md: button.tsx:37, icon size-11 :39).
- Hit-area expansion: `data-basalt-hit` / `data-basalt-hit-scope` give an invisible ::after to `--basalt-hit`, with an overlap cap `--basalt-hit-gap` (pkg/src/styles.css:195-233). Many small controls hand-roll the same trick (`after:` + `pointer-coarse:after:min-h-11`: button.tsx:32, card-menu.tsx:34, chart-card-frame.tsx:37,51, quick-picks.tsx:22). Button `sm` stays 24px drawn with a 44px overlay (button.tsx:32, 38, 41-43).
- touch-action: `touch-manipulation` only on tab-bar tabs and More rows (tab-bar.tsx:66, more-surface.tsx:45); `touch-none` on resizers, slider, sortable handles (slider.tsx:15, panel.tsx:50, sortable-list.tsx:23, rail-resize.tsx:85); charts `pan-y` on coarse (pkg/src/charts/host.tsx:41, 66).
- Tap highlight: global transparent on button, a, [role=button], [role=tab] (pkg/src/styles.css:83-92).
- Pressed state: only the tab pill (`group-active/tab:scale-90`, tab-bar.tsx:68-69). `ui/button.tsx` has 0 `active:` classes. Hover-only fills (`hover:bg-accent`) are the only feedback for rows, menu items and cards on touch.
- Floors are asserted for the shell: bar 48, tabs 44, surface rows 48 (pkg/tests/layout/shell-mobile-nav.layout.test.ts:381, 440).

## 6. Tables on a phone

- Plan: `pkg/src/table/core/plan.ts` assigns priority 1/2/3 and a card slot per column and computes `reducedFrom` (480, 700 or 800: smallest step where priority 1+2 fit, plan.ts:17-18, 271). `tierAttributesOf` writes `data-phone` and `data-below` from props only (pkg/src/table/parts/tiers.tsx:14-24), so server HTML is already the right tier. Tiers are CSS container queries on the table scroller's own width, not the viewport (pkg/src/table/table.css:1-12, 347+).
- Options: `phone: 'cards'(default) | 'scroll' | 'columns'` (pkg/src/table/contract.ts:393), `cardsBelow: 'regular'(480) | 'wide'(800) | 'always'` (:417), `look: 'reading' | 'grid'` (:405-409), per column `priority 1|2|3` and `card: 'title'|'subtitle'|'badge'|'value'|'meta'|'edit'|'detail'|'hidden'` (contract.ts:27-36). Both a table in a half-width desktop cell (~730) and a phone fold to cards (agent/skills/basalt-design/references/chart-view.md:21).
- Card structure (table.css:347-480, below 480 and again at 800): the SAME `<tr>` becomes a CSS grid row `grid-template-columns: minmax(0,1fr) auto`, padding 12px 16px, gap 4px 12px, bottom hairline via inset box-shadow; header visually hidden, its sort/select controls `visibility:hidden` (sort moves to the toolbar). Cells stack full width; identity cell is the title (weight 500, col 1); `actions` sits col 2 row 1; a mono entity id rides the title line; every other value is a line prefixed by its header (`data-label` ::before `'Header: '`) with the money unit appended (`data-unit` ::after). `card: 'hidden'` cells are display:none; priority-3 cells show on the card. So a card is a labelled-value list row, not a bordered card surface: no ring, no radius, no per-card background.
- List look as alternative: yes, but as a reader-selected layout, not a phone strategy. `layout: 'table' | 'list' | 'board' | 'gallery'` (contract.ts:94, `layouts` prop :470); `list` = one flex line per row from card places, from 480 up, and "phone cards below" (table.css:1389-1450). Board and gallery read the same card face (pkg/src/table/layouts/model.ts:1-20, up to 4 badges). `phone: 'scroll'` pins the identity column and scrolls sideways; `phone: 'columns'` keeps three columns (name, value, first meta) and moves the rest to details (contract.ts:386-391).
- Row activation: compact opens a bottom Sheet detail (detail-sheet.tsx:81-111); `detail`, `onRowActivate` and the Details door are described in agent/skills/basalt-design/references/table.md:90.
- Missing sheet is a dev warning (tiers.tsx:41-55): the tier CSS is `basalt-ui/table.css`, added by `basalt()`.

## 7. Charts on a phone

- Height: bare chart box = clamp(160, ratio x cqw, 420) with ratios micro .5, narrow .62, regular .5, wide .4 (pkg/src/charts/box.tsx:17-18, 36-37); ChartCard boxes: auto `clamp(12rem, 50cqw, 26.25rem)`, tall `clamp(18rem, ...)`, short 160 (chart-card.tsx:29-34). At a 342 frame: auto 192, tall 288 (agent/skills/basalt-design/references/chart-view.md:33), bare ~212. Coarse cap `max-height: 45svh` (chart-box.module.css:45-48): 380 on an 844 phone, binds in landscape (390 high: 175).
- Tick density per container class (pkg/src/charts/core/compile.ts:194-199): micro x2 y0, narrow x3 y3, regular x5 y5, wide x6 y5; one tick font, micro 11px (:191); x ticks thinned by stride/bucket (core/ticks.ts:8-60), engine collision gap 8 (compile.ts:209 TICK_MIN_GAP).
- Legend: none < 240, dots 240-479, chips >= 480, chosen by CSS on the chart container so SSR matches (pkg/src/charts/chart-legend.module.css:1-45). Coarse toggles are 24px drawn + 44px overlay capped by `--basalt-hit-gap`; a wrapped dots legend gives ~29px vertical targets (pkg/src/charts/legend.tsx:27-36). Known open finding: the wrapped interactive legend overlaps toggles at 390 coarse (pkg/tests/quality/matrix/known.ts:155-173).
- End labels: `naming="auto"` draws them only at the wide class and with <= 3 lines (pkg/src/charts/labels.ts:64, 74; lines-marks.ts:55; cartesian.tsx:344), so on a phone the legend names the lines unless `naming="endLabels"` is forced.
- Hover vs tap: coarse pointer sets `pin: true` so a tap pins the cursor (compile.ts:2841, cursor.ts:445); host sets `touch-action: pan-y` so vertical swipes scroll the page (host.tsx:41, 66). Tooltip rows are re-gridded so a 390 tooltip does not squeeze names (chart-box.module.css, `.ts-chart-tooltip__row`). Linked focus with lists is hover-driven with a release grace (pkg/src/core/focus-release.ts); a 390 phone-list case is pinned by pkg/tests/layout/kit-expr14-focus-phone.layout.test.ts. Heatmap and interval track read `useCoarsePointer` (heatmap.tsx:388, interval-track.tsx:287). No long-press, no pinch/zoom, no brush on touch.
- SSR caveat: a static (Astro, no island) chart is drawn for 640 and scaled into the 342 box with smaller text (apps/playground-astro/src/parts/findings.ts:30).
