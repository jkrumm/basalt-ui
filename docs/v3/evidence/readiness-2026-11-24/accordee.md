# basalt-ui v3 vs Accordee: cross-validation (HEAD 2fed04240, read-only)

Method: read all 10 reports in ~/.local/state/basalt-accordee/reports, opened 24 screenshots across the six clusters (shell, tables, records, comms, workflows, settings; the reports matched what is visible, no discrepancy found), read docs/v3/BENCHMARK-ACCORDEE-BLUEPRINT.md and the bench README, then checked every verdict in code under packages/basalt-ui. No build, test or server was run, so "YES" means the export exists and a route or block composes it, not that it was rendered today. Paths below are relative to packages/basalt-ui unless they start with apps/ or docs/.

## Verdict

The benchmark brief is out of date in a good direction: at HEAD basalt expresses most of Accordee's structure (surface model, view row, saved views as tabs, record surface in three presentations, wizard, mailbox, schedule, flow canvas, assistant parts, settings kit) with typed, URL-addressable wiring Accordee lacks. The freeze risks that remain are few and are mostly closed unions and missing seams, not missing parts: a closed table layout list, a commands-only palette, a static module-scope nav, no record navigation on a routed record page, and two proven pages (flow, schedule) that a consumer's agent cannot reach. No P1: nothing found that makes a frozen contract wrong in a way a 3.x minor cannot fix additively, with the exception of the layout union (P2, because it changes a persisted saved-view value type).

## Ten most valuable remaining gaps, ranked

1. Palette result sources (records, recents, row actions). Part: `CommandPalette sources`, section above. Highest daily use in Accordee, and a prop-contract change.
2. Open table layouts (timeline, folders, map, forecast as consumer layouts). Option: layout specs registered in `useDataTable({layouts})`.
3. Record page navigation. Option: `PageBar records` with close, prev, next and `j/k`.
4. Flow and schedule as installable blocks (`add flow-builder`, `add schedule-page`), plus add-step menu and group drag on FlowCanvas (Accordee has both; basalt has fold and pan/zoom only).
5. User-editable card grid (dashboard and record overview): `WidgetGrid` with spans, edit mode, add-card picker over a typed card catalog; state through `persisted`/ViewStore-like port. Largest unbuilt Accordee structure; the owner rated it low priority.
6. Capability port for permissions UI (`definePermissions`, `can`), consumed by nav, commands, actions.
7. Auth layout (`AuthLayout` split with showcase slot, `SignInForm` using FormField + OneTimeCode + PasswordInput, all of which exist) and an account switcher in `Account`.
8. Table cell kinds: `c.progress`, `c.avatars`, `c.chips` (icon chips), with filter and footer support.
9. Notification-style list parts: `ActionRow` / inbox feed row (leading icon, entity chip, unread dot, trailing actions), reused by sessions, keys, trash, audit.
10. Human chat thread part (day separators, hover action toolbar, reactions, thread aside) promoted from docs/recipes/chat-thread*.md to a block, since the Composer, SplitPage and PageAside it needs ship.

## Where basalt's composition model looks too rigid

- Closed unions where Accordee varies per module: `TableLayout` (src/table/contract.ts:94), `KindName` (src/table/core/kinds.tsx:314-340), `OverlaySpec.as` (dialog or sheet) (page/define-overlays.ts:15). Accordee offers up to eight layouts of one record set and each module chooses a subset. Fix: registries with built-ins, not unions.
- One palette, replaced wholesale: while an AppShell is mounted BasaltProvider mounts no Spotlight (command-palette.tsx:43-47). Extension has to be a prop of the one palette.
- Two overlay systems that do not meet: `defineOverlays` (modal-ish dialog/sheet stack, typed payloads) and `Peek` (URL, non-modal, three presentations). A record opened from a command or a link in a dialog cannot use the typed registry and also get the peek presentation. Accordee's single "record surface" is both. Consider `OverlaySpec.as: 'record'` delegating to Peek.
- Static nav and a closed shell slot set (`GlobalAction`, `SidebarBlock`, `SettingsConfig` with one mode): fine for apps, rigid for per-user or role-dependent chrome.
- Region claims read element props (shell/parts/grid.tsx:441-470 `readAsideClaim` reads `node.props`), so a wrapped PageAside is not claimed; the dev assertion helps (page/core/claims.ts) but wrapping stays a trap for agents.
- A saved view stores `display` only; Accordee's "Overview Cards" row shows a view can own a record page's card set. Basalt has no seam to attach view-scoped non-table state.

## What is sound (verified in code)

- Surface model, view row and saved-view tabs: `frame`, `PageBar` view row fed by one hook, `ViewStore` port with counts and sharing; Accordee needed a 16-page refactor to get here.
- State ownership is explicit and addressable: filters, tab, folder, compose kind, schedule view/day, flow panel are URL fields (RecordPage.tsx:58-66, Mailbox.tsx:72-80, schedule.tsx props, ref/flow.tsx); display state stays on the device or in a view; Accordee keeps most in localStorage and has no URL for pop-ups.
- Record surface: one anatomy, three presentations, remembered per kind, `?peek=` addressable, prev/next, dock, favourite (page/peek.tsx:34-97). Ahead of Accordee.
- Typed registries that fail at define time: defineNav, defineCommands (chord conflicts throw), defineOverlays (key and payload), defineControls/field.
- Engine: virtualised, server-mode, nested-row, keyboard-driven DataTable on a closed TanStack feature set; resize, reorder, group, aggregates, row height all ship despite the stale header.
- Block tier works as designed: 7 blocks, `basalt-ui add`, manifest ledger, three-way `sync`; blocks import only published specifiers (block.json:3-12). The bench claim "no registry" resolved as a block tier, tested (src/cli/add/blocks.test.ts).
- Forms and settings kit: FormField/Row/Section, Action/Confirm/Group rows, floating unsaved bar, row deep-link flash, WizardDialog with review.
- Agent layer: five shipped rule files with lint ids and type anchors, three skills, per-export docs with use-when/never-when, template AGENTS block; skill routes an agent to a block per archetype (agent/skills/basalt-design/SKILL.md:7).
