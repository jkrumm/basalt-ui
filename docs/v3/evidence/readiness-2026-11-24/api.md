# basalt-ui v3 readiness: public API and type surface

Scope: `packages/basalt-ui/package.json` (exports, peers, files), `packages/basalt-ui/AGENTS.md`, `MAINTAINING.md`, every entry under `packages/basalt-ui/src/*/index.ts`, deep samples of shell, router/nav, table, charts, cards, page, form, register. Read-only: no build, no test, no tsc. The import-graph walk (static value imports, type-only imports skipped) was run over `src/**` in the REPL; type claims below that would need `tsc` to confirm are marked "likely".

Baseline: `v2.29.0` is the last npm release; master is 2771 commits past it, so no published consumer has seen any v3 name. Every v3-era alias, wildcard path and type name is free to change now and costs a break after 3.0.

## Verdict

The engine-level types are strong. Examples are the nav inference machinery, the table contract, the opaque `NavTarget` and the `Slot` register. The weak part is the _published_ surface around them. The shell does not consume the typed nav it is fed. The types the shipped rules name are mostly not importable. Two wildcard entries freeze about 100 internal and test modules as API. And 23 "removed in the next minor" aliases would ship in a major that nobody has installed yet. All of it is cheap to fix now, and each fix is a break after 3.0.

## Sound (keep as is)

- **Nav inference** (router/nav/types.ts:76-187, define-nav.ts:54-60): recursive `Exact` closes the metadata-typo hole at every depth. `RegisteredOr` turns a missing `Register` into an unsatisfiable string literal that names the fix. The id union is pinned by type-guard tests. Wiring the shell to it is what's missing (P1 above).
- **`navTarget`** (router/nav-target.ts:20-43): validated by `ValidateLinkOptions<RegisteredRouter>`, opaque, with its options in a `WeakMap`, so router-free subpaths take `string | NavTarget` without importing the router.
- **The table contract** (table/contract.ts): `Mode` makes client vs server rowCount vs cursor exclusive through `never` keys (lines 182-198). The `focus` / `focusItems` / `focusSeries` and `virtual` / `height` unions are exclusive. `TableEscape` is structural, so no TanStack type crosses the `.d.ts`. `col<T>()` keys are `KeysOf<T, V>`.
- **The `Slot` mechanism** (register.ts:57-61): the indexed-access form avoids the commands/overlays cycle. The `{}` fallback keeps keys `never`, not `string`.
- **Layering by import graph:** `tokens` imports no package. `charts` imports only `@tanstack/charts`, `d3-scale`, react, cva and clsx. The root barrel imports only react. `controls` and `cards` import no router or query. Heavy peers (shiki, pele, atlaskit, axe) are dynamic `import()` only.
- **Named exports only:** the single default export is oxlint's plugin contract, waived with a reason (lint/index.ts:42-43).
- **`any` stays in 3 justified spots,** each waived with a reason: `FilterSpec<any>` for heterogeneous spec lists, and the `F` default of `useDataTable`. Casts in public paths are confined to `withRevalidation` (form/hook.ts:27-32), and that keeps TanStack's own signature.
- **The `Tone` union** is one 6-member type, reused across badge, alert, status, meter, num and progress. `onValueChange` is consistent across primitives except DatePicker. `| undefined` optional discipline holds on frame props.
- There is no TODO, FIXME or HACK in shipped src.
