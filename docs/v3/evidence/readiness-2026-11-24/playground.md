# Playground readiness: apps/playground as the 3.0 showcase

Read-only audit, 2026-11-24, master at 2fed04240. Every number below was counted from the tree; nothing was built or run.

## Verdict

The pages built on shipped parts are sound: 7 ref pages from `blocks/`, 14 kit pages and 6 form pages pass the app lint preset with 2 `oxlint-disable` lines in all 75 route files (7 in all of src, each with a reason), and none uses a hand-built toolbar, an `any` or a legacy name. What an owner sees is not that: the nav is 165 entries (60 hand-written plus 105 scenarios) in 12 sections, 7 of them trial evidence, and the landing page is a link dump. The playground also still runs on the 2.x preset (`basaltViteConfig`, no manifest, 14 hand-written `@source` lines), so `basalt()` and the manifest gates run on no real page. The clean-up is mostly deletion and re-curation, not rebuilding: about 20 route files and 5.7k lines of superseded cycle builds go, the scenarios leave the nav, and one or two exemplar pages (table, charts) are repaired.

- Navigation is one typed `defineNav` declaration over TanStack `linkOptions`, projected onto rail, tab bar, breadcrumb and title (nav-model.tsx:1-14, __root.tsx:1-10); the whole shell wiring in __root.tsx is the pattern a consumer should copy.
- Waiver discipline is excellent: 7 `oxlint-disable` in 440+ files, every one with a reason; `--report-unused-disable-directives` and `--deny-warnings` are on in the playground lint (package.json:17), and the token and stylelint scanners run over src (check-playground-lint.ts:1-20).
- Cycle evidence is isolated: waivers live beside the build (cycle/*/known.ts) and the matrix fails a waiver that no longer matches, so evidence cannot rot silently (known.ts:12-18,101).
- The matrix reads the route directory and scenario list, so deleting a page needs no edit of the harness (routes.ts:1-5). Deletion is cheap.
- Page code uses the data layer the way a consumer would: `defineControls` URL state, `useDataTable`, `shotState`, `createQueryClient`, `routerDefaults` (main.tsx:1-54); no `any`, no `@ts-ignore`, one `as CSSProperties` family for custom properties.
- Peek, record panels, view row, board and mailbox are exercised on real pages (kit/peek.tsx, ref/notes, ref/mail, kit/board).
