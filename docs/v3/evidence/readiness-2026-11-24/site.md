# basalt-ui v3 readiness: content pages (Astro, docs, guides, articles)

Read-only audit, 2026-11-24, master @ 2fed04240. No build, test or server was run: every "never exercised" and "does not check" claim comes from reading code, CI files and tests. Items I could not confirm without a build are marked "not verified".

## Verdict

The static half is sound and measured: no-JS parts, one token set, a CI-held byte and LCP budget, and a 90-part island matrix. The path from a fresh Astro project to that result is not first-class: nothing proves it from the tarball, `init --profile site` only prints to-dos, `astro` is no declared peer, the island guard is a written decision, and the shipped agent layer teaches apps only. Content page types stop at landing blocks plus a bare article frame; Starlight is the docs engine by practice, not by stated decision.

## What is sound

- Static half works as a no-JS contract: parts are provider-, hook- and router-free (`packages/basalt-ui/src/static/index.ts:1-6`), and a 466-line test calls each outside a React render (`packages/basalt-ui/src/static/static.test.tsx`).
- Cost is measured, not claimed: CI `site` job holds zero module JS on static pages, React runtime, island, CSS, LCP and CLS to `apps/marketing/site-budgets.json` (`.github/workflows/ci.yml:114-148`); the matrix measures 90 parts in several modes (76 static-clean) and gates byte ceilings (`ci.yml:283-306`). The MDX cost table is tested against the matrix (`packages/basalt-ui/scripts/mdx-island-cost.test.ts`).
- `basaltAstro()` resolves the site's own Astro and Tailwind plugin from the project root, so no duplicate copies (`packages/basalt-ui/src/astro/index.ts:67-70`), and needs no `astro` install to import (pack-test smoke, `pack-test.sh:231-236`).
- The hydration ladder, one-provider-per-island and prefetch rules are written and justified (`packages/basalt-ui/docs/astro.md:101-125`); the MDX tags choose a directive by prop (`packages/basalt-ui/src/astro/mdx/Chart.astro:17-25`).
- Direction discipline is real in CSS: `logical-properties=error` in the site preset (`configs/oxlint-site.json:169`), `padding-inline-start`/`margin-block-start` in `prose.css`, `rtl:-scale-x-100` on chevrons, every visible string a prop (`packages/basalt-ui/src/static/article-layout.tsx:38`).
- Guards that already cover site roots: doctor maps `static`/`astro` to the `site` floor (`install.ts:34`), CI runs `sync` + `git diff --exit-code` + `doctor` on marketing (`ci.yml:134-136`), `check-tokens` scans `.astro`/`.mdx` (`check-tokens.ts:13`).
- One token set serves both: `static.css` imports the same `tokens.css`, and `starlight.css` is pure `var(--basalt-*)` (`packages/basalt-ui/src/css/templates/starlight.css:1-40`).

## Shortest list to make docs, guides and articles on Astro a first-class, tested path

1. Tarball site test in pack-test (fresh Astro project, `init --profile site`, `astro build`, zero-JS assertion, one island). Closes P1 #1.
2. Declare `astro` and `@astrojs/react` as optional peers; add them to `RUNTIME_PEERS.site`; doctor checks `basaltAstro()` in `astro.config`. Closes P1 #2.
3. `init --profile site` writes the layout, the config line and the island `@source` sheet (or `basaltAstro({ islands })`).
4. Ship the part-interaction table; build-time island check in `basaltAstro()`; doctor profile map from the same table.
5. Site agent set: `basalt-site` rule and skill, per-profile sync set, strip off-at-site lint tags; seed an `.astro` offender in the lint tests.
6. Page-type recipes made real: `SiteHead.astro`, `SiteNav`, guides collection with `[...slug].astro`, blog list, changelog, Shiki dual-theme recipe and CSS; name Starlight as the docs engine and fix MAINTAINING.md:346.
7. Direction and locale: RTL tab keys, `fonts` option shape, `locale`/messages on the MDX island tags, export `siteScript`.
8. Replace the exact peer pins with tested ranges; commit the matrix summary only.

Order: 1 and 2 first (they decide what freezes), then 5 (cheap, shapes every agent run), then 3, 4, 6, 7, 8.
