# Self-audit: the agent layer (rules, skills, reviewer, templates, CLI init/sync/doctor/shot, guards)

Scope: `packages/basalt-ui/agent/**`, `src/cli/**`, `src/commands/**`, `src/guard/**`, `configs/oxlint-*`, `.claude/{rules,skills,agents}`, `docs/waves/design-parity/**`, `docs/waves/argo-friction.md`. Date 2026-11-09, basalt-ui 2.29.0. Paths are relative to `packages/basalt-ui/` unless they start with `docs/`, `.claude/` or `apps/`. **[F]** observed, **[J]** judgement.

## 0. Verdict

1. **[J]** The agent layer is the product's second half, and about 85% of what makes it work is Mantine-free: the _method_ (concept, catalogue, encoding law, states, anti-defaults, reviewer rubric, shot harness, measured detector), the _enforcement architecture_ (every rule bullet ends in a tag, generated coverage headers, grace ladder, budgets, drift tests) and the _delivery model_ (managed vs seed, manifest). Only the build laws (`basalt-mantine.md`, half of `basalt-tokens.md`, `basalt-controls.md` selectors) and the setup skill are Mantine-bound.
2. **[F]** Two independent consumers that deliberately left Mantine (epos teamchat, factory console) took basalt's **tokens, fonts and design principles** and nothing of the agent layer: epos copied 15 principles into its own `ui/DESIGN.md:17-35` citing basalt files; the console runs the _method_ (`apps/console/DESIGN.md` "How a screen is built") while stating "its build laws do not [apply]" and hand-rolled one raw-colour test (`apps/console/test/no-raw-colour.test.ts`). Neither used `check-theme --tokens-only` (console `package.json` has no `basalt` key). The portable value is principles + method + tokens; the unported value is enforcement. v3 must make enforcement portable to Tailwind class strings or it will be re-hand-rolled per app.
3. **[F]** What measurably raised agent output (trial series v2→v7, same task): fixing basalt-owned component defects found by each trial, plus a catalogue/anti-defaults skill that removed the repeated app defects and every "fallback to a default" encoding. What did not: app copy quality (restated figures) and more rounds (>3 untested; row 229 shows non-convergence).
4. **[F]** The deterministic `shot detect` scored **100 with 0 findings on every trial board** while the reviewer found 17-19 defects per board. **[J]** It is a library-regression floor, not an app-quality discriminator.
5. **[F]** The weak link is skill _activation_, not skill content: argo rows 135, 223, 224 (session at monorepo root never sees nested skills; orchestrator never loaded `/basalt-design` at concept stage; implementer subagent skipped the reviewer silently). Rules load by `paths:`; skills depend on a description matching.
6. **[J]** Slimmest v3: 5 rule files, 2 skills + 1 reviewer, one AST lint plugin (class-literal rules + the Router/Query/Chart boundary rules) plus a tiny CSS colour scan, `tokens:css`, `shot`/`detect`, a thinner `init/sync/doctor`. Delete the regex text guard, the 1.x to 2.x upgrade engine, the legacy-hash ledger path, `check-theme --tokens-only`, `audit-allows` as a command.
