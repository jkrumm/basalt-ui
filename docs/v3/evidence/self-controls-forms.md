## 0. Headline

Fact: 85% of the control tier's lines sit in files that import `@mantine/core` (3928 of 4644), but the three things that make it valuable are Mantine-free already: `FieldHandle` lanes (`src/state`), the surface context (`controls/filter-context.tsx`), and the 9 lint rules. The rewrite is a re-skin of ~14 files plus a re-decision on forms; the doctrine ports intact.
Fact: the form layer is the weakest area. `FormRow`'s disable-propagation is dead wiring and `FormSection`/`FormActions` are unreachable (section 5, items 1-3), `useFormDraft`/`useFormSubmit` were deleted at 2.0 for "no consumer" while shutterflow (1.40.3) uses `useFormSubmit`, `FormStateProvider`, `FormActions`, `FormSection` in 19 files (`shutterflow/apps/desktop/src/features/settings/sync/TargetForm.tsx:3-4`).
Judgement: v3 should drop `@mantine/form` + the `inputProps/fieldKey` idiom for TanStack Form on Base UI `Field`, merge `FormRow`/`PanelRow`/`SettingsRow` into one shadcn-`Field`-shaped row, and add the missing draft + submit lifecycle as one small headless module.

## 3. Global vs local controls, URL binding, drafts, validation

### Global vs local (fact)

- There is no "global control" type. Placement is law C1: three homes (page bar, section/widget header, form row), entered only through slot props (`actions filters tabs sync control`); `PageAside` body and `PanelRow` are the two subtree homes (`MAINTAINING.md:430-451`).
- "Global" = the store's lane, not the widget: a field with `{url: true}` is shareable and mirrored; `{url:false}` mirror-only (linewatch `compact`, argo's per-chart selects); `{url:false, persist:false}` memory. `scope: 'global' | 'page'` exists only on `SyncButton`.
- Judgement: "site-wide controls" (brief) are a missing concept. Today they are a store whose key is shared and fields are not on the URL (`createLocalStore`), read by pages via `useValues`. v3 should name it: `createGlobalStore` is `createLocalStore` + `search: store.linkSearch`-style propagation into links, so a global range filter in the shell header follows the user across routes without per-route `validateSearch`. Needs the state agent.
- Cards that "carry their own controls or bind to global ones": `ChartCard`/`StatCard` `actions` slot hosts a bound control (`ViewTabs` allowed, `bound-control-outside-home` reads the slot, `agent/rules/basalt-controls.md:34`). Binding to a global field = pass the same `FieldHandle`; no new API needed. `ChartCard` is outside the Mantine-free boundary and cannot mount `CtlSlot`, so it hand-writes the tier attribute (`CONTROLS-SPEC.md` §5). In v3 the tier is a CSS var, so this special case disappears.

### URL binding (fact, with the traps)

- Resolution URL ⊳ mirror ⊳ fallback; a deep link beats the mirror (`search-store.ts:6-14`). `use()` navigates only when the matched route owns the param, detected by key presence in `useSearch({strict:false})`; honest limit: two stores sharing a param name on overlapping routes read as one owner.
- Every store navigate passes `resetScroll: false`; writes can drop sibling params in the same navigate (`resets: ['page']`).
- Under SSR the first reader resolves exactly what the server did (`hydrationDone`, `isDehydrating` at `search-store.ts:113-120`; `window.$_TSR`). Never read the mirror in a server loader.
- A thunk fallback on a URL-lane field throws at definition (it would pin the computed value into the URL).
- `clear()` UNSETS (deletes mirror key / drops memory value) rather than writing the fallback; `Reset all` and `Clear` both use it (`filter-context.tsx:102-110`). Tested at `controls.router.test.tsx:166-250`.
- `search: store.linkSearch` by reference in nav, never a literal (`search-literal-link`, `use-search-from-literal`). These two rules are router rules, not Mantine rules: carry unchanged.
- Judgement: the range field's three-param shape exists to keep argo's deep links stable; for v3 greenfield, argo's rewrite is the only legacy. Keep `params` renaming, do not add new lanes.

### Validation (fact + judgement)

- Today: Standard Schema in `useBasaltForm` via `schemaResolver({sync:true})` (`create-form.ts:54`), throws at validate time for async schemas (audit finding 10). URL fields validate through the field codec (clamp, allowlist, `NUMERIC_RE`, ISO regex), not through a schema.
- Base UI `Form` + `Field.Root validate/validationMode` (`onSubmit` default, `onBlur`, `onChange`, `validationDebounceTime`) is native; `Form` is "not needed when using TanStack Form" (`handbook/forms.md:4477`).
- shadcn `FieldError` accepts `errors` arrays and Standard Schema issues from Zod/Valibot/ArkType (ui.shadcn.com/docs/components/base/field). shadcn docs document React Hook Form 7.91.0, TanStack Form 1.33.5 and Formisch; the old `<Form>` wrapper is gone from the registry and docs (research report, 2026-11-09).
- Judgement: choose TanStack Form (stable 1.33.5, `2.0.0-alpha.3` tagged `alpha`): same stack as Router/Query/Table/Charts, Standard Schema validators on `validators.onSubmit`, `revalidateLogic` gives submit-then-change. `docs/V2-SPEC.md:361` rejected it only because `@mantine/form` bound Mantine inputs natively; that reason is gone. Spike item: `form.Field` render-prop verbosity vs a thin `<Field of={form} name>` wrapper (audit finding 9).

### Drafts (fact: none exist in 2.x; judgement: three kinds)

1. Field drafts for store-bound controls: SearchFilter and NumberFilter keep a local draft committed on blur/Enter/debounce (`search-filter.tsx:141-200`, `number-filter.tsx:323`). Keep; unify as one hook.
2. Form drafts (local): the deleted `useFormDraft` (store key `basalt:form:<key>`, version, schema-validated restore once on mount, `clearDraft` on success, autosave 500ms debounced via `form.watch`, subscription set frozen at mount). Rebuild on `createPersistedState` + TanStack Form `form.store`/`Subscribe`.
3. Form drafts (server-synced, cross-device): argo's workout draft is the only real implementation (`argo/apps/dashboard/src/lib/queries/{draft-writer,workout-draft}.ts`, `apps/api/src/routes/workout-draft.ts`). Rules worth carrying: per-key debounced writes (900ms), one serialized chain so a DELETE never overtakes a PUT, flush on tab-hide/unmount, poll result is cached but adopted only when the form is "settled" (nothing focused, nothing pending, a human pause since last edit), last-write-wins per whole key never a merge, server stamps `updated_at`.

- Judgement: ship (2) in core; ship (3) as a documented adapter + skill pattern (it needs a server contract), not as an API with a transport.

## 4. (c) Mantine coupling, and what shadcn / Base UI / Tailwind 4 change

### Exact coupling (fact)

- 14 of 22 control files import `@mantine/core`; 1 imports `@mantine/hooks` (`search-filter.tsx:19`, `useDebouncedCallback`); `controls-dates` 1 file imports `@mantine/dates`; `forms` 3 files import `@mantine/form` (`create-form.ts:5`, `field.ts:18`; `form-state.tsx` only React).

- Mantine-free already: `filter-context.tsx`, `filter-set.tsx`, `select-filter.tsx` (delegates), `glyphs.tsx`, `control-name.ts`, `filter-base.ts`, `uncontrolled.ts`, all of `src/state`, `src/router-tanstack`.

### Order of work for a rewrite (judgement)

1. Port tests first, not code: items 4-11, 16-18 of section 5 as component tests that do not mention Mantine (they use `field` handles and roles), so they run against both stacks during the cutover.

## 7. Open questions (owner decisions)

1. Distribution: are controls shipped in the npm package (Base UI + Tailwind as peers) or as a shadcn custom registry the app copies? Decides lint provenance, the `peer-boundary` family and whether "take what you want" can still yield one look.
2. Form library: TanStack Form (recommended, same stack) vs React Hook Form (shadcn's default tab, 7.91.0). Spike result needed on `form.Field` verbosity before locking.
3. Typed `FilterSpec[]` vs JSX children for `FilterSet` (removes registry and double-mount, loses JSX composability).
4. Date picker: shadcn `Calendar` on `react-day-picker` 10.0.2 vs a custom range control built on Base UI primitives (no date primitive exists). Own the ISO/UTC conversion either way.
5. Server-synced drafts: ship an adapter or only teach the pattern.
