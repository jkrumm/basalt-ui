# basalt-ui self-audit: process, release and doctrine history (input to v3)

Scope: basalt-ui's own repo at master `6f1007a8`, npm latest 2.29.0 (`packages/basalt-ui/package.json:3`), 2026-11-09.
Paths are repo-root relative; `pkg/` = `packages/basalt-ui/`. **F** = observed fact (cited), **J** = my judgement.
Library facts re-verified today: semantic-release 25.0.9 source (`node_modules/semantic-release/lib/**`), npm 11.6.2 (local dry-run),
Tailwind docs v4.3, Base UI releases page (1.9.0 stable, 2026-10-09), oxc JS-plugin docs.

## 0. Headline

1. **The framework's value is already mostly Mantine-free.** 44% of source lines (31.5k of 72.0k) sit in directories with zero `@mantine` imports
   (tokens, charts, state, format, cli, guard, common, router-tanstack); only 70 of 345 source files import Mantine (F, section c). The v3
   rewrite is a UI-layer rewrite (shell, controls, dashboard, table, theme: ~40k lines, 54 CSS modules) on top of a carried-over spine.
2. **The enforcement spine earned its keep; the release/process doctrine did not scale.** Fleet waivers across 6 apps: 14 inline waivers plus 3 weatherorb config downgrades, argo 0
   (`docs/waves/maturation-v2/consumer-usage.md:18`). Meanwhile "no majors" turned a 25-day 2.x into 29 minors carrying ~2,300 lines of MIGRATING
   (`pkg/MIGRATING.md:1046-3346`) and left three consumers stranded on 1.x.
3. **After 2.0 the surface and the code grew, not shrank.** 2.0.0 deleted net -12.0k src lines and 395 -> 104 symbols; the next 29 minors
   added net +25.4k src and +31.0k test lines and 104 -> 124 symbols (git numstat v1.41.0..v2.0.0..v2.29.0). "Net-negative waves" (AGENTS.md
   doctrine) was never enforced by a gate; budgets were raised each wave (`pkg/scripts/check-budgets.ts:48-60`).
4. **Doctrine flip is small but has 9 homes** (section 7). The release gate is the hard part: semantic-release cannot maintain 2.x from a
   `2.x` range branch while master is still unreleased at 2.29.0 (normalize.js:36-45), and the factory only works on the default branch.
5. **Do first, before any v3 code lands:** release the 8 unreleased package commits as 2.29.1 (`git log v2.29.0..HEAD -- pkg`), and fix
   `publish.yml` to pass `--tag` (npm 11 rejects a prerelease without it; a bare publish of a lower 2.x after 3.x would retake `latest`).

Constraints discovered (F unless J):

- semantic-release 25.0.9: a config must have 1-3 _release_ branches (`lib/definitions/branches.js:19-21`), so maintenance + prerelease alone is invalid.
  A `N.x` maintenance branch is capped by master's releases: `max = lowest(first master version not in any maintenance branch, range upper)`
  (`lib/branches/normalize.js:36-45`). With master unreleased at 2.29.0, a new `2.x` branch accepts **no release** until master ships its first
  v3. Docs: "Only versions in range >=1.1.0 <1.5.0 can be published from 1.x" while master is at 1.5.0 (semantic-release workflow-configuration).
- A prerelease branch exists: `{name:'v3', prerelease:'next'}` releases `3.0.0-next.1` on a BREAKING commit (docs). **npm 11.6.2 refuses
  `npm publish` of a prerelease version without `--tag`** (local `--dry-run`: "You must specify a tag using --tag"), and a plain publish defaults to
  `latest`. Because publishing happens in `publish.yml` (not `@semantic-release/npm`), that file owns the tag.
- npm Trusted Publisher is bound to workflow filename `publish.yml` (memory `basalt-ui-npm-trusted-publisher`): keep one publish workflow, branch-agnostic.
- Factory: ships through origin default branch, reads `origin/main|master|main|master`, merged = reachable from the default ref
  (`software-factory/.claude/worktrees/factory-100-1/docs/design.md:767,943,1124`). A long-lived non-default integration branch is not a supported factory lane.
- release.sh hard-codes `BRANCH="master"` and the workflow names (`release.sh:86`); `release.yml` takes `--ref`.
