# Self-audit: shell, nav, page/aside regions, mobile transformation, router integration

Scope: `packages/basalt-ui/src/shell`, `src/router-tanstack`, `src/surfaces.ts`, `docs/ASIDE-SPEC.md`, plus the files they weld to (`provider/create-router.tsx`, `provider/route-transition.ts`, `commands/shell-bridge.ts`, `agent/rules/*`, `configs/oxlint-plugin.js`, layout tests). Date 2026-11-09, basalt-ui 2.29.x. All paths below are relative to `packages/basalt-ui/` unless they start with `docs/` or `apps/`. Fact and judgement are marked: **[F]** observed, **[J]** judgement.

## 0. Verdict in six lines

1. **[J]** This domain is the product. Roughly 60% of what is worth keeping is _algorithms, laws and tests with no Mantine in them_: the nav model + active resolution, `projectMobileNav`, aside docking, the claim/outlet/portal regions, the measured-height contract, the `Main`-is-the-scrollport contract. They port nearly verbatim.
2. **[F]** The Mantine-specific 40% is `AppShell` (it supplies five landmarks, the `--app-shell-*` variable contract, region offsets, the transition timing) and `Menu`/`Drawer`/`Popover`/`NavLink`/`Tooltip`/`ScrollArea`/`Collapse` inside sidebar and mobile bar. shadcn has **no equivalent of `AppShell`, `BasaltShell`, or the mobile tab bar**; its Sidebar block is a sidebar only. Both shadcn apps in the fleet hand-built their shell (section 3.3).
3. **[F]** Of 25 shell options on `BasaltShell`, argo uses 9 (`brand nav isActive badges globalActions sidebarBlocks settingsMenuItems settingsMenu storageKey`), rb 6, shutterflow uses `account` and `headerHeight`, obsidian uses `search` + `sidebarBlocks`. The audit `docs/waves/maturation-v2/shell.md` shell-04 ("consumer-less props") is **partly false today**: `account` (shutterflow), `search` (obsidian), `isActive` (argo, finances), `headerHeight` (shutterflow) have consumers.
4. **[J]** Slimmest v3: `defineNav` (kept), one `Shell` composed from a CSS grid with named regions (no AppShell), `PageBar` and `PageAside` as route-declared regions (kept), `projectMobileNav` (kept), shadcn `Sidebar` primitives NOT adopted wholesale (see 5.2).
5. **[F]** Biggest silent-loss risk: 5,864 shell test lines + 2,015 real-Chrome layout lines encode ~40 measured defects (section 4). They assert Mantine class names/vars in places; the _numbers_ must be re-pinned, not the selectors.
6. **[F]** Doctrine drift to fix on the way: `docs/CONTROLS-SPEC.md` C8 says the breadcrumb comes from `staticData.title`; the code derives it from the nav item label (`router-tanstack/use-nav.ts:121-148`). `StaticDataRouteOption` augments `title/icon/navSection` (`router-tanstack/index.ts:18-25`) and **nothing reads them** (grep over `src`, no hit outside the declaration). Dead surface.

## 3. (c) Mantine coupling, and what shadcn / Base UI / Tailwind 4 change

### 3.1 Exact degree of coupling [F]

- **Direct `@mantine/*` importers in shell (non-test):** 9 of 20 files (`index`, `app-brand`, `app-breadcrumbs`, `app-mobile-nav`, `app-sidebar`, `app-sidebar-account`, `nav-count-badge`, `sidebar-blocks`, `sidebar-search`), plus a comment-only hit in `nav-types.ts`. **Mantine-free by import:** `page-bar`, `page-aside`, `page-title`, `mobile-nav-model`, `sidebar-block-model`, `aside-docking`, `use-size-class`, `nav-glyph`, `account-types`, all of `router-tanstack`.
- **But page-bar/page-aside are indirectly coupled** through `CtlSlot`/`theme` (`page-bar.tsx:36`, `theme/ctl-theme.tsx`), `controls/*` (FilterPill, FilterSheet, SyncButton, BarActionRow), `FilterSetScope`, and CSS modules that read `--app-shell-*`.
- **Mantine primitives used:** `AppShell` (Header/Navbar/Main/Aside/Footer) + `rem` in `shell/index.tsx`; `Menu`, `Drawer`, `NavLink`, `ScrollArea`, `Stack`, `Text`, `UnstyledButton` in mobile nav (21 JSX hits); `Collapse`, `Popover`, `Tooltip`, `Menu`, `NavLink`, `ScrollArea` in sidebar (24 hits); `ActionIcon`, `Kbd`, `Badge`, `Skeleton`, `Progress`, `Anchor`, `Group`.
- **AppShell gives for free, which v3 must build:** the five semantic landmarks (`<header>/<nav>/<main>/<aside>/<footer>`, verified in Mantine's installed `AppShell*.mjs` `component:` values), the `--app-shell-{header,navbar,aside,footer}-{height,offset,width}` and `--app-shell-padding` variables with responsive resolution, region transitions, `collapsed.{mobile,desktop}`, and `[data-with-border]` seams painted in `--vx-divider` via the theme's `AppShell.extend({vars})` (`shell/index.tsx:524-527`).
- **How basalt fights Mantine today [F]:** `app-main.module.css` restates Mantine's four padding offsets as margins to make Main the scrollport and relies on the CSS `@layer mantine` losing to unlayered rules (`app-main.module.css:15-19`); `:root:root` overrides of `--app-shell-*` for landscape phones (`:186-215`); `.mantine-ActionIcon-root` selectors (`app-header.module.css:154`); `--ai-size-md` copy (`app-brand.module.css:31-34`); `rem()` + `--mantine-scale` multiplications. Obsidian's app-side override CSS (225 lines, 14 `!important`, `header.mantine-AppShell-header` selector, `consumer-obsidian.md:41,54,167`) is the same fight on the consumer side.
- **Hidden cross-module weld:** `defineNav` (a "headless" module) registers the Spotlight mount (`nav.ts:172`) and `provider/slots`; `useNav` imports `Link` and `shell/nav-types`; `shell/index.tsx` imports `controls/actions`, `commands/shell-bridge`, `state/persisted`. The layering claim in `router-tanstack/index.ts:1-6` ("No Mantine, no JSX") holds only for imports of Mantine.

## 4. (d) Hard-won invariants a rewrite would silently lose

Each is observed in code, tests or docs. "Pinned by" says what would catch the loss.

### 4.1 Layout and scrolling

1. **Main is the scrollport; the document never scrolls.** Margins (not padding) offset Main so it can be in normal flow; a `position: fixed` Main would create a stacking context and break scroll restoration (`app-main.module.css:1-20`). `data-scroll-restoration-id="basalt-main"` is read by TanStack Router scroll restoration (`shell/index.tsx:574-580`); `scrollRestoration: true` is a `createBasaltRouter` default (`provider/create-router.tsx:117`). Pinned by: `no-horizontal-overflow.layout.test.ts` reads `main.scrollWidth <= clientWidth` (hence `overflow-x: auto`, never hidden, `app-main.module.css` ~`:135`).
2. **Root is a column flex so margins cannot collapse through it.** Measured regression: document `scrollHeight` 892 vs 844 viewport, i.e. a phantom scroll of one header height (`app-main.module.css:20-35`). Pinned by: `shell-chrome.layout.test.ts` "everything under it starts there".
3. **`--basalt-main-content-h`** = viewport minus header, footer + safe-area, band + its 1px border (`var(--basalt-page-bar-h, -1px) + 1px` nets 0 when no band), minus 2x block padding. `height:100%` cannot do this (`app-main.module.css:111-123`). Needed because argo hand-computed it in 3 files (v2 audit shell-07).
4. **The 1px band border is outside the measured box** (`--basalt-page-bar-h` is the content box of an unconstrained element); the aside header's `+ 1px` in `min-height` exists because its own border sits inside an explicit `min-height` (`ASIDE-SPEC.md` §0 "header's height tracks"). Measured: seams 9px apart before the fix (`page-aside.layout.test.ts:210`).
5. **Landscape phone**: header/footer heights clamp to `9dvh`/`9.4dvh` at `max-height: 480px` below `sm`, floored at the row token + 1px (`app-main.module.css:186-215`); the floor is the _token_, not 45px, because density > 0 grows the row.
6. **Safe area**: the mobile `.bar` carries no `env(safe-area-inset-bottom)` because Mantine's footer already adds it; the real gap is `--app-shell-footer-offset`, closed by `.mainSafeArea` (`MAINTAINING.md:274-276`). In v3 this is inverted: we own the footer, so exactly ONE place adds the inset. Obsidian documents an iOS 26.x WebKit safe-area bug it works around (`consumer-obsidian.md:43`).
7. **Page gutter is responsive tokens (8 / 16 / 24), stepping at `sm` and `md`, not a spacing key** (13px at every width was the bug; `shell/index.tsx:384-405`). Pinned by `shell-chrome.layout.test.ts:353-377`.
8. **Header height is one token at every width** (law C14); `appShellHeaderMobileHeight` (97, two-row) was deleted. No header height is React state.
9. **`--basalt-page-bar-h`**: layout effect + callback ref, guarded `height > 0`, removed on unmount, first publish re-aims `location.hash` instantly (`page-bar.tsx:303-340`). Lost lessons: a RefObject measured `null` through a portal; a zero from ResizeObserver collapsed a sticky offset mid-navigation; a passive effect scrolled past the heading on cold `/page#anchor`.
10. **Aside leading edge is the REGION's seam**, painted only when claimed (a collapsed Mantine aside keeps its border-box and would draw a 1px ghost at the viewport edge, measured on `/dashboard`, `shell/index.tsx:519-523`).
11. **Unclaimed aside = 0 width, `collapsed.desktop`**, so an empty home costs nothing (C14); open aside docks only if `expanded` AND `navbar + aside + 720 <= viewport` (`aside-docking.ts:14-45`), else it reserves a 36px rail and overlays.
12. **Nav scroll region stops on a whole row, not through one** (mask + end-stop, `app-sidebar.module.css:156`, `shell-chrome.layout.test.ts:550`); first nav row has the same top offset expanded and collapsed (`:677`); rail does not widen section gaps (`:711`).
13. **Collapsed-rail badges**: the right section is `display:none` in the rail, so a badge became invisible (friction rows 10 and 17); fixed by `railDot`/`data-basalt-rail-dot`, extended to non-primary groups. A destination in a non-primary group has to appear in the rail.

### 4.2 Mobile bar

14. **Exclusivity by coverage**: an ITEM tab covers only itself; children stay reachable in More; a SECTION tab covers its pruned subtree. Before the fix two `aria-current="page"` tabs lit at once (measured, 5-slot bar) (`mobile-nav-model.ts:95-115`).
15. **Menu vs sheet is not the guarantee that keeps content above the fold; CSS `max-height: min(72dvh, 560px)` + inner scroll + `overscroll-behavior: contain` is.** `menuMax` 6 to 12 after a measured "big door on mobile" report (`mobile-nav-model.ts:36-55`). Floating menu runs `flip:false` because flipping upward escapes the viewport (`app-mobile-nav.tsx:51-56`). Pinned by `mobile-nav.layout.test.ts:190,294,434,490`.
16. **Active retap order**: attempt the scroll first, suppress navigation only if something moved; disabled guard on ALL row builders because `data-disabled` is a styling hook only, and CSS `pointer-events:none` was removed (a swallowed tap with no press state reads as broken) (`app-mobile-nav.tsx:340-368`).
17. **Focus race**: closing the More menu (`returnFocus`) and opening the nested Drawer (focus trap) in one handler leaves focus on the bar; fixed with one `requestAnimationFrame` (`app-mobile-nav.tsx:391-399`). A Base UI rewrite changes the primitive but not the race.
18. Touch targets hold 44/44/48 floors at density -3/0/+3 (`mobile-nav.layout.test.ts:366`); active pill is a neutral ink pill behind the ICON only, never the identity accent, identical with and without icon at every density (`:535,574`).
19. **Last content pixel sits above the bar** when scrolled to the end (`:329`); a sheet's row insets are symmetric and the scrollbar gutter never overlaps a row (`:611`, measured 18 left / 30 right before).

### 4.3 Regions and claims

20. **`PageAside` mounts its children exactly once at each width.** Measured 2 mounts for one sheet because `PageBar` publishes its row-2 claim from a layout effect, so the first pass rendered the in-flow form then dropped it. Fix: wait one commit when inside a shell (`page-aside.tsx:333-345,426-429`). Pinned by `page-aside.layout.test.ts:146`.
21. A claim's cleanup must be identity-checked (`claimPanel` releases only its own claim); a late `publishFolded` from a released aside must not resurrect its fold; the Escape baseline advances to each acted signal or a viewport resize crossing `sm` re-folds an aside the user reopened (`page-aside.tsx:77-115,~360-380`; `page-bar.tsx:122-125`).
22. The aside `title` is both visible header and `aria-label`; a missing one ships an unnamed landmark, so it is `assertRequiredProps`-enforced (`page-aside.tsx` F-ERR-1 comment).
23. **One kebab per header**: `usePageKebabClaimed` makes the shell's own kebab render only when no `PageBar` holds one (`shell/index.tsx:626-690`).
24. Wrapping `<Outlet/>` in React `<ViewTransition>` is inert and fights the router's `defaultViewTransition`; the lint `route-view-transition` encodes this (`surfaces.ts:289-291`).

### 4.4 Router integration

25. **Anchor identity**: a new anchor function per resolve is a new component type, remounts every `<a>`, loses focus on the link just clicked. WeakMap per config, keyed by override mode (`use-nav.ts:79-102`). Hence "define `nav` at module scope".
26. **`useMatchRoute` is `useCallback(fn,[router])`, stable**; the change signal is `useRouterState(s => s.location.href)`, a deliberately unread memo dep (`use-nav.ts:158-163,257-260`). Easy to "clean up" into a stale-active bug.
27. `Link` spreads its own `aria-current` last, so `activeOptions:{exact:true, includeSearch:true}` makes basalt the only authority on active (`use-nav.ts:90-94`).
28. **Search-param navigations**: every store write uses `navigate({to:'.', search, replace, resetScroll:false})` and reports a rejected navigate (`search-store.ts:135-150`); a write from outside the owning route persists only (param-presence detection, `search-store.ts:11-24`); `resets:['page']` drops page in the same navigate so Back restores both.
29. **SSR**: until the first reader commits, the client must resolve exactly what the server did (`window.$_TSR` check, `search-store.ts:113-121`); `size class` uses `sizeClassHint`, server snapshot is `'compact'` by default (`use-size-class.ts`); `roomToDockServerFallback` avoids folding a default-open aside for one commit (`aside-docking.ts:34-37`).
30. **`defineNav` needs `Register { router }`**; without it `RegisteredRouter` is `AnyRouter`, every `to` widens to string, and the definition validates nothing, so the parameter becomes an unsatisfiable literal whose text is the fix (`nav.ts:175-181`).
31. `nav-types.ts` is TYPE-ONLY by contract so `dist/router-tanstack` gains no edge into `shell/`; `check-dist-layering.mjs` enforces it (`nav-types.ts:1-6`, `docs/FRAMEWORK-FREE.md`).

## 5. (e) The slimmest v3 shape of this domain

### 5.1 How controls bind to the shell and the router [F]

- **Home model (law C1):** a control lives in one of three homes: a `PageBar` slot (`actions filters filtersEnd tabs sync`), a header slot on `Section`/`WidgetHeader`/`ChartCard`/`StatCard`/`BasaltDataTable`, or a form row. A fourth _region_ (the aside) hosts the first and third.
- **State binding (C2/C3):** a filter or tab takes `field={store.field.x}` only; `value`/`onChange`/`size` do not exist as props. A `FieldHandle` is created by `createSearchStore` (URL > localStorage > fallback) or `createLocalStore` (no router).
- **Router binding:** the field's `use()` setter calls `useNavigate()` with `{to:'.', search, replace, resetScroll:false}` and mirrors to localStorage (`search-store.ts:135-150,361-450`). `store.validateSearch` is passed to the route; `store.linkSearch` is passed _by reference_ to `navTarget`/`defineNav` links (rules `search-literal-link`, `use-search-from-literal`).
- **Shell binding:** `FilterSet` provides a `FilterSurface` context (`pill` | `sheet` | `panel`; `controls/filter-context.tsx:50-61`) so the same bound control renders as a pill in the bar, a 44px row in the mobile `Filters (n)` sheet, and an inspector row in the aside. The home sets the size tier (`CtlSlot`, law C5). `FilterSet` reports `useFilterRegistration`/`useFilterCensus` so the count pill and "reset" are derived.
- **Global vs local:** global controls are `globalActions` data on the shell (`SyncButton scope="global"`, `ThemeToggle`, notification bell); page-local controls are `PageBar`. Both fold into the same single kebab on mobile via the claim. Imperative globals: `toggleSidebar`, `setColorScheme` via `commands/shell-bridge.ts`.
- [J] This binding is the right shape and is the least Mantine-dependent part of the controls story; `controls/*` is 9,514 lines, owned by another audit. Everything in this section survives if v3 keeps `FieldHandle`, the three surfaces, and the typed slot budgets.

## 6. Open questions that are real owner decisions

1. **Adopt shadcn `Sidebar` primitives or own the rail?** shadcn's Sidebar is built around an offcanvas mobile Sheet (`useSidebar().openMobile`) which contradicts law "no mobile sidebar, tab bar is the nav". Owning the rail costs ~700 lines; adopting means disabling its mobile path and keeping only its desktop `icon` collapse. Tendency: own it, copy the sub-component vocabulary so agents recognise it from shadcn training data.
2. **Collapse persistence medium**: localStorage with `isSet` (today, flashes on SSR) versus a cookie read server-side (SSR must be allowed, brief). Not decided by anything in the repo.
3. **Do `PageBar`/`PageAside` stay React-portal claims, or become route-declared (TanStack `staticData`/route context read by the shell)?** Portals work and are tested; route-declared chrome would remove the layout-effect/one-commit-wait class of bugs (section 4 items 9, 20) but moves slot content out of the page component, which breaks the "page owns its filters and their stores" locality. Tendency: keep portals.
