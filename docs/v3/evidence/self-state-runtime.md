# Self audit: state, provider, query client, telemetry, dev dock, vite preset

Scope: `packages/basalt-ui/src/{state/,state.ts,provider/,query-client.ts,unwrap.ts,telemetry.ts,dev-dock.tsx,vite*.ts}` plus
`router-tanstack/search-store*.ts` (the `./state` barrel re-exports `createSearchStore` from there, `state.ts:25`). All paths below
are relative to `packages/basalt-ui/src/` unless stated. Observed fact is marked (F), my judgement (J). Date 2026-11-09, basalt-ui
2.29.0 era (`docs/STATUS.md`).

## 0. Headline

(F) About 80% of this domain by lines is UI-library independent. 4 444 of 5 514 non-test lines import nothing from `@mantine/*`;
the coupled remainder is `provider/index.tsx` (574), `provider/lab-theme.ts` (175), `dev-dock.tsx` (149), the modals/spotlight
mounts (66+33+73) plus one _semantic_ coupling that no import scan sees: the Mantine colour-scheme key and attribute baked into
`vite-boot.ts:27,30,33`, `tokens/core.ts:899`, `vite.ts` docs and `cli/shot/capture.ts:1026`.
(J) v3 keeps `state`, the router/query wiring, telemetry, `basaltRouterOptions`, `route-transition` and the PWA/head half of the
vite preset nearly verbatim. It deletes the runtime palette injection, `lab-theme`, the slot/modals-wait machinery and the
`theme.other.basalt*` stash, and it needs ONE new small module (theme/colour scheme) to replace what `MantineProvider` did silently.
