# Self audit: table, virtual lists, data composites (v3 input)

Scope: `packages/basalt-ui/src/{table,dashboard,common}` at master 6f1007a8 (basalt-ui 2.x, `@tanstack/react-table` 9.2.8 pinned, react-virtual 3.14.20 installed). Paths below are relative to `packages/basalt-ui/` unless they start with `docs/`, `tests/` or `/Users`. Facts are cited file:line; "Judgement:" marks opinion. Consumer evidence read from sibling repos (read-only). `~/IuRoot` epos code is described as pattern only.

## 0. Verdict in five lines

1. The table is not weak in features-per-prop; it is weak in **shape**: one 2232-line Mantine-bound component (`src/table/data-table.tsx`), uncontrolled `initial*` state, no virtualization, one pager, two filter kinds, and a phone story built from three unrelated JS mechanisms.
2. "Non-responsive" has a precise cause: the default phone behaviour is a **JS-measured column fold + auto-pin** (`data-table-fold.tsx:177-335`), not a designed mobile layout. Cards exist only if the consumer writes `renderCard` (opt-in, 8 of argo's 13 tables), and the card mode drops sorting, selection and row actions (`data-table.tsx:1974-1988`, 807-811).
3. "Immature": no row virtualization (10k rows: 1.48 s first render, 2.1 s per sort; `docs/waves/evidence/w6/table-baseline-1.41.md:5,15-17`), no server-state port (every consumer hand-glues URL/store to `on*Change`), no summary row, no column visibility menu, no row expansion beyond the fold, no saved views.
4. Adoption is **taught, not enforced**: no oxlint rule or guard kind bans a hand-built `<Table>`/`<table>` (`configs/oxlint-basalt.json:4-26` has none; `configs/oxlint-plugin.js` only polices controls inside cells). Result: 6 of 10 consumer repos hand-roll tables.
5. The hard-won invariants are mostly in **tests and comments**, not in docs; a rewrite that starts from shadcn's Table recipe loses ~20 of them silently (section 5).

- `./data/virtual` (`BasaltVirtualList`) was **deleted in 2.0**: "no consumer; Virtual stays an internal dep of the transcript/table" (`docs/waves/v2-surface.md:693-696`). The "table" half of that sentence never happened: `grep virtual src/table` is empty.

## 2. Why "immature" and "non-responsive": exact causes

### 2.1 Non-responsive (observed)

| #   | Cause                                                                                                                                                                                                                                                                                                                           | Evidence                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |

## 7. Slimmest v3 shape of this domain

Judgement. Target: **net-negative lines** vs 3507+7133+1567 TS (12 207 lines) and 3633 CSS, by deleting measured fold/containment, slot API, Mantine pass-throughs, lazy virtual seam and unconsumed Board/zones.

```
table/
  data-table.tsx          ~600  shell: toolbar slot, scroller, head, body, foot, states (no logic beyond layout)
  use-data-table.ts       ~250  one hook: features (hidden), state port, server mode, selection, query branch -> table instance
  table-state.ts          ~150  TableState port + adapters (stores, router search, localStorage); controlled by default
  cell-kinds.tsx          ~350  kinds registry: entity status number money relative-time meter text + delta trend bar link person
  responsive.ts           ~120  priority -> container-query tiers (data-attrs), default card derivation
  parts: toolbar, pager, column-menu, bulk-bar, row-actions   (shadcn-style files, each exported)
list/ virtual-list.tsx    ~200  react-virtual as a plain dependency; EventList/Board/feeds reuse it
```

Design moves (each ties to a section 2 cause):

1. **Responsive by CSS tiers, not measurement.** `meta.priority` becomes `1 | 2 | 3`, mapped to Tailwind container variants on a `@container` table wrapper (`@max-md` hides tier 3 into the disclosure, `@max-sm` tier 2). SSR-stable, zero `ResizeObserver` for fold, deletes R1-R3 and about 800 lines. Keep the floor (identifier + one value) as a rule: priority 1 cannot be assigned to more than two columns (lint/type).
2. **Cards by default at the phone tier.** Default card = first `entity` column as title, `status` as badge, `relative-time` as meta, remaining kinds as label/value pairs, `rowActions` as kebab; `renderCard` overrides. Sorting becomes a sort `Select` in the toolbar below the card threshold, selection stays as a tick, so card mode loses nothing (R4, R5). Judgement: rendering both a table and a card DOM would trip `basalt/responsive-twin`; derive one DOM and let CSS reshape, or keep the single-body swap keyed on container width as today.
3. **One scrollport.** The table owns its horizontal scroller; vertical cap optional; sticky header sticks inside it only. Delete page-sticky, `stickyHeaderOffset`, measured containment, `.mantine-AppShell-main` selector (R6, R7). With virtualization a scrollport is mandatory anyway.
4. **Controlled state port, URL-first.** Every state slice is a `FieldHandle`-shaped value (like facets are today, `data-table.tsx:237-252`), so URL, localStorage, server-synced preference and plain `useState` all plug in; remount-by-key and effect-resets (M2) disappear. Saved "views" = a named preset of the whole slice.
5. **Server `mode`.** `mode="client"` or `mode={{ server: { rowCount } }}` flips sorting, filtering and pagination to manual together; the breach matrix (`BREACH_REMEDY`) shrinks to "rowCount missing", a type error.
6. **Virtualize.** `virtual` (or auto above a row threshold) windows the `<tbody>` with a spacer-row technique; measured against the 10k lane baseline (`table-baseline-1.41.md`) as an acceptance number: first render and sort under one frame budget per visible row count, not per total.
7. **Lint closes the gap.** `basalt/hand-rolled-table` (new) so linewatch/shutterflow/email-gateway-style tables cannot recur; `control-outside-home` stays; add `basalt/table-selection-needs-row-id` only if the type cannot express it.
8. **Dashboard slimming.** Delete `Board` unless the Kanban consumer is named in the plan; keep `Meter` bar/ring/segments, drop `zones` and forecast unless a consumer is named; fold `StatStrip` into `StatGroup`; export `QueryState`; keep `WidgetHeader`, `DeltaBadge`, `Section`, `BarList`, `EventList`.
9. **Port order.** Pure modules first (they are Mantine-free and tested): `planColumnFold` replaced, `foldOrder`, `dataQueryBranch`, `meter-model`, `event-list-model`, `query-state-like`; then the 216 table tests re-pointed at the new DOM; then the 7 layout suites at 390/360/320 and 1440.

## 8. Open decisions that only the owner can take

1. Fold fidelity: accept tiered container-query priority (SSR-stable, coarser) instead of the measured fold (exact, hydration-shifting)? This decides ~800 lines and every table's phone look.
2. Table as one prop-driven component (enforced look, today's model) versus shadcn-style copy-in parts (own and bend, weaker enforcement); recommended: one component built from exported parts, so both ends exist.
3. Board and Meter `zones`: name a consumer or delete (doctrine says delete).
