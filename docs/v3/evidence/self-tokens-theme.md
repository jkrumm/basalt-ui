# Evidence: basalt-ui own tokens, derive engine, theming (for the v3 rewrite)

Scope: `packages/basalt-ui/src/{tokens,theme,theme-lab}`, `src/styles.css`, `docs/DESIGN-CORE.md`, `docs/MANTINE-THEMING.md`. Paths below are relative to `packages/basalt-ui/src` unless they start with `docs/`, `scripts/`, `configs/`. Date 2026-11-09. "Fact" = read in code or run; "Judgement" = mine.
Third-party facts: Tailwind 4.3.4 + `@base-ui/react` 1.9.0 + `shadcn` 4.23.0 as installed in `software-factory/apps/console/node_modules`; docs via `agw web read` on tailwindcss.com and ui.shadcn.com/docs/theming (2026-11-09).

## 0. Bottom line

1. The token layer is already framework-free and already feeds a shadcn + Base UI + Tailwind 4 app: the factory console runs `basalt-ui tokens:css --only core` into a 45-line hand-written `@theme inline` bridge (console `src/styles/index.css:15-45`). The portable asset is `tokens/` (3,633 lines, 0 of 10 files import Mantine). The Mantine layer (`theme/index.ts` 1,699 lines, 41 `Component.extend`s, 6 of 9 theme files import `@mantine/core`) is DROP in full.
2. Of 220 emitted `--vx-*` names, only ~51 are scheme-dependent colour/shadow pairs; 121 are `--vx-space-*` and 99 of those are named for one basalt React component (`core.ts:474-668`). Under Tailwind 4 the 4px spacing scale, `h-8` control heights and the text ladder are utilities on `--spacing`/`--text-*`, so those 99 have no job.
3. Density and radius collapse from "rebuild a JS theme object + emit 108 vars" into two unitless CSS vars (`--vx-density`, `--vx-radius-level`) multiplied into `--spacing` and `--radius-*`. This removes the "dev slider gap" that cost `provider/lab-theme.ts` (175 lines) and `VX.legendGap/margin/dotR` frozen at load (`tokens/core.ts:149`). Zero consumers use the knobs (section 3.4), so this is also a product question.
4. The derive engine is the most valuable and least coupled thing here: contrast by construction (fill band, status solver, ink floor). KEEP. Its one gap is delivery: `tokens:css` takes no `--accent/--radius/--density` flags (`cli/tokens-css.ts:54-110`), so the one shadcn consumer with a different accent hand-edited hexes (employer app: navy accent, hand-pulled "one step"), which the doctrine forbids.
5. Stock shadcn conflicts with two basalt laws, observed in console copies: `dark:` colour branches in class strings (`button.tsx` outline/destructive; DESIGN-CORE principle 5 says never branch on scheme) and `text-base md:text-sm` inputs (14px at >=768px, under the iOS 16px floor; `styles.css:150-153` is unconditional). Lint and owned-copy edits must cover both.

### 3.2 Density and spacing

Fact: TW4 default `--spacing: 0.25rem` (`tailwindcss/theme.css:325`); every `p-*`, `gap-*`, `h-*`, `size-*` is `calc(var(--spacing) * N)` (`--spacing()` doc). Stock shadcn controls hard-code utilities: Button default `h-8 px-2.5`, xs `h-6`, sm `h-7`, lg `h-9`; Input `h-8` (console `ui/button.tsx:23-30`, `ui/input.tsx:11`). Those equal basalt's tiers 32 / 24 / 28 / 36 (`controlHeightCtl` 32, `Widget` 24, `Dense` 28; `palette.ts:283-345`).

Proposal: `@theme { --spacing: calc(0.25rem * var(--vx-density, 1)); }` (non-inline). One multiplier then moves every utility, control height and gap, including stock shadcn components, with no per-component keys. SPACE_FIXED (hairline, 2px track inset, 2px progress) comes free: borders and rings are not spacing utilities. Unverified in a spike: nested `calc` with `--spacing` as a `var()` expression (docs show the mechanism, no one has run it here).

Losses to design for (each is a current guard):

- Integer px. `scaleSpace` rounds so `1.5px` insets do not blur and the 2:1 pairs hold (`palette.ts:900-905, 1084-1090`). A float multiplier gives 2.8px units at -3. Options: round the multiplier to quarter steps, or `round()` on the unit (already used in `styles.css:432`), or accept sub-pixel. Not decided.
- Touch floors (mobile bar 49, rows 44, search trigger 24, `touchControlHeight`): `palette.ts:1092-1112`. v3: `min-h-(--vx-hit)` on coarse, which `pointer-coarse:` can carry.
- Rem-keyed heights: the Mantine `rem x --mantine-scale` form is a11y-critical (`MAINTAINING.md:188`). In TW everything is rem already.
- Row line-height additive law (`ROW_LINE_HEIGHT_STEP = 1/30`): becomes the `--text-sm--line-height` fixed at 20px; drop the knob.

### 3.3 Radius

Fact: basalt anchors card 10 / ctrl 6; derived floating 11, tight 5, fine 4; additive 1px per level, clamp 0 (`palette.ts:188-209`). shadcn: `--radius` base 0.625rem with x0.6/0.8/1.0/1.4/1.8/2.2/2.6 (ui.shadcn.com/docs/theming). Mapping by role as console does. Knob: `--vx-radius-card: max(0px, calc(10px + var(--vx-radius-level, 0) * 1px))`. Same law in CSS, tested by reading the emitted formula (replace `radius.test.ts` 144 lines with a 20-line property test).

### 3.4 Knob usage across the fleet (fact)

`createBasaltTheme(` in argo, weatherorb, image-gateway, shutterflow: bare, no options. One use of the removed `{ inputs: 'desktop' }` (shutterflow `apps/desktop/src/shell/theme.ts:10`; V2-SPEC:204 deleted that option). `density:`/`radius:`/`derive:` appear only in basalt-ui's own tests and layout fixture (`tests/layout/fixture/main.tsx:44`). `DeriveControls` imported by no consumer. So the four-knob surface, 764 lines of lab and ~2,000 lines of density/radius tests serve no shipped identity.

Judgement: keep the capability (the Athena case shows an accent that must differ per product, and the doctrine says never hand-edit) but cut it to what is used: seed accent + neutral + vibrancy at build time; `radius` and `density` as a 3-preset enum or small integer range; `lightLevel/darkLevel/accentBrightness` stay in the engine as defaults, exposed only via CLI flags.

### 3.5 Delivery path (fact + judgement)

`tokens:css` flags: scheme attribute/class, `--light-class`, `--default-scheme`, `--media-fallback`, `--only core|all`, `--check` (`cli/tokens-css.ts:54-110`). No derive, radius, density, fonts. `fonts:css` reads the stacks out of `styles.css` by regex (`tokens-css.ts:126-139`), which dies when `styles.css` loses its Mantine content. v3: one `basalt-ui tokens:css [--accent #hex --neutral --vibrancy --radius --density --tailwind]` emitting (1) `:root` + scheme blocks, (2) the generated `@theme inline`/`@theme` block, (3) shadcn aliases, with the same `--check`. The Vite plugin can call the same emitter so a Vite app needs no committed file. Config lives in the existing package.json `"basalt"` key.

## (d) Hard-won invariants a rewrite would silently lose

Each is recorded in code or docs; none is enforced by TypeScript alone.

1. Fill band is a law, not a taste: white label >=4.5:1 AND fill >=3:1 on both pages pins luminance 0.165 (`derive.ts:100-113`; `theme/contrast.test.ts:1-30`, 385 lines). Untuned, five families sat below the page floor and three needed black labels.
2. `ON_ACCENT_WHITE_CONTRAST_MIN = 3.0`, not 4.5: 4.5 flipped to dark ink at brightness +1/+2 for fills that still read (`derive.ts:128-135`). Docs say 4.5 (`MAINTAINING.md:209`, `palette.ts` FILL doc); measured default is ~4.9. Doc/code inconsistency to resolve, not both.
3. `clampFillTone` must check both pages: unclamped `accentBrightness +5` reaches ~1.9:1 on the light page (`derive.ts:101-170`).
4. Seed chroma is normalised `max(seed,40)`: a lighter seed of the same hue gives the same palette (`derive.ts:16-30, 405`).
5. Status solids walk tone 0.25 at a time until 4.5:1 on every text surface including `rowHover/rowSelected`; `excellent` is fill-only and guarded by `basalt/status-fill-as-text` (`status-text.ts:28-80`, D22, D51). Unreachable tone throws.
6. Axis/tick colour uses the derived opaque `faint`, not ink-at-60%, which measured 4.06:1 (`palette.ts:1217-1220`).
7. Divider is an ink alpha (9% light, 8% dark), not a hex: the old `#e5e5e5` flipped polarity at `lightLevel <= -3` and was grey on a slate page (`palette.ts:1355-1362`, `divider-contrast.test.ts`). Three line tokens, three roles, mapping one `--hairline` onto `--vx-surface-hairline` doubles the ring (`FRAMEWORK-FREE.md:260-290`).
8. Seam, ring, control edge: a surface gets exactly one of the three; closed rectangles are cards (`docs/archive/DESIGN-SPEC.md:490-511`, inversion #12). Card carries no `border`, the ring is inside `--vx-shadow-card`.
9. Raised shadow is asymmetric by design: dark = drop + inset rim; light = drop only. A light edge is a darkening and every placement failed (border look, then double bottom border). "Do NOT tidy" (`palette.ts:111-134`). A hover lift and a materialising `subtle` shadow were tried and reverted (`MAINTAINING.md:220-226`). Every shadow site must name where its box radius comes from (the ring is drawn by that box's corners): `scripts/check-theme-css.ts` via `tests/theme-css-gate.test.ts`.
10. Per-scheme selector specificity: `:root[attr]` 0-2-0 beats `html[attr]` 0-1-1 and bare `[attr]` ties with `:root` so source order decides; the legacy no-options output is byte-identical because consumers override under `html[data-mantine-color-scheme]` (`core.ts:845-875`, pinned by `tests/palette-css.test.ts`). The Mantine form of the same bug is documented at `MANTINE-THEMING.md:139-143` (binding in `variables` loses to the scheme selector).
11. Light-mode surface bindings and the reason for `--mantine-color-default-border: transparent` (depth is a shadow for every `variant="default"` control) are Mantine-only (`theme/index.ts:1496`); the principle survives: no control gets a border for depth.
12. Layer ordering is load-bearing: the plain Mantine CSS bundle is unlayered and beats every layered rule, silently killing the iOS floor; `doctor` flags it (`styles.css:5-17`). The TW4 analogue: basalt base rules in `@layer base`, never unlayered. Third-party CSS that is unlayered (maplibre) needs `:root:root` doubling (`styles.css:418-446`).
13. iOS floor: element-level `font-size: max(16px, ...) !important`; `!important` is the one allowed use because an inline `style` beats every layer (`styles.css:127-153`, `styles.floor.test.ts`). Console's shadcn `Input` is `text-base md:text-sm` (14px at >=768px): below the floor on iPad.
14. Pointer tier uses `pointer: coarse` (primary), never `any-pointer`; overlay is `::after` (Button owns `::before` for loading), `overflow: visible` except `[data-loading]`, `--vx-hit-gap` caps overlap (`styles.css:300-330`).
15. `@media`/`@container` cannot read custom properties, so literals duplicate the token and a test pins them (`tokens/breakpoint-literals.test.ts`, `core.ts:331-346`). TW4 generates the variants from `--breakpoint-*`/`--container-*`, but hand-written `@media` keeps the problem. Whether `theme()` or `@variant` can be used in `@media` was not confirmed by the Tailwind docs page I read (no section); check before relying.
16. Mobile inset ladder lives in the token sheet because inline styles cannot carry queries and a CSS module may be tree-shaken (`core.ts:921-965`).
17. Type ladder discipline: new rung must sit 1.06-1.17x from neighbours; rungs are role-named; `lg` = 16 is the iOS floor; a 20px rung was rejected (`core.ts:92-130`).
18. Hubot Sans: slashed zero, no `zero` feature -> digits from Nunito via `unicode-range` face; `font-stretch: 88%` is a knob for Hubot only (D36, `styles.css:36-68`; `FRAMEWORK-FREE.md` warns it condenses other faces). Numerals proportional + lining (D33); `tabular-nums` only table columns and axis ticks; `[data-numeric]` is the one tabular+mono contract (`styles.css:187`).
19. Mono data text drops ligatures (`<>` is two characters), `styles.css:100`.
20. Autofill: UA yellow cannot be overridden; paint an inset 100vmax shadow plus a 600000s transition; a themed input's own box-shadow outranks it (`styles.css:155-168`).
21. Focus ring = accent as ink, not fill (`styles.css:198-201`); slider fill is ink unless it encodes a status.
22. Density law details worth porting as tests if the knob survives: stack unit rebuilt from one rounded unit (4/8/12/16/24 exact multiples); `0.1 x +-3` replaced `0.06 x +-5` because 41 of 108 values were byte-identical at one notch; mobile bar floor is 49 not 48 (border eats 1px); `stickyHeaderClearance` is the one level-0 break; level 0 returns values verbatim, no `Math.round` (`palette.ts:900-935, 1054-1124`; `theme/density-relations.test.ts` 510 lines).
23. Known gap that is not lab-only: `VX.legendGap/margin/dotR` freeze at module load (`MAINTAINING.md:194`). In v3 chart margins read CSS vars or are constants; do not repeat the pattern.
24. Provider hot path: pinned default palette singleton + FIFO cache of 32 keyed by `JSON.stringify(config)`; `createBasaltTheme` must be called at module scope (`palette.ts:1371-1405`, `index.ts:1648-1655`). Moot if palette is build-time.
25. Dev gating: `process.env.NODE_ENV` literal read so production bundles drop dev checks (`core.ts:772`, `common/dev-gate.test.ts`, `MAINTAINING.md:137`).
26. Layering is CI-tested: `./tokens` must resolve and SSR with no Mantine installed (`scripts/check-dist-layering.mjs`, `scripts/pack-test.sh`). In v3 the same test should assert `./tokens` resolves with no React and no Tailwind.
27. Guard core must not import `tokens/palette` or `derive` (colour math on every Write/Edit hook): `guard/index.ts:1-6`, which is why `space-scale.ts` is a 13-line leaf. Keep the leaf discipline.
28. Unknown CSS vars fail silently (`var(--vx-accentFil)` resolves to nothing). camelCase aliases were removed in 2.x; `REMOVED_VX_NAMES` gives the migration text. `unknown-vx-token` left grace at 1.36.0 (`core.ts:741-749`).
29. `tokens-only` profile must be declared in package.json, never inferred; inference would silence 16 kinds in any repo that keeps Mantine in another workspace (`FRAMEWORK-FREE.md:355-362`).
30. Generated stylesheet contract: line 1 marker, line 2 provenance, formatter-stable `rgba()` args and alphas; reword either and basalt reports its own output (116 findings in rollhook) (`cli/tokens-css.ts:21-33`).
31. Provenance gap: `derive.ts:1-8` says every constant was "calibration-checked" against `apps/playground/src/poc/derive.ts`, and "do not re-tune without re-running that calibration". That file no longer exists (`ls apps/playground/src/poc` fails). The calibration evidence is gone; port the numbers with their tests, not their justification. Also 59 code comments cite `docs/DESIGN-SPEC.md`, which lives in `docs/archive/` now.
32. Radius history oscillated (8 -> 10 -> 7 -> 10): `docs/archive/DESIGN-SPEC.md:219` still says 7px. Values live only in derive/palette constants; any prose with a number rots.
33. Mantine's `autoContrast` handed white to lime at 2.24:1 and resolves scheme-blind (`theme/chrome-vars.ts:6-58`). The lesson (foreground is a paired token, measured) is the shadcn `*-foreground` convention; keep it as a test over a PAIRS table.
34. Stock shadcn has `dark:` colour branches (`ui/button.tsx` outline, destructive) that contradict principle 5 and compound tokens with `/NN`; `bg-input/30` on a pre-alpha token would be wrong.

## Open items and risks

- Name for accent-as-ink: shadcn `accent` is a hover surface; our `--vx-accent` is brand ink (links, active icon, primary series, ring). Candidates `--primary-ink`, `--link`, `--brand`. Needs one decision before the bridge is generated.
- Unverified (no spike run): `--spacing: calc(0.25rem * var(--vx-density))` in non-inline `@theme`; `round()` on the unit; whether TW4 lets a hand `@media` consume `--breakpoint-*` (docs page lacks it); `light-dark()` coverage. All four are 1-hour spikes.
- Console evidence is one app. Athena (employer app) rebuilt its own token names and Tailwind namespaces on top of the same derived values (`--canvas/--paper/--ink`, `--text-*: initial`, own `--spacing-*`), i.e. the second consumer did NOT use the `--vx-*` names. Pattern: both used `@theme inline` + `--*: initial`; neither used the knobs. Teaching one generated bridge should serve both.
- Doc drift found in this domain: MANTINE-THEMING.md radius/default-border (above); `core.ts` var counts; `derive.ts` header to a deleted file; 59 comments to an archived spec; fill-band "4.5:1" vs 3.0 floor.
