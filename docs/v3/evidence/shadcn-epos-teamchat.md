# Evidence: epos teamchat UI (shadcn base-nova + assistant-ui), held off basalt-ui

Audited 2026-11-09, read-only. Root: `~/IuRoot/epos-ai-teamchat-athena/ui/` (cited as `ui/`; repo-level docs as `repo/`). Employer code: patterns only. Measured with grep/wc on `ui/src` excluding `*.test.*`, `*.gen.ts`, `cn-tables.ts` unless stated. "Fact" = observed; "Judgement" = mine.

## 0. Headline

- **The census is zero**: not one `basalt-ui` import, dependency or lockfile entry (`ui/package.json:1-48`, `package-lock.json` has 0 hits for "basalt"). The app is a 17-day-old (first commit 2026-10-22), 61.6k-line non-test / 42.6k-line test SPA that took basalt as _values and a design reference_, then re-grew most of what a framework would have given it: store, router, query layer, settings sync, shell, data table, controls, chat look, guard tests.
- It is the best available proof of what v3 must own. Judgement: every hand-rolled module below is a framework-shaped hole; the ones with races (settings sync, SSE resume, URL params) are the expensive ones.
- Stated reason for not installing basalt (fact, `ui/DESIGN.md:39`; verified against `packages/basalt-ui/package.json` 2.29.0): 12 non-optional peers incl. `@mantine/core|hooks|modals|notifications|spotlight`, `@tanstack/react-query`, `@tanstack/react-router`. A shadcn v3 removes that blocker; the app's next move would then be to adopt v3, not keep forking values.

## 4. How shadcn really feels here

**Token layer (fact).** Two tiers, neither is shadcn's default. (1) `tokens.css`: plain CSS vars (`--canvas --paper --panel --wash --ink --ink-2 --ink-3 --rule --hairline --accent --good --warn --bad --cat0..7 --seq*`, spacing `--s1..s7`, `--shadow-0..3`, `--header-h`, `--sidebar-w`, `--measure-*`), shared with a non-React report template and kept in parity by test (`tokens.test.ts:40-70`). (2) `index.css:27-139` `@theme inline` wipes Tailwind defaults (`--color-*: initial`, `--text-*`, `--shadow-*`, `--breakpoint-*`) and re-exports tokens as utilities (`bg-paper text-ink-2 shadow-sm`); shadcn's semantic names are aliases (`background=paper, card/popover=panel, primary=accent, muted=wash, accent=hover, border=hairline, ring=focus, destructive=bad`). Pain recorded: shadcn `accent` (hover surface) vs the brand accent forced a repo-wide mechanical rename `accent -> primary` (`DESIGN.md:218`).

**`components/ui` (fact).** 39 files, 2,431 non-test lines. Base UI primitives actually used: avatar, button, checkbox, collapsible, context-menu, dialog, input, menu, popover, select, separator, tabs, toast, toggle(-group), tooltip, merge-props, use-render. Not installed from shadcn: sidebar, sheet, table, card, alert, form/field, switch, radio-group, progress, scroll-area (listed in `DESIGN.md:362` but absent), pagination, breadcrumb, calendar, bubble, message-scroller, trace. App-specific additions in `ui/`: `lozenge`, `edge-shade`, `term-hint`, `running-dot`, `athena-ink`, `dropdown-checkbox-item`, `dropdown-submenu`, `resizable` (react-resizable-panels 4.18.1), `avatar-photo`.
Customisation is class-level and uniform (fact): shadcn variants kept but repainted. `ui/button.tsx` variants `default` (accent fill, "one per view"), `outline` = raised neutral (panel fill + `shadow-ctrl`, no border), `secondary` = ink tint, `ghost`, `destructive`, `link`; sizes `xs 24 / sm 28 / default 32 / lg 36` + `icon-*`; comments cite the owner's rule "no blue buttons" (`button.tsx:11`). Churn per primitive is low (max 4 commits each: `term-hint`, `dropdown-menu`, `avatar`) -> once repainted, copy-in primitives were stable. Most churn went to app composites, not primitives.

**Composition (fact).** Base UI `render` prop instead of `asChild` (e.g. `<TooltipTrigger render={button}>`, `Messages.tsx:159`); popups mount a tick after click so tests must `await findByRole` (`repo/AGENTS.md:4075-4077`). `data-slot` is present in every shadcn file (cva/`data-slot="button"` etc.) but used by app code only ~10 times (`data-slot="athena-answer|answer-strip|chat-card|tickets-toolbar"`), i.e. as CSS/test hooks, not as a styling contract. Only 6 `cva(` call sites in 5 files (button, badge, tabs, input-group, toggle); 135 `data-[...]:` variants, 27 named `group/`/`peer/`. `cn` is the `cn` 0.5.0 package with AOT tables generated from `@theme` (`lib/cn.ts:1-9`, `make ui-cn-tables`, CI fails when stale) because tailwind-merge defaults read custom `text-prose`/`text-display` as colours and drop them. Judgement: this is a real shadcn+custom-scale papercut that v3 will hit the moment it ships non-default type/shadow scales.

**Recurring pains (fact unless marked).**

1. Silent Tailwind breakpoint reset: `md:` emits nothing, 227 arbitrary `[48rem]` variants as workaround, documented only in prose (`AGENTS.md:4249`). No guard.
2. Bundle cost of Base UI + floating-ui: first load 210.8 -> 330.8 kB gzip after adopting shadcn (`scripts/check-bundle.mjs:7-14`); recovered by lazy-chunking the chat (342 -> 200 kB) and `lazyModule`; "about 0.4 kB headroom" of entry budget in the handover (`repo/docs/waves/HANDOVER-2026-11-05.md:90`).
3. Phosphor icons: all six weights shipped per icon; custom Vite plugin prunes unused weights (`vite.config.ts:11-30`, `scripts/phosphor-weights.ts`). 163 icon imports.
4. Raw-value escape: tests, not lint, forbid hex/px/rgb and off-scale shadows (`tokens.test.ts:137-215`); a pasted shadcn component fails until `cn` import and `px` literals are rewritten (`AGENTS.md:4074-4076`).
5. Esc/focus layering across Base UI popups + a hand drawer + modal (`state/keys.ts:60` `layerOpen`; `Modal.tsx` pulls stray focus back every render).
6. Nested scroll/overscroll: whole-app rubber-band on macOS needed `overflow:hidden; overscroll-behavior:none` on html/body (`DESIGN.md:389`).
7. Layout shift from lazy blocks: every AI block reserves its final height computed in TS (`show/heights.ts` 238 lines of rem arithmetic mirroring CSS, `GENERIC_REM`, `TABLE_ROW=2.25`...). Judgement: CSS/TS duplication, fragile; a framework `reserve` contract would remove it.
8. Visual drift: first build was judged "a bad horrible model build ... not like every other shadcn page" (`DESIGN.md:5-6`): 62 `border-hairline` + 43 `border` classes made it read as a wireframe. Fix was tokens + three-surface depth, not a different library.

## 8. Migration cost and risk onto shadcn-based v3

Cost (judgement, from counts): HIGH-LEVERAGE, LOW-RISK for the app: it is already shadcn + Base UI + Tailwind 4 with semantic aliases, so a v3 that keeps shadcn's token names and `data-slot` attributes lets `components/ui` (2.4k lines) be swapped for v3 primitives mostly 1:1. The expensive part is replacing hand-rolled infrastructure, which is also where v3 value is.

| Work                  | Size driver                                                       | Risk                                                                                                                                                                    |
| --------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| tokens -> v3 tokens   | `tokens.css` 174 lines + 2 aliasing layers                        | low; parity test already exists, but the report template shares the values (non-React consumer must still read plain CSS vars)                                          |
| `components/ui` -> v3 | 39 files / 2.4k LOC; 8 bespoke twins                              | low-medium; lozenge/edge-shade/term-hint are app-specific                                                                                                               |
| stores/router/query   | 44 stores, 163 requests, 25 effect guards, 14 history sites       | HIGH: behavioural (back/forward, cursor resume, idempotent reducer, race guards). Conversation + settings must keep their tests (`conversation.test.ts` 1,356 lines)    |
