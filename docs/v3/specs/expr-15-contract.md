# Spec: a mono date column and the StatCell chart slot under `primitive-bypass` (expression cycle 15)

Issue 2574, plan row `v3-expr-15-contract`. With no verdict in 24 hours I build on the defaults below.

## The problem

Expression cycle 15 (`docs/v3/cycles/expression-15.md`) met two kit gaps that need a public field or change what `primitive-bypass` denies:

| Gap                                                                                                                                                                                                                                                                                                                                      | Cases                                                                                                          | What the builder did                                     |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| A date column has no mono face. `c.date` and `c.relativeTime` take no `mono`; only `c.entity` does (`docs/col.md`). Every other time slot in the kit (a figure `period`, a stat `sub`, an entity name, a footer fact) already has one.                                                                                                   | n72 .30 (phone card "Received: 8 Nov 2026" in the body face, X5), n73 wish ("Due: 15 Nov 2026")                | nothing: no field to set                                 |
| `primitive-bypass` (form `chart-body-root`) reports a `Sparkline` in a `StatCell` `chart` slot as "outside a card" when the group sits in a `Page` or `Section`. The same slot on `StatCard` passes, because the rule's frame test is the name pattern `Card` / `*Card` / `*Panel`, and `StatCell` (inside `StatGroup`) matches neither. | n69 (moved the trend into a wrapper component, ExprN69.tsx:249), n73 (a waiver with a reason, ExprN73.tsx:176) | a wrapper or a waiver; no point lost, two escape hatches |

## What I will build

**1. `mono` on `c.date` and `c.relativeTime`.** `DateOptions` and `RelativeTimeOptions` gain `mono?: boolean`, documented as on `c.entity`: "the value is a time: drawn in the mono face with tabular numerals". The cell's `<time>` carries `data-monospace` and `font-mono tabular-nums`, so the face follows the value wherever the cell is drawn: the desktop cell, the reduced tier and the phone card's labelled line ("Received:" stays in the label's body face, "8 Nov 2026" is mono), the same split the entity's `sub` already makes. Text exports, filters, sort and the tooltip of a relative time do not change. Tests: a mono date and a mono relative time render `data-monospace` with the mono class in the cell and on the phone card's line; the unset column renders neither. `docs/col.md`, `docs/table.md` and the shipped chart rule ("a time … in an entity column's name or sub … sets `mono`") name the date column too; agent text is regenerated.

**2. `StatCell` is a card frame to `chart-body-root`.** The rule's frame test admits `StatCell` beside `Card`, `*Card` and `*Panel`, so a shipped chart kind written in a `StatCell`'s `chart` slot (or anywhere under a `StatCell`) passes, as it does under `StatCard`. Reason: the slot is a kit-drawn frame (a fixed 28 px box called only in `ready`/`stale`, with its own error boundary), the same contract `StatCard`'s 72 px slot has; nothing about a cell makes the chart bare. Lint tests: a `Sparkline` in `StatCell chart={(box) => …}` inside `StatGroup` inside `Page`/`Section` passes; a bare `Sparkline` in the same `Section` still reports. The rule's doc comment and the skill's line name `StatCell`.

- No change to `StatGroup` itself, and no frame allowance for other cell-shaped parts until a case asks.
- No time-of-day column from a fixed clock, no byte formatter, no spread positions for app code (one case each, out of scope).
