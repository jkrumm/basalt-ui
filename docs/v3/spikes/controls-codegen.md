# Spike: controls on file routes (S1) and the remaining codecs (S8)

Both hypotheses hold on Router 1.170.46: a file-route app with codegen keeps the branded validator, `types.input` and `search.middlewares`, and the codec, retain, multi, history and `toWindow` cases all pass under both parse configs. They also pass unchanged on argo's locked 1.170.38. Four findings do not flip a verdict but change sections 3 and 5 of the concept: the middleware type seam, the cross-store ownership throw, a no-op push under a masking history, and the string-only config's number coercion. Each is under Then.

Harness: `bun tools/spikes/controls-codegen/run.ts` (one JSON object on stdout, exit 0 when the harness ran). Concept: `docs/v3/concepts/controls-url-state.md` section 9, S1 and S8. The 37-test prototype is not in the tree; `src/controls.ts` rebuilds sections 4 and 5 and is throwaway, since `ctl-2` re-implements `defineControls`.

## Question

- **S1.** Does the controls half work on file routes with codegen? The prototype was code-based and argo is the file-route risk. Refuted if the brand does not survive codegen, `types.input` stops rejecting an undeclared key, a `@ts-expect-error` negative stops erroring, or a middleware stops running.
- **S8.** Do the kinds the prototype never ran (`number`, `boolean`, `range`), `toWindow`, `retain` on argo's `finance.tsx` shape, a full-default `multi` and a masking history behave under both router parse configs? Refuted if any codec fails to round-trip, a child drops a retained key, an empty `multi` collapses into the full default, a history count is off, or `toWindow` yields neither preset nor from/to.

## Method

**Harness.** `tools/spikes/controls-codegen/` has its own `package.json` with exact pins: `@tanstack/react-router` 1.170.46 (router-core 1.171.39), `zod` 4.6.7, `typescript` 6.0.3, `@tanstack/router-generator` 1.167.46 (the 1.167 line argo's CLI uses; its lockfile has 1.167.38). `bun.lock` and `node_modules` are gitignored. No browser: a fake `window` feeds `createBrowserHistory` and counts `pushState` and `replaceState` calls, so entry counts are what a browser would keep. router-core's `isServer` constant is `true` in plain Node and makes `navigate` a no-op, so `src/setup.ts` sets `NODE_ENV=test` first (bun test sets it too).

**S1.** Twelve route files under `src/routes`, generated by the real `Generator` into `src/route-tree.gen.ts`. The name is not `routeTree.gen.ts` because the root `.gitignore` ignores that one, and a clean checkout could not type-check without it. Shapes follow argo: a root route with a global store; a `/finance` layout mounting the page store; six children, three inheriting the layout's validator and three repeating it (argo repeats it today); a range page with a push field and `extend(zod)`; a full-default `multi` page; and `/wrapped`, whose hand-wrapped validator is the negative control. `run.ts` regenerates the tree and compares bytes, reads every route's `options.validateSearch` for the brand and `options.search.middlewares`, renders a file route with `renderToString`, and runs `tsc --noEmit -p .`. Negatives are in `src/negatives.tsx`; an unused `@ts-expect-error` is TS2578, so tsc exit 0 proves each one errors. A probe copy with one directive flipped produced TS2578, so the check bites.

**S8.** Each codec is written through its handle (`navigate`), the href is read back, and a fresh router parses it. Samples include values that look like another type: `'123'`, `'007'`, `'1e3'`, `'true'`, `'null'`, `'[1]'`, `' 5'`. The two parse configs are Router's default JSON codec and shutterflow's `parseSearchWith((v) => v)` with `stringifySearchWith(String)`. A second table decodes hand-written and cross-config URLs. `retain` starts on a sibling child with a page-store key, a non-retained key and a global key, then follows a bare nav (no `search`) to each of the 6 children, and from each child to `/garmin-health` and `/`. History deltas count entries in the fake window. The masking history is written fresh on argo's `private-history.ts` model (address bar shows `month`, `from`, `to`, `year`, `range`; the real href rides in `history.state`).

**Mutation check.** Three throwaway edits each turned the run red: `retain: []`, a number codec that rejects `2`, and a strip middleware over `[]`. They are reverted.

**Interpretation, fixed before measuring.** "A push field adds 1 even when the stripped default is written" is read as: writing the default to a push field currently at a non-default value removes the param from the URL and still adds one entry. Writing a value equal to the current one changes no URL and is reported separately (`pushSameValue`, `pushDefaultWhileDefault`), not as a criterion.

**Router delta.** `run.ts` copies `src/`, installs `@tanstack/react-router` 1.170.38 into a scratch directory in the OS temp dir, runs the same cases and diffs every leaf. The delta is not a verdict input.

Back after a push returns to the previous search in all three. The masking row differs once: Router's same-location test compares `history.state` minus its own keys (`router.js` `isSameLocation`), and the masking history adds `__realHref` to the stored state but not to the next location's, so an identical push reads as a new location.

**Masking history** (`s8.maskingHistory`, both configs). After a write, the router location and `handle.get` see `search=secret`, the address bar shows `month` only, a fresh router over the same window restores `secret` from `history.state`, a URL opened from the address bar starts without it, and Back across a navigation restores it. Controls read the router location, never `window.location`.

**`toWindow`** (`s8.toWindow`, both configs): default and preset give `{preset}`; a valid `from`+`to` gives `{from,to}` and beats a preset; a half pair, a reversed pair, an impossible date (`2025-13-40`) and an unknown preset give `{preset}`. Writing a custom range drops `window`; writing a preset drops `from` and `to`; a half pair writes nothing and adds no entry.

**Cross-store ownership** (`s1.crossStoreOwnership`). A page store may reuse `window`, `from` and `to` that another page store owns (argo does, on different routes). A page store taking a global's param throws, as do two fields on one param and the `w.` prefix.

**Router delta** (`routerVersionDelta`). 1.170.46 against 1.170.38, both on router-core 1.171.39: 0 differing leaves, tsc exit 0 on both. Only the react-router layer differs, so this says little about router-core drift.

**Not run.** `autoCodeSplitting` (argo sets it): the splitter runs through the Vite plugin, which this harness does not load. Its split set, read from the installed `@tanstack/router-plugin` constants, is `loader`, `component`, `pendingComponent`, `errorComponent`, `notFoundComponent`; `validateSearch` and `search` stay in the route file. That is a reading of source, not a measurement: the package is not a harness dependency, and the copy read is the 1.167.35 install in argo's tree (`dist/esm/core/constants.js`), so the version it applies to is not pinned here.

## Then

`ctl-2` proceeds on the section 4 and 5 design. These amendments go in with it; this spike makes none.

- **`search.middlewares` property type (section 5).** `search: { middlewares: overview.middlewares }` type-checks only if the property is typed assignable under any parent, here `(context: unknown) => never`. Typed by the store's own search, it fails on every route below a global, because a route's array is typed by its full search and the parameter is contravariant. Router's own `stripSearchParams` avoids this with a generic inferred from the contextual type, which a property cannot do. Keep the property and ship the loose type, or make it a call and keep the strict one; the first keeps the sketch.
- **Two stores owning one param (section 3, 4.2).** "Throw at definition" is wrong for page against page: argo's pages share `window`, `from` and `to`. Throw only when one of the two stores is global (or inside one store); the brand already covers the rest.
- **No-op writes.** The handle should skip `navigate` when the value equals the current one. The duplicate Back entry was measured on this harness's masking history, not on argo's `private-history.ts`; both store the real href in `history.state` the same way (`withRealHref`), so argo's should behave alike, but that is a reading to confirm before it becomes a requirement. Argo's finance filters are replace fields, so today's cost is zero; it bites the first push field on a masked route.
- **Codec input widening (1.3).** The string-only config is not string-only on the way in: Router's `qss` decode turns `128`, `true` and `false` into a number and booleans whatever the parser is. `enum` and `multi` must accept a lone number or boolean as `string` already does. The prototype's `multi` takes any lone scalar; the results exercise only the number case (`?levels=1` reaches it as `1`), not a boolean. Section 1.3 lists array or comma string for `multi` and says nothing of a bare number.
- **Interpretation to confirm.** The push-field criterion was read as "writing a stripped default from a non-default adds 1". If the owner meant "any write adds 1", `pushSameValue` and `pushDefaultWhileDefault` (0 plain) refute it, and the no-op guard above is the wrong behaviour.
- **Harness facts for the build.** Node tests of the router half need `NODE_ENV=test` (bun test sets it). A generated tree must not be named `routeTree.gen.ts` in a fixture app that is committed.
