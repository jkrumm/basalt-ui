# TanStack map: what basalt binds, and how

Verdict: basalt takes TanStack Form as a new optional subpath, `basalt-ui/form`, built on `createFormHook`; takes TanStack Start as a host option of `basalt-ui init` with no runtime subpath and no peer; keeps the five bindings it has (Router, Query, Table, Virtual, Charts); waits on Hotkeys and DB until each tags 1.0; and refuses Pacer and Store, which give a UI kit nothing to pre-bind. Every binding stays an optional subpath behind an optional peer, in the pattern of `basalt-ui/router`: the core, `ui/*`, `./charts` and `./tokens` import none of it, and a plain Vite React app without the peer installs, builds and passes `pack-test`.

The page answers the owner's direction of 2026-11-20 (Issue 2525): "we love TanStack and want to use Start, Query, Hotkey, Form, DB, etc. all they have. But BasaltUI may also work with Vite or so." Before it, the kit bound part of the family and stayed neutral on the rest with no written position; `ARCHITECTURE.md` section 10 refused the Form peer and Hotkeys. Four `agw research` runs (standard depth) read the docs listed per library on 2026-11-20, and `npm view` read every version, tag and peer range the same day. The Spec that turns the takes into parts is the factory artifact of Issue 2525.

## Why Form is the one new subpath

- **The docs make a kit own the hook.** The composition guide has a platform team export one `createFormHook` result with its contexts and pre-bound parts, and downstream apps call `extendForm` to add their own [F3]. Basalt ships no `extendForm`: an app's own control renders as the child of `f.FormField`, which hands it the value and the change handler, so no app in the fleet needs a field part of its own. In 1.33.5 the contexts are module-level, so a basalt part calling `useFieldContext` matches the app's provider as long as one copy of `@tanstack/react-form` is installed; the optional peer guarantees that.
- **Section 3's barrel rule rules out `./controls`.** A barrel imports only peers every symbol in it needs. `FormField` with `control={handle}` and `FilterSet` work without TanStack Form, so the bound layer cannot live in `./controls` without making the peer required there.
- **`./controls` keeps its structural parts.** `FormField`, `FormRow`, `FormFooter`, `toSubmitErrors` and `useFormDraft` stay where they are and keep reading `FieldLike`; `./form` binds them to the contexts and adds the submit wrapper. An app without the peer composes the same parts by hand, as today.
- **The names stay TanStack's.** `useAppForm`, `withForm`, `withFieldGroup` are the names in every TanStack Form guide, so an agent that read the docs writes the right import.

## Why Start is not a subpath

Start renders the same React tree on the server; what changes is the document shell, the router entry and when browser state may be read. Each of those is a file the app owns (`__root.tsx`, `router.tsx`, `vite.config.ts`), which is `init`'s job, not a runtime export. Basalt already ships the one runtime piece the shell needs: `themeScript()` from `basalt-ui/theme-script` is the string `ScriptOnce` takes [S4]. The binding is therefore an `init` option plus a test that `BasaltProvider` and `AppShell` render on the server without touching `window` (Start's hydration guide: read browser state in effects, behind `ClientOnly`, or through `createClientOnlyFn` [S5]).

## What changes elsewhere when the Spec has its verdict

- `ARCHITECTURE.md`: a "Contract amendment" row in section 14 for `./form` (subpaths, symbols, peers) and for this map; the section 10 row that refuses `useBasaltForm` and the `@tanstack/react-form` peer goes; the Hotkeys refusal stays with "later at 1.0" as its reason. Applied with Issue 2525: `./form` ships `useAppForm`, `withForm` and `withFieldGroup` (3 value symbols, 37.1 KB gz measured with the engine, ceiling 39), `form.Form` takes the submit `meta` a `Stepper` form needs, and the playground's forms run on it.
- `agent/skills/basalt-design/references/forms.md` and `forms-research.md` § The form engine: both say the app imports `useAppForm` from `basalt-ui/form`; the "basalt ships no hook, no adapter and no peer" line and the "never the ui Form here" line go.
