name: basalt-charts
description: Draw a chart in a basalt-ui app: pick the shipped kind or compose CartesianChart marks, give a series its colour, wire focus between the chart and its lists, label the answer on the mark, then verify the frames. Covers Lines, Bars, Sparkline, Heatmap, BandStrip, IntervalTrack and hand-drawn marks.
when_to_use: Whenever a page draws a chart, a sparkline, a heat grid or any data mark; when a chart is restyled, a metric gets a colour, or a table or list should follow a chart's hover. Use it together with basalt-design.

Procedure only. The contract is `.claude/rules/basalt-charts.md`; the design rules with their worked examples are [basalt-design charts](../basalt-design/references/charts.md); every prop is in `node_modules/basalt-ui/docs/<kebab-name>.md`. Read [cartesian-chart-guide](node_modules/basalt-ui/docs/cartesian-chart-guide.md) before a custom mark and [use-chart-focus](node_modules/basalt-ui/docs/use-chart-focus.md) before any focus wiring: both carry code that compiles.

## Steps

1. **Question, surface, form.** Write the one-sentence question, then the parts it needs (the mark, the figure, the detail list, table or timeline), where each sits and what they share. A chart with a detail list sits beside it at a wide container, the list scrolling at the chart's height, and stacks at a narrow one; a form laid out along time or a chain (`IntervalTrack`, a timeline, `ChainView`) takes the full row with its list below. Pick the form the next action needs, then the cheapest way to draw it: a shipped kind whose form is that form, else `CartesianChart` marks in the page's own chart file. A kind is never picked because it is nearest, and a missing kind never justifies a different form. A form repeated in this app is extracted into that chart file, never into a new kind.
   - `Lines` or `Bars`: a value over time or a category. `Sparkline`: a trend in a cell or tile, written straight into a `StatCard` or `StatCell` `chart` slot (`basalt/primitive-bypass` reads that slot as a card, and a wrapper component hides it). `BandStrip`: one gap-free row of states over time. `Heatmap`: two categories crossed, the cell value the answer. `IntervalTrack`: spans and point events on rows over time.
2. **Colours.** Author each series colour once, as a `{ light, dark }` pair (lighter on dark, deeper on light) under `series.<group>.<key>` in `<root>/basalt.tokens.ts`, the app's one series file (`init` seeds it in the first `--root` and imports its sheet). That file is the only one that writes colour literals. A chart series takes the pair, `color: tokens.series.<group>.<key>` after `import tokens from './basalt.tokens'`. An HTML mark (a `Meter`, a track `div`, a dot) takes the variable of the same pair: `groupTokens('<group>', tokens.series.<group>).<key>` from `basalt-ui/tokens` is `var(--basalt-<group>-<key>)`, so one kind keeps one colour in the chart, the list and the track. After an edit run `basalt-ui tokens:css --extra <root>/basalt.tokens.ts --out <root>/basalt.tokens.css`, which declares those variables; `doctor` fails a stale sheet. Never write a `BasaltRegister` augmentation or `defineSeries`: the sheet's `.d.ts` registers the keys.
3. **Marks and focus.** Compose marks from the allowed `@tanstack/charts/*` subpaths. `useChartFocus(query.data, { announce })` is one handle (`undefined` while loading, never `data ?? []`): pass it as `focus` to `CartesianChart` or `Heatmap`, whose host owns the tab stop, the arrow keys and the announcement, and dim the rest against `plot.focused`.
   - The figure's `value` and `delta` are the answer and stay while a hover moves. The focused reading goes in the figure's `period` and `status` through `focus.readout(rest, read)`, or in the tooltip. It carries every measure the parts draw, short enough for one line at 390. A held run is read whole through `focus.span` (its best or its sum), because `focus.readout` reads only its first item.
   - The mark that answers carries the answer at rest: the leading line's end value, the totals on the top bars, the gap at today. Name each line at its own end with a `text` mark placed by `chartLabels`; on a band axis name the keys that matter with `x.ticks` as a list, never default thinning. A footer fact about one mark is on it; a state is named by its meaning ('so far'), never its look; a `highlight` fill has a legend entry. Bars take `values: true` or `(v, d) => text`: a stack's total, or a segment's with `valuesAt: 'segment'`; unfit labels drop.
   - The accent goes to the item that answers: a bar series' `highlight: (d) => boolean`, never a second series split off for colour. One fact takes one status hue.
   - Cap the domain where one value crushes the rest (`y.domain`; a `Sparkline` takes `cap`): the kit draws an off-scale caret and the readout keeps the true value. A zero bar keeps a baseline tick that takes focus. A dot series whose dots coincide sets `spread: 'x'` or `'y'`.
   - A `Sparkline` with `axisLabels` is a chart host: give each point its name, `{ value, label: 'W41' }` or `{ value, at }`, so the readout says which point it is.
   - Marks drawn through the seam set `legend: false` on their series and are named in `ChartCard` `legend`, whose entries toggle the series with the same `key`.
   - `x.title` and `y.title` name the axes, a vertical rule is a `refLines` entry with `axis: 'x'`, a log x is `x.scale: 'log'`, and a region the question asks about is a zone with `axis: 'x'`, never a hand-drawn `rect`. Direct labels sit at `plot.x` and `plot.y` pixels through `chartLabels.place` ([custom-marks](references/custom-marks.md)). A hover already pins x and y on the axes, so never draw a crosshair. `plot.plotHeight` is the plot and `plot.data` every raw row; `fillOpacity` is one number per mark, so split rows into one mark per opacity.
   - A part-to-whole of a few parts is a one-row stacked `BarList` (`series` and `parts`); a `Heatmap` has `annotate`, `states` and `tickCols`.
4. **Linked parts.** Every list of the page's items (a `DataTable`, a `BarList`, a timeline) joins the one focus, with or without a chart on the page. Draw the chart at the list's grain so `DataTable focus` joins the two by id; pass the handle to `BarList focus`, or spread `focus.item(i)` on hand-drawn rows inside a container that spreads `focus.target`. A list of groups beside samples spreads `focus.groupItem(name)`, a list of series `focus.seriesItem(key)`; stacked panes each take the one `focus`, and a chart of a parent's children joins through `focus.hold`. A page with no chart renders `focus.live` once; a chart renders it itself. When the period follows focus the tooltip is off (`tooltip={false}`). The announcement names the focused item's values in the tooltip's order, with their units, for the series that datum draws. Stacked panes keep a 160 px floor each; the card grows to hold them. The wiring is in [linked-parts](references/linked-parts.md) and the recipes [seam-bar](node_modules/basalt-ui/docs/recipes/seam-bar.md), [seam-track](node_modules/basalt-ui/docs/recipes/seam-track.md) and [seam-linked](node_modules/basalt-ui/docs/recipes/seam-linked.md).
5. **Card and states.** Wrap the chart in `ChartCard` (`chart={(box) => …}`) and pass the query as its `phase`. Every slot the ready frame draws is passed in loading too, the subtitle included; an error `PageSummary` takes `message` and `retry`: run `rg -nU '(footer|sub|rows|delta|status)=\{\s*[\w.!]+\s+(\?|&&)' <page dir> -g '*.tsx'` and change each hit to the same labels with empty values. A `cursorValue` series colours its cursor dot per datum with `getMarker: (d) => ({ color })`.
6. **Verify.** Run the repo's gate and fix every finding at its source. Then run the Done list of the [basalt-design skill](../basalt-design/SKILL.md): the fact count, the read-aloud section, the one-view lines and every frame opened, the keyboard frame from `basalt-ui shot <route> --states keys` included.
